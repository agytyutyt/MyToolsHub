## 1. 验收范围与通过标准

**验收对象**：主体（26.5 MB，仅含 admin）+ 插件集（**16 个插件**）+ 依赖组件包（11 个）+ 离线组件（LibreOffice / Chrome）。

| 项 | 说明 |
| --- | --- |
| 通过标准 | **必测项（标 ★）全部通过**；非必测项不通过需给出结论与影响面；无"未验证"项（无法验证的必须写明原因） |
| 执行顺序 | 先跑 §2.5 的**自动验收**（共 32 条，含 5 条默认按条件跳过：F-20/F-22 需大模型 Key、R-06 需 `--app-dir`、S-01 需 `--media`、S-02 需 `--user2`；另 F-12 未装 cv2 组件时也会跳过），出报告；再人工补它覆盖不到的（浏览器侧解码、需 Key 流程、纯交互界面） |
| 缺陷分级 | **阻塞**（功能不可用/数据风险，必须修）｜**严重**（主流程可用但结果错）｜**一般**（有替代路径/提示不清）｜**轻微**（文案、样式） |
| 结论口径 | 阻塞/严重为 0 才能判"通过"；一般/轻微列出清单并约定修复版本 |
| 建议人力 | 执行 1 人 + 复核 1 人；干净机部署与功能约 1 天，升级回滚约半天 |
| 验收环境 | **一台干净机**（部署手册 §1 的环境基线，共 7 项；尤其第 5 项 `msvcp140.dll` 必须为 False）+ 一台已装环境（升级验收） |

## 2.5 自动化验收（先跑这个，人工只补差集）

仓库里带一个**自动验收脚本**，把本文里可 HTTP 驱动的用例跑一遍并出报告——先跑它，
人工只做它覆盖不到的部分（浏览器侧解码、需 Key 的流程、纯交互界面）。

**目标机通常没有 Python**，所以有两条用法：

### ① 目标机：用「自动验收工具包」（推荐，无需 Python）

解压 `JZToolsHub-验收测试-v<日期>.zip` → 启动服务（双击主包 `start.bat`）→
**双击「一键验收测试.bat」**。包里是：

| 文件 | 说明 |
| --- | --- |
| `acceptance-runner.exe` | 单文件 exe（**内含 Python 运行时**；目标机无需装 Python，也不联网） |
| `一键验收测试.bat` | 双击入口：连本机 5000 → 跑全组 → 写 `验收报告.md` → 暂停等你看结果 |
| `testdata\` | 各插件测试文件 + 预生成二维码/视频（脚本默认读它） |
| `README.md` / `使用说明.md` | 覆盖范围、跳过项口径、常见问题（连不上 / 缺依赖 / 改端口…） |

可选参数（直接命令行跑 exe）：`--base http://<目标机IP>:5000`、`--groups F,R`、
`--media <插件包目录>`（跑 S-01）、`--app-dir <程序目录>`（跑 R-06；不填会自动探测注册表 / `%LOCALAPPDATA%`）。

### ② 开发机 / 有 Python 的环境：直接跑脚本

```powershell
python tools\e2e\acceptance-runner.py --base http://127.0.0.1:5000 `
       --report build\acceptance-report.md

# 带可选开关能多跑三条：
#   --app-dir "%LOCALAPPDATA%\JZToolsHub"  → R-06（--check-deps 真实 import 自检）
#   --media deploy\插件包                   → S-01（改一个字节的包必须被拒绝）
#   --user2 <普通账号> --password2 <口令>   → S-02（非超管不能管理插件）
```

> 改了脚本要重出工具包：`powershell -ExecutionPolicy Bypass -File tools\e2e\build-acceptance-kit.ps1`

| 项 | 说明 |
| --- | --- |
| 覆盖 | 用例清单与条数以 `tools/e2e/acceptance-runner.py` 的 `@case` 为准（2026-09-24 核对为 32 条，其中 5 条按条件跳过）：F 组功能（admin/file-filter/info-transfer/trajectory-*/knowledge-base/shared-docs/notice-board + base64/json-formatter/md5-generator **3 个纯前端页面**）、R 组依赖一致性、S 组安全、X 组边界与并发 |
| 退出码 | 0 = 无 FAIL（SKIP 不算失败）；1 = 有 FAIL；**2 = 连不上 / 登录失败（一条用例都没跑）** —— 接进 CI 或批处理时判据用「非 0 即异常」 |
| SKIP 口径 | **不假装通过**。会 SKIP 的只有三类：① 硬编码人工项 `F-20`/`F-22`（需大模型 Key）；② 缺开关的 `R-06`/`S-01`/`S-02`（加 `--app-dir`/`--media`/`--user2` 即跑）；③ 环境性降级（`F-12` 未装 cv2、`R-06` 程序目录未装组件）。**报告里没出现的用例属"未注册"**（`F-14` qr-video-decode、`F-09`/`F-16`/`F-19`/`F-21`/`F-23`/`F-25`、`F-30` 取色器、`F-31` 地图，以及 D/U 全组与 `R-03`/`R-04`/`R-05`/`R-08` 等）—— 它们是**人工验**，不是"跑过且跳过"，逐条见 §9.3 与本文对应编号（完整注册清单以 runner 的 `@case` 为准） |
| 旧版主包 | R-06 对**不认识 `--check-deps` 的旧版 exe** 会安全失败并报出该目录版本号（同时收掉被拉起的进程），提示"请用本批主包验收" |
| 前置 | 实例已启动、测试数据就位（工具包自带；仓库运行时读 `testdata\`）、依赖组件按需装好 |

> 自动验收跑的是**真实接口**（上传/解码/导出/校验/并发），不是"页面能不能打开"。
> 例如 F-10 会做"静态码原件传输 → 解码 → 导出"并比对 **sha256**；R-06 会在冻结 exe 里对
> 每个组件声明的模块做真实 import。失败项会打印响应体，便于直接定位。

## 5. 依赖与降级验收（R 组）

> 设计口径：**缺依赖不阻断安装**，插件仍加载并标注"功能降级"，页面横幅指出"缺什么 + 哪个功能失效 + 怎么修"。

| 编号 | 用例 | 操作 | 预期 |
| --- | --- | --- | --- |
| R-01 ★ | 缺组件时插件仍可用（部分功能） | **不装** openpyxl 组件，打开 file-filter | 插件正常打开；xlsx 提示不可用，csv 仍可用；后台该行 openpyxl 显示**红色 ×** |
| R-02 ★ | 装组件后**免重启**生效 | 服务运行中装 openpyxl 组件 → 刷新插件页 | 插件自报依赖由 `false` 变 `true`，无需重启（首页"降级"标记同步纠正） |
| R-03 ★ | 组件间依赖提示 | 只装 cv2 组件 | 前置提示"还需要依赖组件 numpy"；自检失败并点名 numpy（不是"包不完整/缺运行库"） |
| R-04 ★ | 多组件共存 | 再装 numpy 组件 | 两组件**同时存在**（目录 + 登记）；`--check-deps` 返回 `ok: true` |
| R-04b ★ | **服务运行中装组件**（文件被占用） | 服务运行且组件已被加载时，再装/重装该组件 | 安装器**自动暂存**并提示「重启服务后自动生效」（不报 Permission denied、不留半个组件）；重启后组件就位、登记正确 |
| R-05 | 缺 LibreOffice | 上传 `.doc` 到知识库 | 提示"安装离线组件"；`.docx` 不受影响 |
| R-06 ★ | 自检工具 | 程序目录执行 `JZToolsHub.exe --check-deps out.json` | 已装组件的模块**逐个真实 import**，全部 `ok`（含 VC 运行库验证点） |
| R-07 | 后台依赖展示 | 后台 →「查看已安装依赖（含版本）」 | 框架包 / 外部组件 / 依赖组件分列，含版本与来源标注。**注意命名口径**：面板按**发行包名**列出（`python-docx`、`opencv-python`、`zxing-cpp`），而插件 `requires` 声明用 **import 名**（`docx`、`cv2`、`zxingcpp`）——同一件东西的两种写法；悬停徽标可见"要求 vs 实际" |
| R-08 | 按组件卸载 | `install-dep-component.ps1 -Remove cv2` | 只删 cv2（含空目录）；numpy 保留且自检仍通过 |

## 6. 升级与回滚验收（U 组）

| 编号 | 用例 | 操作 | 预期 |
| --- | --- | --- | --- |
| U-01 ★ | 插件独立升级 | 后台上传新版插件包 → 校验预览 → 应用 | 校验项（哈希/版本区间/ABI）全过；应用后自动重启；版本与登记一致 |
| U-02 ★ | 一键扫描安装升级 | 介质目录放新版插件包 → 扫描 → 装 | 状态显示"可升级 x → y"；逐项进度可见 |
| U-03 ★ | 主包升级**防回退** | 先单独升级某插件到更高版本，再装主包 | 该插件**不被主包内嵌版本覆盖**；状态登记也不被改写 |
| U-04 ★ | admin 单独升级 / 不可卸载 | 升级 admin 包；再尝试卸载 | 升级成功；卸载被拒绝（核心插件） |
| U-05 ★ | 插件回滚 | 后台回滚到上一版本 | 代码与登记回到备份版本；数据未被触碰 |
| U-06 | 主包回滚 | `install.ps1 -Rollback` | 程序目录回到上一主包版本；数据根不变 |
| U-07 | 登记对齐 | 手工改插件目录版本 → 后台「一键对齐登记」 | 登记与实际一致；按钮置灰 |
