## 1. 一句话

**这是一个"解压即用、目标机可完全无外网"的 Windows 部署包。** 主包只含应用本体（≈27 MB，解耦后；仅含核心插件 admin；具体体积以出包产物为准）；
目标机可能缺的浏览器（Chrome）与知识库预览要用的 LibreOffice，作为**独立的「离线组件包」**按需分发，
需要时在目标机就地一键安装，全程不需要联网。

### 1.1 五种分发物（默认主包已瘦身）

| 分发物 | 体积 | 何时需要 | 目标机操作 |
| --- | --- | --- | --- |
| ① `JZToolsHub-v<版本>.zip`（主包） | **≈27 MB（解耦后；以出包产物为准）** | 必装 | 解压后双击「一键安装.bat」 |
| ② `JZToolsHub-离线组件-LibreOffice核心-<版本>.zip` | **≈163 MB** | 需要 `.doc` / `.xls` 原样式预览时 | 解压后双击「安装LibreOffice核心组件.bat」（**免管理员**） |
| ② `JZToolsHub-离线组件-Chrome-<版本>.zip` | ≈160 MB | 目标机没有可用浏览器时 | 解压后**以管理员身份**运行「安装Chrome浏览器.bat」 |
| ③ `JZToolsHub-依赖-<pkg>-v<版本>.zip`（依赖组件包） | 随组件而异（以出包产物为准） | 目标机缺第三方库时（`cv2` / `numpy` / `zxingcpp` / `zfec` 等）；不装则相关插件功能**降级**而非不可用 | 解压后双击「安装依赖组件.bat」（**免管理员**，装到 `<程序目录>\runtime\pylibs\`；详见 §9） |
| ④ `JZToolsHub-插件-<插件id>-v<版本>.zip`（插件包） | 随插件而异（以出包产物为准） | 只升级某一个插件时（不必重出整包） | 解压后双击「安装插件.bat」（**免管理员**） |

> 第五种是**移动端 APP**（扫码接收信息传输的文档）：源码在 `android-app/`，**不随主包**分发，
> 打包与分发见 `android-app/InfoParse/InfoParse-APP打包手册.md`。五种分发物的口径与本表同源。
> （业务插件**不在主包内** —— 主包只带核心插件 `admin`，其余插件一律走 ④ 插件包/插件集分发；
> 插件清单以 `plugins/*/manifest.json` 为准，本文不复述个数。）

> **为什么拆开**：组件占原主包体积的七成以上，而且并非所有目标机都需要（已装 Office / WPS 的
> 不需要 LibreOffice；多数机器自带 Chrome / Edge）。拆开离线组件后主包从 437 MB 降到约 122 MB（后续插件解耦进一步收窄至仅含核心插件 admin，**当前体积见 `HANDOFF.md` §2.2**）。
> 组件还能**独立升级与卸载**。要出旧式「组件随包」的胖包：`build-deploy.ps1 -WithOfflineRuntime`。
>
> **插件包**是第四种分发物：把**单个插件**的代码快照单独发布，解决"其实只改了一个插件，
> 却要让所有机器重下整包（解耦后 ≈27 MB；以出包产物为准）"的问题。它只动程序目录的 `plugins\<插件id>\`；插件的用户数据
> （数据根目录 `plugins\<插件id>\`）全程只读、逐字节不变。安装器先校验版本与逐文件哈希、
> 再备份旧版，最后才替换，出错可一条命令回滚。详见 §11 与 `docs/design/插件独立升级方案-设计文档.md`。

> **LibreOffice 组件对目标机是隐身的**：不写注册表、不建快捷方式、不改文件关联与默认应用，
> Microsoft Office / WPS 照常使用，工具箱也能继续用它的高保真预览。
> 完整可行性评估与实测证据见 **`docs/guide/LibreOffice核心组件一键安装评估.md`**。

## 2. 包内组成

### 2.1 默认（瘦包）：不含离线组件

解压后 `deploy\JZToolsHub\` 体积与文件数**以出包产物为准**（解耦后主包仅含核心插件 admin）；`version.json` 的 `offline` 字段为**空串**。
下表为其余构成；`runtime\` 目录**完全不存在**（包内无 `chrome\*.msi`、无 `libreoffice-core.zip`）：

| 路径 | 体积 | 数量 | 作用 |
| --- | --- | --- | --- |
| `_internal\` | 以出包产物为准 | 以出包产物为准 | **Python 运行时 + 主包冻结依赖**（Flask / waitress / cryptography / pystray / PIL 等 `JZToolsHub.spec` 的 `PACKAGES`；其余第三方库改由「依赖组件包」提供）。由 PyInstaller 生成，**不要手动改** |
| `JZToolsHub.exe` | 以出包产物为准 | 1 | 应用本体（无控制台窗口，托盘常驻） |
| `plugins\` | 以出包产物为准 | 以出包产物为准 | **仅核心插件 `admin`**（解耦后；业务插件走插件包 / 插件集分发）。前端可直接改、重启生效 |
| `static\` | 以出包产物为准 | 以出包产物为准 | 框架首页与外壳页前端 + SVG 图标回退 |
| `config\tools.json` | — | 1 | 工具注册清单**模板**（首次启动复制到数据根目录） |
| `config\installed-deps.json` | — | 1 | **已安装依赖清单**（`scope=shipped`，构建期由 `tools\gen-installed-deps.py` 采集写入）。后台「已安装依赖」面板与插件可运行性判定的真源，也是 `tools/verify-package.py` 的必需文件 |
| `docs\` | 以出包产物为准 | 以出包产物为准 | 仅随包层：索引 `docs/README.md` + `docs/guide/`（交付手册）+ `docs/design/`（设计文档）；内部层 `eval/plan/archive` 不随包 |
| `install.ps1` `一键安装.bat` `一键卸载.bat` `start.bat` | — | 4 | 安装 / 卸载 / 启动入口 |
| `version.json` | — | 1 | `{app, schema, commit, built_at, python, offline, plugin_api}`，模板同步的触发依据 |

> **`wheels/` 与 `tools/`（除 `plugin-upgrade`）不随主包**：解耦后 `wheels/` 无运行时消费方已移出；`tools/` 只带目标机离线装插件用的 `plugin-upgrade`；`zfec` 等改由「依赖组件包」按需提供（见 §9）。

### 2.2 随包携带组件时（`-WithOfflineRuntime`）

解压后 `deploy\JZToolsHub\` 体积与文件数**以出包产物为准**（在瘦包基础上多出 `runtime\`）：

| 路径 | 体积 | 数量 | 作用 |
| --- | --- | --- | --- |
| `runtime\` | **约 324 MB** | 以出包产物为准（2026-09-24 核对为 11） | **离线运行组件**（Chrome MSI + LibreOffice **裁剪核心包**；见 §3）。除 §3 表列出的 7 个文件外，还随包 4 个 LibreOffice 核心组件的安装/卸载脚本与日志：`install-libreoffice-core.ps1`、`安装LibreOffice核心组件.bat`、`卸载LibreOffice核心组件.bat`、`安装日志-LibreOffice核心.txt` |

> 主包**默认不带**这一项。组件占体积七成以上且并非人人需要，故改为独立分发（§1.1）；
> 组件包内的 LibreOffice 是「一键安装、对目标机隐身」的形态。


**不包含**（按设计排除）：

* 用户数据 —— 账号、组织架构、台账、文档、公告、大模型 Key 等全部在**数据根目录**
  （默认 `%USERPROFILE%\.jztoolshub`），与程序目录分离，升级不丢。
* 本机运行时配置与密钥 —— 插件树内精确名 `config.json`（含 API Key）在打包时被清理；
  配置**模板**另命名为 `*.template.json`，不会被误删（原因见 `docs/archive/P0问题修复方案.md` FIX-1）。
* 插件运行数据与缓存 —— `data/`、`.task_cache/`、`__pycache__/`、`out/`、`*.pyc` 全部清掉，首启自动重建。

### 3.1 为什么 LibreOffice 用"裁剪核心包"而不是完整 MSI

应用的 Office 预览只用 **两条 soffice 转换**：`.doc → .docx`（`dhr` 引擎）与
`.xls → .xlsx`（`xhr` 引擎）—— 都是 Writer / Calc 的过滤器，**不需要 UI、帮助、拼写词典、
界面语言包、图标主题，也不需要 Draw/Impress/Math/Base 的运行时**。

官方 MSI 解包后有 **1522.6 MB / 19418 个文件**，其中绝大部分是死重：

| 死重 | 体积 |
| --- | --- |
| 拼写词典（`share\extensions\dict-*`，60 种语言） | 471 MB |
| 界面语言资源（`program\resource\<locale>`，124 种语言） | 266 MB |
| 界面语言注册表包（`share\registry\res\fcfg_langpack_*.xcd`） | 90 MB |
| 图标主题（`share\config\images_*.zip`，21 套） | 65 MB |
| 字体（`Fonts\`，阿拉伯/希伯来等打包字体） | 51 MB |
| Python-UNO 运行时 + Java 桥 | 42 MB |
| 剪贴图集 / 文档模板 / 向导 / Basic 宏库 / PDF 导入 | 43 MB |
| 离线帮助 / readme / 预设 | 13 MB |

由 `tools/build-libreoffice-core.py` 在**打包机**上解包并裁掉这些（保留 `zh_CN` 等中英语言
资源与许可文件），得到：

| 项 | 完整 MSI | 裁剪核心包 |
| --- | --- | --- |
| 包内占用 | 357.5 MB | **164.5 MB**（省 193.1 MB） |
| 目标机解包后 | 1522.6 MB / 19418 文件 | **557.9 MB / 2824 文件** |
| 目标机安装耗时 | 95~130 秒（`msiexec /a`） | **约 24 秒**（解压） |
| 需要管理员 | 否 | 否 |

> **⚠️ 裁剪的坑（2026-09-14 踩过）**：`presets\` 目录**绝不能删** —— 删掉后 soffice 在
> **全新 user profile** 下会以 `Fatal Error: … 安装无法完成`（退出码 77）启动失败。
> 之所以容易漏掉：若复用已初始化好的 profile，裁剪后的树看起来完全正常；而应用每次转换
> 用的都是**唯一临时 profile**，等于每次都是首次启动，线上必崩。
> `help\` 与 `readmes\` 是安全的，别和 `presets\` 归成一类一起删。
> 工具内已有 `MUST_KEEP` 不变量检查 + **构建期冒烟测试**（全新 profile 跑一次
> CSV→XLSX）来兜住这类问题。

### 3.2 为什么走"打包机裁剪"而不是 MSI 功能选择

`msiexec /a`（管理安装）**会忽略 `ADDLOCAL` 功能选择** —— 实测按官方功能表只保留 378 个
功能后，仍解出全量 1522.6 MB / 19418 个文件。所以只能"先全量解包、再裁剪"，无法靠官方
功能选择省事（该 MSI 的功能划分本身很干净：`gm_Langpack_*` 356.7 MB、
`gm_r_ex_Dictionary_*` 455.2 MB、`gm_r_Files_Images` 71.7 MB，但 `/a` 不认）。

`msiexec /a` 本身仍是**免管理员、不写注册表**的管理安装，解出的目录可直接运行 —— 这是
内网受限机器的关键（很多现场账号没有本机管理员权限）。

安装后应用**自动探测**，无需改任何配置：

```
插件配置 office.soffice_path  >  环境变量 XHR_SOFFICE  >  <程序目录>\runtime\libreoffice\program\soffice.exe
```

验证：启动后访问 `GET /api/knowledge-base/status`，`soffice` 字段非 `null` 即生效。

### 3.3 想改裁剪清单 / 换 LibreOffice 版本

```powershell
# 重建核心包（源 MSI 或裁剪清单版本变了才会真正重跑；约 4 分钟）
python tools\build-libreoffice-core.py --force
# 只校验已有产物
python tools\build-libreoffice-core.py --verify-only
```

改完清单要把工具里的 `PRUNE_VERSION` +1，否则缓存不失效。换 MSI 后**必须重建** ——
`build-deploy.ps1` 会核对核心包与源 MSI 的 sha256，对不上直接报错中止。
仍要随包带完整 MSI：`build-deploy.ps1 -KeepFullLibreOffice` —— **该开关只跳过「把 MSI 移出包外」这一步**，
裁剪核心包与完整 MSI 会**同时留在包内**，体积回到两者相加的量级（2026-09-24 核对：核心包 + MSI + Chrome ≈ 682 MB），
不是回到"只用完整 MSI"的旧口径。

## 4. 部署流程（目标机）

> **默认主包已瘦身**：下面第一段是 **`-WithOfflineRuntime` 胖包**流程（主包自带 `runtime\`，安装器末尾自动装 Chrome、解包 LibreOffice）。
> **瘦包（默认）流程**：装完主包后，`install.ps1` 若发现源包无 `runtime\manifest.json` 只会打印离线组件指引、不自动安装；
> 需要 LibreOffice 预览时，**另解压「离线组件包」`JZToolsHub-离线组件-LibreOffice核心-<版本>.zip`，
> 双击其中的 `安装LibreOffice核心组件.bat`（免管理员、对目标机隐身）即可**（Chrome 组件才需右键提权运行）。

**胖包（`-WithOfflineRuntime`）流程：**

```
① 把 zip 拷进内网（U 盘 / 内网文件服务）→ 解压到任意可写目录
② 双击「一键安装.bat」            ← 装到 %LOCALAPPDATA%\JZToolsHub（可用 -InstallDir 改）
                                  末尾会自动装 Chrome、解包 LibreOffice
③ 若第 ② 步提示 Chrome 需提权：右键「runtime\安装离线组件.bat」→ 以管理员身份运行
④ 双击 start.bat 启动 → 浏览器访问 http://localhost:5000
   默认管理员 admin / admin123，登录后请立即改密
```

其余动作：

| 目的 | 操作 |
| --- | --- |
| 升级到新版本 | 解压新 zip → 双击「一键安装.bat」（识别既有安装后就地更新；数据与用户配置保留） |
| 只补装/修复离线组件 | 双击 `runtime\安装离线组件.bat`，或 `... -SkipChrome` / `-SkipLibreOffice` 单独处理 |
| 只看不装（先确认） | `powershell -File runtime\setup-offline-runtime.ps1 -DryRun` |
| 卸载 | 双击「一键卸载.bat」→ 输入 Y（连用户数据一起删；保数据用 `install.ps1 -Uninstall -KeepData`） |

## 5. 体积、磁盘与时间成本

| 项 | 数值（默认瘦包 / 随包携带组件） |
| --- | --- |
| zip 包 | **≈27 MB（解耦后；具体体积以出包产物为准）** / 随包携带组件另计（见 §1.1 与 §3） |
| 解压后（部署目录） | 体积与文件数**以出包产物为准**（解耦后仅含核心插件 admin） / 随包携带组件另计 |
| 安装到 `%LOCALAPPDATA%` 后 | 程序 ≈ 27 MB（以出包产物为准）；随包携带组件时另加 LibreOffice 解压 ≈ 558 MB（核心包载荷 164 MB 仍在 `runtime\`）+ Chrome |
| 峰值额外需要 | 压缩包 + 部署目录需同时存在 → 预留空间 ≈ 出包产物体积 ×2；随包携带组件时再叠加组件包体积（以实际为准） |
| 安装耗时 | 复制文件 1~3 分钟；LibreOffice 解压 **约 13 秒**（实测 12.7 s）；Chrome 静默安装 1~2 分钟 |

> 若另装 LibreOffice 组件包：核心包（164 MB）解完后只是可重解的载荷，
> 确认 soffice 可用后可删掉它再省 164 MB（安装器会在完成时提示）。

> 不想装离线组件：**默认就不装**。应用照常运行（目标机需自备浏览器，
> 知识库 `.doc`/`.xls` 高保真通道降级）。需要旧式胖包时加 `-WithOfflineRuntime`。

## 6. 适用场景

| 场景 | 该包是否适用 | 说明 |
| --- | --- | --- |
| **内网 / 专网目标机，无外网** | ✅ **主场景** | 依赖全部随包；Chrome 与 LibreOffice 均可离线安装/解包 |
| 完全隔离（air-gap）交付 | ✅ | 除本包外不需要任何外部资源；`.NET`/MSI 均为 Windows 自带组件 |
| 目标机无管理员权限 | ✅ **部分** | LibreOffice 免管理员解包可用；Chrome 装不了 → 用机器上已有的 Edge（基线要求同内核 ≥79）或让管理员补装一次 |
| 有外网的普通机器 | ✅ 用默认瘦包 | 主包已不含组件（≈27 MB，解耦后；以出包产物为准）最省事，Chrome/LibreOffice 按需在线上或离线装 |
| 只改了前端（`static\`、`plugins\<id>\frontend\`） | ⚠️ 不必重打 | 直接改目标机上的对应文件，重启 service 即生效 |
| 只改了插件后端（`backend\*.py`） | ⚠️ 不必重打 | 目标机替换该文件后**重启服务**即生效（后端不热重载） |
| Linux / macOS 目标机 | ❌ | 当前只产出 Windows x64 产物 |

## 7. 校验

```powershell
# ① 包内组件清单与实际文件是否一致（体积 + sha256），不联网
python tools\fetch-offline-bundle.py --verify-only

# ② 应用侧自检（启动后）
#    GET /api/knowledge-base/status → office_render.available / soffice
#    GET /api/tools                 → 工具列表（插件是否全部加载）
```

> sha256 只能证明"这份字节与打包时一致"，**不能证明上游来源真实性**：Chrome MSI 官方不发布独立哈希；
> LibreOffice 官方对每个 MSI 提供 `.asc` GPG 签名，如需强验证请另行用 gpg 校验。

## 8. 已知限制与未验证项

1. **Chrome 静默安装未在提权环境实测** —— 逻辑已就绪（`msiexec /i … /qn`，已装则跳过），
   但开发会话无管理员权限，只能走到"打印提权指引"这一步。
2. **"真断网机器"上的完整链路未实测** —— 开发机上已实测：`msiexec /a` 免管理员解包 ✅、
   **裁剪核心包解压 + 应用零配置探测 + 两条真实转换链路 ✅**、`render_sheet(.xls)` /
   `render_word(.doc)` 高保真渲染 ✅（`warnings` 为空即证明没走兜底通道）。
   缺的是"从零解压 → 一键安装 → 启动"整条链路的现场走查。
3. **Chrome 组件用的是固定 URL `stable`** —— Google 会持续更新该地址内容，冻结的 `sha256`
   迟早会失配。发版前需重跑 `fetch-offline-bundle.py --pin` 刷新清单，或改用带版本号的地址。
4. **裁剪核心包只保证两条转换** —— `.doc → .docx` 与 `.xls → .xlsx`。若将来要新增
   **PDF 导入 / 图片导出 / Draw·Impress·Math·Base 相关**能力，需要重新评估裁剪清单
   （已删掉 `share\extensions`、`share\xpdfimport`、`Fonts\`、多语言资源等）。
5. **主题/帮助/拼写词典在裁剪包里没有** —— 这是 headless 转换用不到的东西，
   不影响应用功能；但如果有人想把这个便携副本当"桌面版 LibreOffice"用，它并不完整。
6. **许可文件已保留** —— `license.txt` / `LICENSE.html` / `NOTICE` / `CREDITS.fodt`
   都在裁剪包里（MPL-2.0 再分发要求保留声明）。裁剪清单里有对应不变量检查。

## 10. 常见问题

**Q：目标机能装但 Chrome 没装上，影响使用吗？**
A：不影响。Chrome 只关乎浏览体验；用机器上已有的 Edge（同内核）即可。LibreOffice 才是功能性的
（且它免管理员就能装）。

**Q：LibreOffice 组件能单独卸载吗？**
A：能，而且就该这么做。双击「卸载LibreOffice核心组件.bat」（带二次确认），等价于删除
`<程序目录>\runtime\libreoffice\`。卸载后工具箱本体照常运行，仅 `.doc` / `.xls` 高保真预览降级
（`.xls` 走 xlrd 兜底、`.doc` 明确提示不可转换）。因为安装时没写注册表、没建快捷方式，**卸载没有残留**。

**Q：装了 LibreOffice 组件后，目标机的 Office / WPS 会不会被影响？**
A：不会。组件不注册文件关联、不写 `HKEY_CLASSES_ROOT`、不改默认应用，也无快捷方式与
「程序和功能」条目 —— 对使用者是隐身的。调用时一律 headless + 唯一临时 profile，
连目标机已有的 LibreOffice 配置都不会碰。完整依据与实测见
`docs/guide/LibreOffice核心组件一键安装评估.md`。

**Q：安装 LibreOffice 组件时报「自检未通过」，怎么办？**
A：**先看日志** —— 脚本同目录下的「安装日志-LibreOffice核心.txt」，里面有系统环境、每一步结果，
以及 soffice 的**原始 stdout / stderr 与退出码**。自检失败时请把这个文件发给维护者（旧版只报
"未产出 xlsx"，等于没说）。常见原因与对策：

| 日志里的现象 | 原因 | 处理 |
| --- | --- | --- |
| `退出码=77` + `Fatal Error: 无法启动应用程序` | 核心包内 `presets\` 缺失（组件包不完整，或被杀软吃掉） | 安装器会**自动重解压后复检**；仍失败则重新获取组件包 |
| 耗时很久后 `转换超时` | 首次要初始化 profile，杀软还在扫描 2800+ 个文件；实测 20~180 秒都属正常 | 加 `-SmokeTimeoutSec 600`；或 `-SkipSmoke` 先装、再实测预览 |
| `无法启动 soffice.exe` / 进程被杀 | 杀软、AppLocker、受控文件夹访问 | 加白名单后重试 |
| `程序目录不可写` | 工具箱装在 `C:\Program Files` 之类需权限的目录 | 右键「安装LibreOffice核心组件.bat」→ **以管理员身份运行** |
| **`退出码 -1073741502`（`0xC0000142`）**<br>**`-1073741515`（`0xC0000135`）**<br>耗时仅 1~2 秒、**零输出**、profile 都不建 | 目标机 VC++ 2015-2022 运行库**缺失或版本不匹配**（管理安装解包不会把 VC 运行库放进 System32） | **安装器会自动把组件自带 `System64\` 的 DLL 补齐到 `program\`**（日志出现 `[补齐]`）。仍不行则补装 VC++ 2015-2022 可再发行组件（x64）。详见 `docs/guide/LibreOffice核心组件一键安装评估.md` §3.6 |

三条自救命令（在组件目录下执行），按顺序升级：

```
powershell -ExecutionPolicy Bypass -File install-libreoffice-core.ps1 -VerifyOnly
powershell -ExecutionPolicy Bypass -File install-libreoffice-core.ps1 -Force
powershell -ExecutionPolicy Bypass -File install-libreoffice-core.ps1 -Force -SkipSmoke
```

`-VerifyOnly` 只自检、不动文件；`-Force` 先清空旧树再解压；`-SkipSmoke` 跳过自检直接装
（装完请自己打开一个 `.doc` / `.xls` 验证）。**注意「自检失败」不等于组件不能用** ——
杀软往往只在首次拦截，此时组件其实是好的，直接启动工具箱实测即可。

**Q：为什么不在打包机上就把 LibreOffice 解包好，让目标机"零步骤"？**
A：**已经是这么做的。** 打包机用 `tools\build-libreoffice-core.py` 解包 + 裁剪 →
打成 `libreoffice-core.zip` 装进「离线组件包」，目标机只需解压（实测 **12.7 秒**），不再需要
`msiexec /a`。之所以不直接放"解好的目录"，是因为裸目录会让包体按未压缩体积增长（558 MB），
而 zip 只有 164 MB。裁剪掉的死重见 §3.1。
唯一没能做到"零步骤"的是**必须双击一次**——因为主包与组件包是分开分发的（§1.1），
这样主包才能从 437 MB（含离线组件）降到 122 MB（仅离线组件拆分），后续插件解耦进一步收窄至仅含核心插件 admin（**当前体积见 `HANDOFF.md` §2.2**），组件也能独立升级/卸载。

**Q：裁剪过的 LibreOffice 会不会影响预览保真度？**
A：不会。裁掉的是词典、界面语言、图标主题、字体、帮助这类**与格式转换无关**的东西。
`render_sheet(.xls)` / `render_word(.doc)` 的 `warnings` 为空（即走的是 LibreOffice 高保真
通道，不是 xlrd 兜底），转换产物内容与完整版一致 —— 已实测。

**Q：升级时会不会覆盖我改过的前端？**
A：会。`一键安装.bat` 会复制整包文件。改过前端请在升级后再改一次，或把改动回写到仓库源码
（推荐：下次打包即带上）。

## 11. 插件包（单独升级某一个插件）

> 设计依据：`docs/design/插件独立升级方案-设计文档.md`（方案 / 契约 / 验收口径）。
> 本节是目标机操作口径，与 §4 的整包部署并列。

### 11.1 什么时候用它

- 某个插件修了 bug 或加了功能，其它插件与主程序都没动 → 出**插件包**（体积随插件而异、以出包产物为准），不必重出整包（解耦后 ≈27 MB；以出包产物为准）。
- 目标机是**离线**的 → 插件包和整包一样是"解压 + 双击"，不需要联网。
- 需要新增/卸载某个插件 → 同一套工具（插件包带注册片段时可一键上架）。

### 11.2 目标机操作（两条等价路径）

**路径 A：离线脚本（推荐，免管理员、可离线）**

```
1. 解压 JZToolsHub-插件-<插件id>-v<版本>.zip 到任意临时目录
2. （推荐）先体检：powershell -ExecutionPolicy Bypass -File install-plugin.ps1 -List
3. 双击「安装插件.bat」，读控制台结论；浏览器按一次 Ctrl+F5
```

**路径 B：管理后台（推荐，免命令行、免解压，管理员操作）**

```
1. 浏览器登录工具箱 → 管理后台 → 「插件管理」卡片（仅超级管理员可见）
2. 「离线升级包」处选择 zip（整包上传，不要解压）→ 校验并预览（先只读校验，给出增删改计划）
3. 确认无误 → 点「确认应用」→ 程序自动完成 备份 → 替换 → 停服重启，页面恢复后自动刷新
4. 可选：在「共享盘批量更新」处填共享盘上的 index.json 路径 → 检查更新 → 勾选 → 批量升级
   （全部成功后同样自动重启一次）
```

页面上的「应用后自动重启服务」默认勾选；取消勾选后回到"应用完自己点「立即重启服务」"的旧行为。
自动重启期间服务约 5~10 秒不可用，页面会自行等待并刷新，无需人工干预。

两条路径**用同一套校验规则**（规则单点定义见 `docs/design/插件独立升级方案-设计文档.md` §4/§5.3），
产物格式也完全一致；区别只是"谁来跑"：脚本走命令行、后台走页面。页面上的「回滚」「启用/停用」
也在同一处操作。

安装器会依次做：**只读校验**（包结构 / 逐文件 SHA256 / 目标机版本 / 主程序最低版本）
→ **备份旧版**到数据根 `backups\plugins\<插件id>\` → **替换代码**（只动 `plugins\<插件id>\`）
→ **登记状态**（数据根 `config\.app_state.json`）→ 需要时**停/启服务并冒烟自检**。
**任何拒绝都发生在第一次写操作之前**，拒绝时目标机与升级前逐字节一致。

### 11.3 常用命令

| 动作 | 命令 | 是否重启 |
| --- | --- | --- |
| 安装 / 升级 | 双击「安装插件.bat」（或 `install-plugin.ps1`） | 含后端改动时自动停→启（约 2 秒） |
| 体检 | `install-plugin.ps1 -List` | 否 |
| 只演算不落盘 | `install-plugin.ps1 -DryRun` | 否 |
| 回滚 | `install-plugin.ps1 -Rollback <插件id>` | 视包而定 |
| 卸载 | `install-plugin.ps1 -Uninstall <插件id>` | 是 |
| 同号重装 / 越过版本限制 | 追加 `-Force`（仍强制校验哈希） | — |

- 指定目录：`-InstallDir <程序目录>`；数据根不在默认位置时 `-DataRoot <数据根目录>`。
- 纯前端插件可 `-Hot` 不停服替换（含后端改动的包会被拒绝）。
- 用户数据全程不动：只读校验、备份、替换都只涉及程序目录与 `backups\`。

### 11.4 开发侧出包

```
powershell -ExecutionPolicy Bypass -File tools\build-plugin-package.ps1 -Id <插件id>
```

产物在 `deploy\插件包\`（`JZToolsHub-插件-<id>-v<版本>.zip` + 旁挂 `.sha256`），
同时更新入库的发布登记 `tools\plugin-packages.json`。构建期强制校验（任一失败即中止）：

| 校验 | 说明 |
| --- | --- |
| 版本递增 | `manifest.json.version` 必须大于上一发布版本（防"改了但没升版本"） |
| 前端缓存戳 | 改过 `.js`/`.css` 就必须递增入口页的 `?v=N`（规范 F-2） |
| 依赖白名单 | 后端第三方依赖必须 ∈ 框架已打包清单 ∪ 插件自带 `vendor/`（否则目标机必然 ImportError） |
| 运行态零夹带 | `data/`、`.task_cache/`、`out/`、`config.json`、`__pycache__` 等一律剔除（与整包清理同一份规则文件） |
| 结构合法 | `manifest.json` / `entry` / `backend/routes.py` 的 `register(app)` 等 |

### 11.5 与整包升级的关系（重要）

- 整包升级**不会**把已单独升级的插件降级回去：`install.ps1` 会比对数据根状态登记，
  对版本更高的插件**跳过覆盖**并打印提示（确需以主包为准时加 `-ForcePluginOverwrite`）。
- 插件新增的配置键会在**下次启动**自动补进数据根运行配置（`jztools_data.sync_plugin_templates`，
  只补缺失键、不覆盖用户已改的值）。
- 单独升级过的插件，建议尽快并入主包随下一版整包发布，避免两处版本长期分叉。

### 11.6 已知限制

- 插件包**只含插件代码**，不含 `JZToolsHub.exe` / `_internal/`（主程序更新仍走整包）；
  包声明 `min_app_version`，主程序过低时直接拒绝并提示先升主包。
- 需要**新增第三方 pip 依赖**或新外部程序的插件，不能靠插件包单独升级（要么把依赖 vendor 进插件目录，
  要么随主包发布）——构建期的依赖白名单校验会拦下这类包。
- 回滚是"整目录替换"语义：当前目录里不在该备份中的文件会被丢弃（安装器会先列出这些文件）。
- 插件包**不是签名包**：用 sha256 旁挂文件 + 可信介质传递；签名留待后续增强。
- 管理后台的**自动重启 / 「立即重启服务」只在打包运行（`JZToolsHub.exe`）下生效**：源码开发模式
  会明确提示"不自动重启"（Flask 调试重载通常会自行重启），此时应用仍然成功，只是需要手工重启。
- 「共享盘批量更新」读的是**本机可访问的路径**（内网共享盘或本地目录皆可），不做任何联网下载。
