## 0. 一页流程

| 改动范围 | 要跑的步骤 | 耗时 |
| --- | --- | --- |
| 只改文档 / 前端（`static/`、`plugins/*/frontend/`） | ② → ③ → ④ | ~3 min |
| 改了 `app.py` / 插件后端 / 第三方依赖 | ① → ② → ③ → ④ | ~10 min |
| 只改一个插件 | **别重出主包**，出插件包（`tools/build-plugin-package.ps1`，见 README §3.4） | ~1 min |

```powershell
# ① PyInstaller（源码改了才跑；产物 dist\JZToolsHub\ = exe + _internal）
python -m PyInstaller --noconfirm --clean --distpath dist --workpath build JZToolsHub.spec

# ② 增量组装 deploy\服务端\JZToolsHub\（复制 + 清理运行态 + 模板自检 + version.json + start.bat）
python tools\build-deploy-local.py -Version 2.1.0     # 同号重出加 --force；先看计划加 --check-only

# ③ 压缩出包 → deploy\服务端\JZToolsHub-v<版本>.zip
powershell -ExecutionPolicy Bypass -File build-deploy.ps1 -ZipOnly

# ④ 校验（必跑；--smoke 再加解压启动冒烟）
python tools\verify-package.py deploy\服务端\JZToolsHub-v2.1.0.zip --smoke

# ⑤ 上线自测（可选，会停掉本机正在跑的服务）
powershell -ExecutionPolicy Bypass -File deploy\服务端\JZToolsHub\install.ps1
```

**为什么不直接跑完整的 `build-deploy.ps1`**：它开头会 `Remove-Item -Recurse` 删 `dist/`、
`build/`、部署目录，本机工具会话的 safe-delete 把「批量删除 >50 项」拦成进程中断；且整包构建
（PyInstaller 冷缓存 ~6 min + 组装 + 压缩 ~3 min）会撞工具 **600 s 命令上限**。
所以拆两段：PyInstaller 与压缩各自单跑，组装用 `tools\build-deploy-local.py`（**增量合并，从不删库**）。
`-ZipOnly` 用既有部署目录重压缩，**版本号取部署目录里的 `version.json`**，与 ② 天然衔接。

## 1. 前置检查（30 秒）

- **工作区必须干净**：`git status --porcelain` 为空，否则 `version.json.commit` 记 `<sha>-dirty`
  （事后无法定位这个包是哪份源码打的）。临时文件、日志、解压冒烟目录**一律放仓库外**（`%TEMP%`）。
- **先 commit 再出包**：包内带 `README.md`/`HANDOFF.md`，要让「包内文档 = 戳指向的提交」，
  就得先提交文档再组装（否则包里的文档比发布记录旧一版）。
- **打包解释器**：`python -V` 须为 **3.14.x**；第三方依赖 14 项齐全
  （缺 `zfec` 用 `pip install --find-links wheels zfec`，它没有 3.14 官方 wheel）。
- **`dist` 要不要重跑**（省 6 分钟）—— 与本手册其余命令一致，用 **PowerShell** 比对时间戳
  （GNU `find -newermt` 在 Windows 上不可用：`find` 是文本过滤器）：
  ```powershell
  $t = (Get-Item dist\JZToolsHub).LastWriteTime
  Get-ChildItem app.py, jz_*.py, jz_host, static, plugins, config, docs -Recurse |
    Where-Object LastWriteTime -gt $t
  ```
  （`jz_*.py` / `jz_host` 即框架源码——jz_host 为 P2-4 拆出的宿主模块包，改动必须重跑 ①）
  无输出说明源码未变，**可复用现有 dist**，只跑 ②③④。

## 2. 版本号规则

- **一律三段式 `X.Y.Z`**：`plugin_admin.semver_cmp()` 只认 `\d+\.\d+\.\d+`；两段式 `2.0` 会让插件包
  `min_app_version` 校验退化成「版本号无法比较 → 跳过该项」。
- **必须大于上一版**（版本号是目标机 `sync_templates()` 的触发依据；同号 → 模板同步全跳过）。
  只在「只改了文档/工具、无功能与模板变化」时才 `--force` 同号重出。
- 既有部署目录里的 `app` 就是上一版，`build-deploy-local.py` 会自动 patch 递增。

## 3. 组装（`tools/build-deploy-local.py`）做了什么

**组装只有这一份实现**（2026-10-10 P2-2：原 `build-deploy.ps1` §3.1–§4 的整段组装已并入本脚本，
`.ps1` 全程跑时反向调用本脚本组装——不再有两份口径要一起改）。
**随包清单单一真源 = `tools/package-content.json`**（`core_plugins` / `copy_dirs` / `copy_files` /
`tools_dirs`；本脚本、`build-deploy.ps1`、`tools/verify-package.py` 三方共读，**改口径只改它一处**）：

1. `dist\JZToolsHub\*`（exe + `_internal`）→ `deploy\服务端\JZToolsHub\`；
2. `static/` + 核心插件 `plugins/admin/`、`plugins/store/`（**仅核心插件白名单=admin+store，非全量插件**）+ `tools/plugin-upgrade/`（**仅此子目录，非全量 tools/**）
   + **`docs/README.md`、`docs/guide/`、`docs/design/`** + 四份根契约文档（`README.md`、`HANDOFF.md`、`插件设计规范.md`、`移动端APP.md`）
   + `config\tools.json` + `install.ps1` + 两个 bat（`一键安装.bat`、`一键卸载.bat`）；
   > **`wheels/` 已移出主包**（解耦后无运行时消费方；`zfec` 等改由「依赖组件包」提供）；主包默认不含离线运行组件（瘦身），
   > 口径见 `tools/package-content.json`（`core_plugins` / `copy_dirs` / `copy_files` / `tools_dirs`）。
   > **docs 分层随包（2026-09-17 起）**：只带"交付层 `guide` + 设计层 `design` + 索引"；
   > 内部层 `docs/eval`（一次性评估稿）、`docs/plan`（活清单）、`docs/archive`（历史留证）**不随包**。
   > 口径定义在 `tools/package-content.json`（单一真源，**改一处即改全**），
   > 改完 `verify-package.py` 会断言"内部文档层未随包"。
3. 复制与清理都读 `tools\plugin-payload-rules.json`（与「插件包」共用真源）——**排除清单以该 JSON 为准**，
   本文只列要点：目录 `data`/`.task_cache`/`__pycache__`/`out`/`node_modules`/`.venv`/`venv`/`.git`
   与**保留名 `dev`**（只放开发用验证服务，绝不能上目标机；插件目录命名请避开它）；
   文件 `config.json`/`config.local.json`/`.env`/`_build_phase8.py`…；
   通配 `*.pyc`/`*.pyo`/`*.log`/`*.tmp`/`*.orig`/`*.bak*`/**`test_*.py`**/**`conftest.py`**
   /`*_test.py`/`*.mp4`/`yunfu*`/`simulate_*.py`/`generate_qr_stream.py`（后四项是 map-marker 的本地测试素材，已 gitignore）；
   对 `plugins/` 再兜底清一遍；
   > **插件内的 `test_*.py` 不随包（2026-09-17 起）**：只服务开发与构建期，目标机不需要
   > （此前 5 个插件测试脚本会随整包与插件包一起分发，属 20260914 评估报告 P1-3 遗留项）。
4. **模板自检** 期望数由**组装侧**按 `tools/package-content.json` 的 `core_plugins` 动态累计
   （组装只有一份实现，改口径只改该 JSON）；**`tools/verify-package.py` 用的是静态常量
   `TEMPLATE_MIN`**（当前 0，即"不因模板数量失败"），别把两者的口径混起来。当前核心插件 admin 无 `*.template.json`
   → **期望数为 0**，不足即中止；
5. `logs/` 目录、`version.json`（**UTF-8 无 BOM**，Python `json.load` 遇 BOM 报错）、
   `start.bat`（**GBK**，= PowerShell `-Encoding Default`）；
6. `config\installed-deps.json` —— **已安装依赖清单**（`scope=shipped`，取自 `_internal` 实际随包集合），
   由 `tools\gen-installed-deps.py --out <部署目录>\config\installed-deps.json` 在打包解释器上生成；
   **生成步在组装脚本**（`build-deploy.ps1` 全程跑时调用它，同一份实现），在
   dist 拷贝之后调用（因为 `gen-installed-deps.py` 由 `--out` 反推 `<程序目录>\_internal`）；
   `tools/verify-package.py` 把该文件列为 `REQUIRED` 必需项（缺了 ④ 校验必失败），
   并交叉断言「清单包集合 ↔ `_internal` 实际随包集合」双向一致。

**不管**：PyInstaller、压缩、删 `dist/`、删部署目录 —— 后两者故意不做（safe-delete 与复用 dist）。

> ⚠️ **调整过 `docs/` 目录结构后，首次出包前要先清空 `deploy\<部署目录>\docs\`**：
> 组装是**增量合并**（只写不删），源里已不存在的旧文件会滞留在部署目录里并被打进包。
> 例：2026-09-17 docs 分层时，旧平铺的 21 份 `docs\*.md` 就属于这类残留。

## 4. 校验（`tools/verify-package.py`）

检查项（口径与 `verify-package.py` 一致；数值阈值随解耦动态化）：

- zip CRC 全量、文件数合理、**无顶层目录前缀**、`REQUIRED` 关键文件齐、`start.bat` 为 GBK；
- `version.json` **七字段**（`app` / `schema` / `commit` / `built_at` / `python` / `offline` / `plugin_api`）+ `app` 三段式 + `commit` 无 `-dirty`；
- 配置模板阈值：`verify-package.py` 用**静态常量** `TEMPLATE_MIN = 0`（当前核心插件 admin 无模板 → 阈值为 0）；动态累计在组装侧（见 §3 第 4 项）；
- `config/installed-deps.json` 多项断言：可解析且非空、`modules` 映射非空、`scope == "shipped"`、清单包集合与 `_internal` 实际随包分发集合一致；
- `plugins/` **仅含核心插件 admin+store**（无非核心插件）、**不含 `wheels/`**、`tools/` **仅含 `plugin-upgrade`**、`plugins/` 无运行态夹带；
- 无内部文档层 / 插件测试脚本随包（`docs/{eval,plan,archive}`、`test_*.py` / `conftest.py`）；
- 末尾打印 zip 的 sha256。
`--smoke` 追加：解压到 `%TEMP%` → **自动挑空闲端口**（不会撞本机 5000 上正在跑的服务）→
`JZTOOLS_DATA_ROOT` 指向临时目录启动（**真实数据根零污染**）→ 断言首页 200 / 登录页 200 /
匿名 `/api/*` 401 → 杀进程，打印日志尾部与冒烟目录路径。

> 注意：`/api/<不存在的路由>` 匿名访问也回 401（Flask 的 `before_request` 在路由匹配之后、
> 404 抛出之前执行），**不能用「某接口返回 404 还是 401」判断跑的是哪版代码**；看
> `version.json` 与插件 `manifest.json` 版本。

## 5. 上线

| 场景 | 操作 |
| --- | --- |
| 目标机安装/升级 | 拷 `deploy\服务端\JZToolsHub-v<版本>.zip` → **解压**（内容直接在根）→ 双击 `一键安装.bat` → `start.bat` 或桌面图标启动 |
| 本机自测上线 | `powershell -ExecutionPolicy Bypass -File deploy\服务端\JZToolsHub\install.ps1`（同版本重跑合法，会整体覆盖程序文件） |
| 离线组件（不在主包） | 另解压 `deploy\服务端\JZToolsHub-离线组件-LibreOffice核心-<版本>.zip` → 双击安装 bat（免管理员、对目标机隐身）；Chrome 组件才需提权。**该包不走商店上架**（消费侧=服务器；边界详见「出包体系总览 → 两类组件的边界」） |
| 卸载 | `一键卸载.bat`（删程序 + 用户数据）；保留数据用 `install.ps1 -Uninstall -KeepData` |

- 安装**不碰用户数据**：数据根 `%USERPROFILE%\.jztoolshub`，只合并 `config\tools.json`（保留用户
  启停/排序）与补全插件 `config.json`（保留 LLM 配置）；`plugins/` 中「已用插件包单独升到更高版本」
  的插件默认跳过（防回退），要强制以主包为准加 `-ForcePluginOverwrite`。
- **`install.ps1` 会停掉正在运行的服务且不自动重启**：装完记得起 `start.bat` / 桌面图标。

### 5.1 壳身份门与发版顺序（2026-10-11 需求①，硬约束）

- **浏览器只保留管理后台**：业务面（`/`、`/tool/*`、插件页面、业务 API、商店）对无壳标识的请求一律 403（`jz_host/shell_gate.py`）；管理后台 `/admin` 照常。接入密钥在管理后台「系统设置 → 桌面端接入密钥」查看/复制/重置（数据根 `config/shell-token.json`，首启自动生成）。
- **发版顺序 = 客户端先发、服务端后发**：新客户端对旧服务端多带一个头（无副作用）；旧客户端对新服务端会 403（客户端显示"需要接入密钥"指引，不白屏）。全量升级窗口先发桌面端包，再发主包。
- **密钥分发**：管理后台复制密钥 → 各桌面端「连接设置」（客户端菜单 `/connection` 页）填写，或写入 `%LOCALAPPDATA%\JZClient\config.json` 的 `remote_token`（构建配置 `server.default_token` 可预置）。
- **紧急开关**：`JZTOOLS_SHELL_ENFORCE=0`（环境变量）或 `shell-token.json` 的 `"enforce": false` → 门整体放行（排障用，启动日志明示）；密钥重置后所有已分发旧密钥立即失效。
- 验收命令：`python tools\e2e\browser-gate-tests.py`（51 项台架）；`verify-package.py --smoke` 已含门口径断言（首页 403 / 带密钥匿名 401 / /admin 可达）。

### 5.2 账号级插件安装批次 · 发版顺序与升级说明（2026-10-12 落地，硬约束）

- **发版顺序 = 服务端先、客户端后**（与 §5.1 相反，两批交替）：客户端网格依赖服务端 store 插件的 installs API（`GET/POST /plugin/store/api/installs`）。新客户端连旧服务器 → 自动降级为旧行为（机器级网格、不合成云卡，不报错）；旧客户端连新服务器 → 不调用新 API，不受影响。两侧可独立滚动升级，全量升级窗口**先发主包（含 store 插件），再发客户端包**。
- **升级后用户可感变化（三条必读，漏写会变成"故障上报"）**：
  1. **新账号空网格**：登录后只显示该账号已安装的插件（账号级登记制取代"全部直出"）——新账号/升级后首次使用需到「插件商店」逐个安装；A 类服务器插件也要装一次（装的是前端副本，秒级）。
  2. **遗留数据归属**：升级后**首个登录账号**自动继承旧机器级插件数据（`<客户端数据目录>\plugins\` → `users\<账号>\plugins\`，自动迁移一次）；**其他账号空白起步**——多账号场景需把 `users\<首个账号>\plugins\<插件id>\` 目录树手工复制到自己的账号目录。
  3. **卸载语义变化**：卸载=从当前账号移除（本机副本保留为缓存，其他账号或重新安装时秒级可用）；「清除数据」只清当前账号名下数据；不再出现「已从本机移除」徽标。
- **服务器端注意**：`<数据根>\store\installs.json` 为新增契约物（store 插件唯一写方，schema 1）；随数据根整体备份。admin 后台暂不展示各账号安装情况（D14，后续需要再立小卡）。
- **降级兼容**：客户端对 installs API 404 有探测降级（不设版本比较，D16）；离线/断网按 `account-state.json` 快照显示（云卡按钮禁用并提示需连接服务器）。
- 验收命令：`python tools\e2e\account-store-tests.py`（55 项台架）；真机走查 → `docs/guide/桌面端与商店真机验收清单.md` R12。

## 6. 坑清单（发版前扫一遍）

| # | 坑 | 对策 |
| --- | --- | --- |
| 1 | 版本号没递增 → 目标机模板同步静默不生效 | 递增 `-Version`；同号重出必须 `--force` 且清楚后果 |
| 2 | `version.json.commit` 带 `-dirty` | 出包前 `git status --porcelain` 必须为空；临时文件放仓库外 |
| 3 | safe-delete 拦「批量删除 >50 项」→ 组装/清理中断 | 别删库：走增量组装；子进程 `powershell -File` 无包装器但整包会超时 |
| 4 | 整包构建 >10 min 撞 600 s 命令上限 | 拆步跑；压缩与解压冒烟都放**后台**，日志重定向到仓库外 |
| 5 | 配置模板命名为 `config.json` → 被清理规则删掉 | 模板一律 `*.template.json`；安装期（`install.ps1 Sync-ConfigTemplates`）与运行期（`jztools_data.sync_plugin_templates`）均为**自动发现**，无需任何登记清单 |
| 6 | `version.json` 带 BOM / `start.bat` 写成 UTF-8 | 组装脚本已按 UTF-8 无 BOM、GBK 处理，别手改 |
| 7 | zip 变成有顶层目录前缀 | `Compress-Archive -Path "$AppDir\*"` 的产物**无**前缀，是历史约定，解压即用 |
| 8 | 源码没改却重跑 PyInstaller | 用 §1 的 PowerShell 时间戳比对判定，能省 6 分钟 |
| 9 | 只改一个插件却重出主包 | 出插件包（<10 MB）；插件包构建期强制校验版本递增、`?v=N` 递增、依赖白名单（真源 = `JZToolsHub.spec` 的 `PACKAGES` **∪ `DEP_COMPONENT_PACKAGES`**；后者由「依赖组件包」提供，需目标机装对应组件、缺则插件降级）、零夹带运行态 |
| 10 | 组件包与主包搞混 | 主包**默认瘦身**（无 `runtime/`）；`install.ps1` 判定看**源包** `runtime\manifest.json`，不是目标目录 |
| 11 | 包内出现 `tools\plugin-upgrade\__pycache__\*.pyc` | **应视为漏清理**：`tools/` 只随包 `plugin-upgrade` 子目录（组装脚本 `tools/build-deploy-local.py` 只拷这一处并对其套用清理规则），出现即查 `tools\plugin-payload-rules.json` 的规则是否被改过 |
| 12 | 目标机插件包被拒但只显示「HTTP 400」 | admin ≥1.3.1 已逐条给原因；四类：同版本重装 / 主程序过低 / 包损坏（哈希不符）/ 全新安装缺 `tools_entry`（见 README §3.4 排查表） |

## 7. 故障处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| `build-deploy.ps1` 报 `InputObjectNotBound` | 工具会话的 `Remove-Item` 包装器不支持管道输入 | 别在工具会话里跑整包脚本；走两段式 |
| 命令被中断/超时 | PyInstaller 冷缓存 + 压缩 | 分步执行；后台跑压缩；必要时只跑 `-ZipOnly` |
| 组装报「dist\JZToolsHub 不完整」 | 没跑过 PyInstaller 或产物被删 | 跑步骤 ①，或确认 `dist\JZToolsHub\JZToolsHub.exe` 存在 |
| 模板自检（阈值随核心插件动态计算，admin 无模板 → 0，不会因数量失败） | 当前不会因模板数量不足失败；阈值由 `tools/package-content.json` 的 `core_plugins` 自动累计，新增含模板的核心插件后才会生效 | 模板一律 `*.template.json`；看 `tools\plugin-payload-rules.json` 是否被改过 |
| `verify-package.py --smoke` 启动失败 | 被安全软件拦 / 端口争用 / 数据根无写权限 | 看打印的进程日志尾部；换机复现；确认 `%TEMP%` 可写 |
| 目标机装完服务没起 | `install.ps1` 不自动启动服务 | 双击 `start.bat` / 桌面「JZToolsHub」 |
| 目标机预览 Office 文件失败（仅旧版 .doc/.xls 保真预览；docx/xlsx/pdf 走 HTML 渲染不依赖它） | 主包不含 LibreOffice 组件（knowledge-base 可选外部依赖） | 装 LibreOffice 核心组件包（双击安装 bat，免管理员；**勿传商店**） |

## 管理进程（supervisor）分件安装与逐插件 worker 迁移（批次 11；T-O2-12 遗留落地）

> 目的：把 A 类服务器插件从「主应用进程内」切到「并列 worker 进程」（隔离 native 崩溃 / OOM，主应用不变）。
> 机制与演练真源：`tools/e2e/worker-migration-demo.py`（8/8——注册单元 → 重启主应用跳过进程内加载 →
> supervisor 拉起 → 真实登录 → 反代访问 worker（身份回环取真实用户）→ 停单元该插件 503 而主应用/登录态照常）。

| 步骤 | 操作 |
| --- | --- |
| ① 分件 | `powershell -File tools\uild-supervisor-package.ps1` → `deploy\服务端\supervisor分件\`；`nssm.exe`（Apache-2.0，不入仓库）由运维放入 `install\` |
| ② 服务化 | `install\install-supervisor.ps1` 注册 Windows 服务（NSSM；服务账户下 `JZTOOLS_DATA_ROOT` 显式注入，确认与主应用同一数据根） |
| ③ 登记单元 | `<数据根>\config\supervisor-units.json` 的 `units` 增一条：`{"name": "<id>", "kind": "plugin", "plugin_id": "<id>", "port": <固定端口>}`（端口分配一次、长期占用；token 在同目录 `.supervisor_token`） |
| ④ 切主应用 | 重启主应用——启动时**跳过 worker 化插件的进程内加载**，该插件 `/api/<id>/*` 由反代桥转发到 worker |
| ⑤ 验证 | 该插件 API 走通（反代 200）；控制面 `POST /stop` 停单元 → 该插件 503 而主应用、登录态、工具清单照常；worker 日志落 `<数据根>\logs\workers\<单元>.log` |
| ⑥ 回滚 | 从 `units` 移除该条目 → 重启主应用（回到进程内加载，零迁移） |
| 顺序（Q7 拍板） | `knowledge-base` → `shared-docs` → `case-report`（notice-board 已于演练通过） |

### 两类组件的边界（别把离线组件传商店；2026-10-08 增补）

`依赖包` 下的两类包**消费侧完全不同，不可互换**：

| | 依赖组件包（`组件包\JZToolsHub-依赖-*.zip`） | 离线组件包（`离线组件\JZToolsHub-离线组件-*.zip`） |
| --- | --- | --- |
| 载荷 | `payload/pylibs/…`（Python 组件：cv2/numpy/openpyxl…） | 自有运行时（LibreOffice 裁剪核心 → `runtime\libreoffice\`；另如 Chrome 组件） |
| 消费侧 | **客户端** `runtime\pylibs\`（插件 import 用；.pending 语义） | **服务器/目标机**程序目录（knowledge-base 的 soffice 查找链第三档） |
| 分发方式 | **商店「依赖」类目上架**（dep-slot；上架机器校验要求 `dep-component.json`+组件清单） | **手工部署**：解压 → 双击包内「安装LibreOffice核心组件.bat」（免管理员）；**不走商店上架** |
| 误传表现 | — | 把离线组件传商店 → 机器校验报「包内缺少组件清单」（格式门禁，属正确拦截） |

- **离线组件当前唯一消费者 = knowledge-base（可选依赖 `required:false`）**：仅影响**旧版 `.doc` / `.xls` 的样式保真预览**（xhr 引擎 LibreOffice 归一化）；`.docx/.xlsx/.pdf` 走双引擎 HTML 渲染不受影响；不装时插件页/后台显示缺件降级提示。
- 服务器侧离线组件的商店通道**已评估未实施**（服务器组件通道属新形态，2026-10-08 需求方口径：不做，维持手工部署 + 本手册）。

双端联动规则（红线 4 的操作化）

1. **共享内核模块（#2）变更**：主包全量自检+smoke 与客户端 verify-client --smoke **双绿**才可提交；
2. **HTML 前端（#3）变更**：主包出包后**必须重建客户端程序包**（客户端自带 static 副本随客户端包发版）；
3. **类 A 插件（#5）变更**：仅出插件包——插件升级在服务器侧完成，客户端经中继零动作；
4. **本地插件（#8）变更**：客户端管理页装包即时生效（worker 全热；hybrid 升级走秒级重启口径，会话免重登）；
5. **依赖分件（#9）**：三份独立更新；**程序更新不触碰 `runtime\` 内核目录**（build-client 已实现保留逻辑，T31 实证）。
