## 1. 环境基线核查（装任何东西之前）

> **为什么必须先查**：开发机通常装过 VC++ 运行库，会把"缺运行库"的问题掩盖掉（假阳性）。
> 第 5 项是本清单的核心——**只有它为 False 的机器，才能验证出真问题**。

| # | 检查 | 命令（PowerShell） | 通过口径 |
| --- | --- | --- | --- |
| 1 | 系统版本 | `[Environment]::OSVersion.Version` | Windows 10 / 11（Python 3.14 基线） |
| 2 | 架构 | `$env:PROCESSOR_ARCHITECTURE` | `AMD64`（arm64 未验证，见 §7） |
| 3 | 是否装过 Python | `Get-Command python -EA SilentlyContinue` | **应为空**（本方案不需要目标机有 Python） |
| 4 | 是否装过 VC++ 2015-2022 运行库（注册表） | `Test-Path 'HKLM:\SOFTWARE\Microsoft\VisualStudio\14.0\VC\Runtimes\x64'` | 记下结果（True 也不阻断，但见第 5 项） |
| 5 | **`msvcp140.dll` 是否存在于系统** | `Test-Path C:\Windows\System32\msvcp140.dll` | **False = 真干净**（能测出问题）；True = 本机测不出该风险，换机器 |
| 6 | 磁盘可用空间 | `(Get-PSDrive C).Free/1GB` | ≥ 1 GB（全量装约 110 MB） |
| 7 | **依赖清单口径**（解包后查主体） | `python -c "import json;d=json.load(open(r'<解包目录>\config\installed-deps.json',encoding='utf-8'));print(d['scope'],len(d['packages']))"` | 输出 `shipped 9`——**不是** `all 93`。口径错会把"目标机上没有的包"判成已安装，缺依赖提示与红 × 都不出现 |

**记录**：把第 4/5 项结果填进 §6 记录表——它决定本次验收对"VC 运行时"这一项的结论是否有效。

## 2. 准备介质

| 分发物 | 文件名（示例） | 必需 |
| --- | --- | --- |
| 主体 | `JZToolsHub-v<版本>.zip`（本批为 **v2.3.3**） | ✅ |
| 依赖组件包 | `JZToolsHub-依赖-<id>-v<版本>.zip` × N（见下表） | 按需（缺则对应功能降级） |
| 插件 | `JZToolsHub-插件集-初始-v<日期>.zip`（或单个插件包） | ✅ |
| 离线组件（可选） | `JZToolsHub-离线组件-LibreOffice核心-*.zip` | 仅需知识库 `.doc/.xls` 预览时（组件包内自带安装器，解压后按 `说明.md` 操作） |
| 离线组件（可选） | `JZToolsHub-离线组件-Chrome-*.zip` | 仅需统一浏览器基线时（系统自带 Edge 即可用） |

**依赖包与插件的对应关系**（决定装哪些）：

| 依赖包 | 体积 | 装它的理由（不装则该功能不可用） |
| --- | --- | --- |
| `numpy` + `cv2` | 14.6 + 47.3 MB | 信息传输 / 轨迹转换的**视频码流模式**（静态码模式不需要）。**cv2 需要 numpy**（cv2 的 import 期就依赖它）：只装 cv2 时安装器会前置提示、自检失败并点名"请再装 numpy"——**两个都要装**，顺序随意（安装器按组件安装，不会互相覆盖） |
| `docx` / `openpyxl` / `xlrd` / `olefile` / `pypdf` | 5.3 / 1.1 / 0.9 / 0.9 / 1.2 MB | 文档与表格读写：知识库预览、共享文档、战报、轨迹报表；**admin 的批量导入导出**（缺 openpyxl 时仅剩 CSV） |
| `qrcode` / `zfec` / `zxingcpp` | 0.9 / 0.9 / 1.8 MB | 二维码出码与校验、视频流解码 |
| `requests` | 1.4 MB | 各插件的大模型（AI）功能 |

## 3. 部署顺序与预期输出

### 步骤 1：装主体

```
解压 JZToolsHub-v<版本>.zip（本批 v2.3.3）→ 双击「一键安装.bat」
```
预期：安装到 `%LOCALAPPDATA%\JZToolsHub`；控制台出现
「**[提示] 当前只有核心插件（admin），工具箱首页暂时没有工具卡片**」及插件集引导；
注册表写入 `HKCU\...\Uninstall\JZToolsHub`（`-NoRegistry` 可跳过）。

冒烟：启动 → 首页 200、能打开登录页、用 `admin / admin123` 登录成功。

> **若这一步失败**（服务起不来 / 登录页 500）：属**主体**问题，按 §5 第 1 条排查。

### 步骤 2：装依赖组件包（顺序无关，可只装需要的；但**组件间依赖必须装齐**）

```
解压 JZToolsHub-依赖-<id>-v<版本>.zip → 双击包内「安装依赖组件.bat」
（PowerShell 等价：`powershell -ExecutionPolicy Bypass -File install-dep-component.ps1`）
```
预期：安装器打印取源/版本 → 安装到 `<程序目录>\runtime\pylibs\` → 调用
`JZToolsHub.exe --check-deps` 做**真实 import 自检** → 末尾「完成：本依赖已可用…」。

| 结果 | 含义 |
| --- | --- |
| 退出码 0 + 自检 `{"imports": {"<包>": "ok"}}` | ✅ 通过（**这就是 VC 运行时的验证点**：自检是真的 import，不只是"文件在不在"） |
| 退出码 1 + `DLL load failed` | ❌ 缺系统运行库 → 见 §5 第 2 条 |
| 退出码 1 + "版本不匹配" | ❌ 组件包与主程序 Python 版本不符 → 取对应批次的组件包 |

体检命令：`powershell -ExecutionPolicy Bypass -File install-dep-component.ps1 -Check`

**每个组件装完的判定**：安装器末尾的「安装结果」里 `ok: true` 且 `imports` 全是 `ok`。
装 cv2 时若看到「本组件还需要依赖组件 **numpy**」——按提示把 numpy 组件也装上即可，
本组件文件不会丢（重复运行安装器不会丢已有组件）。

**按组件卸载**（只想撤掉某一个）：`install-dep-component.ps1 -Remove cv2`（保留其它组件）；
`-Uninstall` 是**卸载全部**组件。

### 步骤 2.5（可选捷径）：后台「一键扫描安装」

介质目录解压好后（插件包 + 依赖组件包放在同一处或一层子目录内），也可**不逐个双击**：

登录后台 → 「插件管理」→「**一键扫描安装**」→ 填介质目录（留空则扫程序目录 / 上级 / 桌面 / 下载）
→ 扫描 → 勾选（默认勾上所有"可安装"项）→ 安装。

- 扫描只读：不解压、不写盘；表格里显示**包版本 vs 本机版本**、ABI 适用性与组件间依赖提示。
- 依赖组件装完**立即生效**（无需重启）；插件包含后端改动时会在装完后自动重启服务。
- 与逐个双击安装完全等价（插件包走同一套校验/备份/登记/回滚流程）。

### 步骤 3：装插件

```
解压 JZToolsHub-插件集-初始-v<日期>.zip → 双击「安装插件集.bat」
```
预期：逐个校验并安装（已是最新版的自动跳过）；结束后刷新首页**出现工具卡片**。

### 步骤 4：后台核对

登录 → 后台「插件管理」：

| 检查 | 通过口径 |
| --- | --- |
| 顶部汇总 | `可运行 N / 降级 0 / 不可运行 0`（未装依赖包时允许有降级） |
| 每行「依赖需求」列 | 已装依赖为**绿色**徽标；未装为**红色带 ×** |
| 「一键对齐登记」按钮 | 显示为灰（全部一致）或可点（有登记漂移，点一次即对齐） |
| 「查看已安装依赖（含版本）」 | 框架包（随主包 6 个）与外部组件（LibreOffice/Chrome）分列，含版本与路径；**装了依赖组件后**，该包逐项出现在列表里并带蓝色「依赖组件：<id>」标注（cv2 显示为 `opencv-python`） |

## 4. 功能冒烟（最小验证动作）

| 插件 | 动作 | 通过口径 |
| --- | --- | --- |
| admin | 登录 → 单位/部门/人员各建一条 → 批量导出 | 导出 xlsx 成功（未装 openpyxl 时提示仅 CSV） |
| knowledge-base | 上传一个 .docx 与一个 .xlsx → 在线阅读 | 内容可读；装 LibreOffice 后再传 `.doc/.xls` 亦可读 |
| info-transfer | 上传小文件 → 静态码模式 → 扫一次 | 出码可扫；**装 cv2 后**视频模式能生成 mp4 |
| shared-docs / notice-board | 建一条文档 / 公告 | 保存并列表可见 |
| character-graph / case-report / trajectory-* | 各走一次主流程（含大模型功能的需先配 API Key） | 无 500；缺依赖时给出**可操作提示**而非堆栈 |

## 5. 故障注入（验证"提示可操作"与"拒绝正确"）

| # | 注入 | 预期 |
| --- | --- | --- |
| 1 | 停掉服务，删 `_internal\python314.dll` 后启动 | 进程立即退出（主体损坏）；恢复方法：重装主包 |
| 2 | **在一台 `msvcp140.dll` 不存在的机器上**装 cv2 依赖包 | 若自检仍通过 → ✅ 组件自带的 VC 运行时生效；若失败 → 需补装 VC++ 2015-2022 运行库（或改用带 `vc_redist` 的依赖包） |
| 3 | 故意不装 `openpyxl`，打开后台批量导入导出 | 提示降级为"仅 CSV"，**不是** 500；插件列表该行显示红色 × |
| 4 | 故意不装 `cv2`，打开信息传输的视频模式 | 页面横幅列出「缺少 cv2：视频码流模式不可用…请安装依赖包 `JZToolsHub-依赖-cv2-v*.zip`」；静态码模式仍可用 |
| 5 | 把为其它 Python 版本构建的依赖包拿去安装 | 安装器在写盘前拒绝：「本依赖是为 Python X.Y 构建的，当前主程序内置 A.B」 |
| 6 | 断网后重复步骤 2~3 | 全流程离线可完成（本方案不联网） |
| 9 | **装了组件但插件仍报"未安装"** | 依次看三处：① `JZToolsHub.exe --check-deps <tmp.json>` 是否 `ok:true`（false 说明组件自身 import 不了，多为缺标准库或 VC 运行库）；② 后台「已安装依赖」是否列出了该组件（没列出说明装到了别的程序目录）；③ 插件页刷新一次（服务运行中装的组件已免重启生效） |
| 7 | 装完 `cv2` 依赖包后，再用插件包重装 info-transfer（`-DryRun` 即可） | 依赖检测表里 cv2 变 **[满足]**，并出现「（已装依赖组件：cv2）」——装过组件还报"缺失"即为旧版安装器的假缺失 |
| 8 | 在未装任何依赖包时用插件包装 info-transfer（`-DryRun`） | 表里逐项 **[可选缺失]**，并打印「提示：以下可选依赖未安装，对应功能在目标机上不可用」+ 每项的修复指引；**不得**中止安装 |

## 7. 本清单未覆盖（需另行验证）

| 项 | 说明 |
| --- | --- |
| arm64 Windows | 主体与依赖包均为 x64 构建（架构一致），Win11 arm64 靠 x64 模拟理论可行，**未实测** |
| 中文用户名 / 超长路径 | 数据根默认位于 `%USERPROFILE%`；建议用中文用户名账户跑一次首装 |

| 共享盘（UNC）路径 | 索引与包文件从 `\\server\share` 读取的权限与延迟（见 TODO T20） |
| 精简系统的 emoji 渲染 | 已有 `static/js/jz-icon.js` 的 SVG 回退；建议在精简系统上开首页目检一次 |
