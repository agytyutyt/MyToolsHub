## 1. 使用方式

1. 本清单条目在**目标机 / 真机**执行；凡能自动化的部分优先并入 `tools/e2e/`（改完即跑），不手工重复。

## 2. R1–R9 逐项

- **现状取证**：`supervisor/install/install-supervisor.ps1:41-43` 要求脚本同目录放 `nssm.exe`（或 `-Nssm` 显式指定），全仓 `nssm*` 零命中（二进制不入库）；`deploy/服务端/supervisor分件/` 组装物已齐（审计 §3.3 R1）。
- **前置条件**：目标机**管理员权限**；运维把 NSSM 放入 `supervisor/install/`；先按 runbook 安装分件（`docs/guide/打包部署手册.md` §「管理进程（supervisor）分件安装与逐插件 worker 迁移」）。
- **预期输出**：服务注册成功且 `running`；关机重启后 supervisor 与主应用自动拉起；控制接口 status / stop-start 可用；日志落数据根。
- **留痕要求**：`install-supervisor.ps1` 输出、`nssm status`（或 `sc query`）文本、重启前后进程与日志片段。

### R2 A 类插件 worker 迁移（真实数据根）

- **现状取证**：真实数据根 `~/.jztoolshub/config/` **无 `supervisor-units.json`**，`app.py:865-874` 按 units 快照决定跳过进程内加载 → knowledge-base / shared-docs / case-report / notice-board 目前**全部仍是进程内**；notice-board「试点」是临时数据根演练（`tools/e2e/worker-migration-demo.py:49` 起 `tempfile.mkdtemp`）（审计 §3.3 R2）。

- **留痕要求**：迁移前后控制接口输出、`supervisor-units.json` 快照、进程列表、逐插件走查用例与结论（含回滚一次）。
