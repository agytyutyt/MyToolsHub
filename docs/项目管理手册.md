## 1. 五分钟建立心智模型

### 1.1 一句话

**一切皆插件**：主程序（`app.py` + `jztools_data.py`）只做四件事——数据根定位、鉴权拦截、
插件后端加载、首页卡片合并；**所有业务功能都在 `plugins/<id>/` 里**，删掉插件目录不留残骸。

### 1.2 必须记住的四条主线

| 主线 | 内容 | 细节落点 |
| --- | --- | --- |
| **插件三层** | 目录即插件 → `manifest.json` 声明 → `config/tools.json` 登记（启停/排序/权限） | 《插件设计规范.md》§4–§6 |
| **数据根** | 程序目录**只读**、用户数据**只写数据根**（默认 `~/.jztoolshub`）；插件一律用 `jztools_data.get_data_root_dir/file()` 定位，禁止拼绝对路径 | `README.md` §4.2、§10 |
| **四种分发物** | ① 主包 zip（框架+全部插件）② 离线组件包（Chrome/LibreOffice）③ 插件包（单插件，<10 MB）④ APP APK | `README.md` §3、`docs/guide/离线部署包说明.md` |
| **鉴权收口** | admin 插件注册 4 个 `before_request`；白名单之外**一切路径**要求登录，非超管访问插件接口还要有该工具权限点 | `docs/design/登录改造与数据隔离-开发设计文档.md` |

### 1.3 现状数字（核对日 2026-09-17）

- 16 个插件：11 个前后端一体 + 5 个纯前端；其中 `knowledge-base` 是唯一同时带
  `frontend/vendor` 与 `backend/vendor` 的插件。
- 数据落盘约定两种形态：**单文件 JSON 库**（`data/files.json`、`data/<id>.json`）与
  **聚合文件**（`config.json` 等管理员配置）。
- 三类"授权可见即可用"的公共资源：`notice-board`、`knowledge-base` 在
  `config/tools.json` 里是 `grant_all: true`，其余 14 个都要逐人授权。

### 1.4 代码落点（改代码前先定位）

| 我要找 | 文件 |
| --- | --- |
| 框架入口、中间件、插件加载、首页卡片合并 | `app.py` |
| 数据根双指针、旧数据迁移、配置模板同步 | `jztools_data.py` |
| 鉴权/组织架构/权限/插件管理 | `plugins/admin/backend/{routes,batch_io,plugin_admin}.py` |
| 打包依赖白名单（缺库先登记这里） | `JZToolsHub.spec` 的 `PACKAGES` |
| 插件 payload 的"代码/数据"边界（两条链路共用真源） | `tools/plugin-payload-rules.json` |
| 打包随包清单 | `tools/build-deploy-local.py` 的 `COPY_DIRS`/`COPY_FILES` + `build-deploy.ps1` §3.2 |

## 2. 环境准备与第一次跑起来

1. **依赖**：`README.md` §2.3（主框架 Flask + cryptography；按需装插件依赖；
   zfec 必须加 `--find-links wheels`，否则退化为源码编译）。
2. **基线**：Python **开发最低 3.12 / 打包 3.14**；目标机 Windows 10+；浏览器 Chrome ≥72。
   依据见 `docs/eval/Python版本选型评估.md`。
3. **启动**：源码模式下插件后端有自动重载；**冻结 exe 模式改插件后端需重启服务**。
4. **别碰真实数据**：写测试时先隔离数据根（见 §3.2 第 3 条）。

## 3. 场景 A：修 Bug / 改一个已有功能

### 3.1 五步流程

1. **定位**：从现象找到插件 → 读 `plugins/<id>/README.md`（接口与已知限制）→
   再看 `docs/design/<主题>-设计文档.md`（设计契约与实现路径）。
2. **判断改动面**（决定要不要重出整包）：

| 改动范围 | 发版方式 |
| --- | --- |
| 只改一个插件（前端或后端） | **别重出主包**，出插件包（`docs/guide/打包部署手册.md` §3.4） |
| 改了 `app.py` / `jztools_data.py` / 多个插件 | 出主包 |
| 只改文档 | 出包只为同步包内文档；也可不出（但包内文档会与仓库不一致） |

3. **改之前查三条硬约束**（违反即事故，清单在 `docs/README.md` → 本文 §7）：

   - 插件后端路由函数名必须带**插件前缀**（`kb_`/`ts_`/`ff_`…）：Flask 以函数名作 endpoint，
     重名直接 `AssertionError` 且无法回滚。
   - 配置模板必须叫 `config.template.json`：打包会删光插件树内所有 `config.json`。
   - 改了插件就要递增 `manifest.json` 的 `version`；改了前端资源还要递增入口页的 `?v=N`。

4. **改 + 自测**：跑该插件的测试（`plugins/<id>/backend/test_*.py`）与相关回归；
   涉及协议的要四端齐改（§7）。
5. **回写文档**（顺序固定）：`plugins/<id>/README.md` → 相关 `docs/design/` →
   `docs/README.md`（如新增/归档文档）→ `HANDOFF.md` → `.workbuddy/memory/` 当日日志。
   详见 `HANDOFF.md` §10.1。

### 3.2 三个最容易出事的点

1. **数据归属要"取自会话"**：`created_by` / `unit_id` / `department_id` 必须从 session 取，
   **绝不接受请求体传入**（否则可伪造越权）。
2. **降级要优雅**：可选依赖缺库时该功能报错、其余功能不受影响，并在 `/status` 里暴露可用性
   （《插件设计规范.md》B-4）。
3. **测试隔离真实数据根**：优先 `app.test_client()`；需要真实服务时用 5100+ 端口，
   并把数据根指到临时目录（`JZTOOLS_DATA_ROOT` 环境变量或替换 `jztools_data.get_data_root`）。

## 4. 场景 B：开发一个新插件

### 4.1 先做选型（决定工作量）

| 形态 | 适用 | 骨架 |
| --- | --- | --- |
| **纯前端（A 型）** | 纯浏览器能算完（编解码、格式化、取色、纯前端扫描） | 只要 `manifest.json` + `frontend/index.html`（+ 可选资源） |
| **前后端一体** | 需要服务端文件处理 / 密钥 / 大模型 / 落盘协作 | `manifest.json` + `frontend/` + `backend/{__init__.py,routes.py}` + `requirements.txt` |
| **封装型（B 型）** | 把外部程序包成插件 | 见《插件设计规范.md》§8.6–§8.10 |

### 4.2 八步落地（每步都有验收动作）

| # | 动作 | 验收 |
| --- | --- | --- |
| 1 | 建目录 `plugins/<id>/{frontend,backend}` | 目录名 = 插件 id，全小写连字符 |
| 2 | 写 `manifest.json`（id/name/version/entry/…） | 字段齐、`version` 从 `1.0.0` 起 |
| 3 | 后端写 `def register(app)`，路由挂在 `/api/<id>/`，函数名带 `<前缀>_` | `flask routes` 无重名；`/api/<id>/status` 可用 |
| 4 | 登记 `config/tools.json`（站点/分类/工具条目） | 首页出现卡片；`enabled:false` 时不加载后端 |
| 5 | 数据落盘走 `jztools_data`，加**归属四字段** | 换数据根后数据跟着走；越权读返回 404（不暴露存在性） |
| 6 | 有配置就放 `backend/config.template.json`（**必须**这个名） | 首启后数据根生成对应 `config.json` |
| 7 | 前端：相对路径、`?v=N`、XSS 转义、图标用 SVG 不用 emoji | 旧 Chrome 下可见；无 JS 报错 |
| 8 | 写 `plugins/<id>/README.md`（**接口契约唯一落点**） | 含接口表、返回结构、落盘位置、已知限制 |

**带模板插件的额外登记**（易漏，漏了会静默不同步）：必须在
① `jztools_data.py` 的 `_TEMPLATE_SYNC`；② `install.ps1` 的 `Sync-ConfigTemplates` 的
`$cfgPairs` **两处同时登记**并保持一致。打包后会自检 `*.template.json` 数量（< 4 即中止）。

### 4.3 收尾自检（缺一项都不算完成）

- [ ] 《插件设计规范.md》§14 质量自检清单逐条过
- [ ] 插件后端加载失败**不影响整站**（`app.py` 已做 per-plugin try/except，你要保证不抛在导入期）
- [ ] 停用/卸载后不留残骸：删目录 + 清 `config/tools.json` 条目，数据默认保留
- [ ] 依赖清单只写实际用到的；框架未打包的库要先登记 `JZToolsHub.spec` 的 `PACKAGES`
- [ ] 出插件包并在**隔离数据根**下冒烟（`tools/e2e/plugin-upgrade-sandbox-tests.ps1` 的沙箱手法）

> **不要跨插件 import**（《插件设计规范.md》B-7）。需要复用就调对方 HTTP 接口
> （样板：`trajectory-sketch` → `file-filter` 的 `/apply`，见 `docs/design/轨迹速写插件-设计文档.md` §5），
> 或者**各存一份逐字节相同的副本 + 断言一致性**（样板：`bg_image.py`，`test_bg_image.py` 断言 sha256）。

## 5. 场景 C：项目移植（换机器 / 换环境）

### 5.1 入手顺序（照这个顺序排查，别从代码开始）

| 步 | 检查 | 为什么 |
| --- | --- | --- |
| 1 | **基线对齐**：OS、浏览器、Python | 基线不符会出现"本机能跑、现场报错"（`HANDOFF.md` §1.1） |
| 2 | **依赖白名单**：`JZToolsHub.spec` 的 `PACKAGES` + `wheels/` | 冻结包只带白名单里的库；缺库先登记 PACKAGES，**别用 `-SkipChecks`** |
| 3 | **外部组件**：`runtime/` 内容与组件包 | 主包默认瘦身，不含 Chrome/LibreOffice；靠组件包单独分发 |
| 4 | **数据根**：双指针是否被带过去 | `config/data_root.json` **是机器相关**的，已 gitignore。**不要**把它复制到新机器（否则会把数据根解析到原作者的目录，静默读写他人数据） |
| 5 | **平台差异** | 当前生产形态是 Windows 10+；Linux 形态是未实施的方向，见 `docs/eval/插件热插拔-容器化改造评估.md` |
| 6 | **离线环境** | 内网无外网时：依赖走本地 wheel / `--no-index`，组件走组件包，插件升级走共享盘或后台上传 |

### 5.2 移植后必须验的四件事

1. 隔离数据根启动 → `/` 200、匿名 `/api/*` 401（`tools/verify-package.py --smoke` 就是这套断言）。
2. `GET /api/tools` 里 16 个插件是否**全部加载**（缺依赖的会在页面提示，不会拖垮主进程）。
3. 各插件 `/api/<id>/status` 的依赖自检是否与预期一致。
4. 数据根首启迁移：旧版（数据在程序目录）会幂等迁入数据根，核对 `config/admin.json` 与 `.admin_key` **同在**。

## 6. 场景 D：打包 / 部署 / 升级 / 卸载 / 数据维护

### 6.1 操作速查

| 动作 | 怎么做 | 细节 |
| --- | --- | --- |
| 打主包 | `docs/guide/打包部署手册.md`（**唯一命令真源**） | 先 commit 再出包（包内带文档，dirty 会写进 `version.json.commit`） |
| 只升级一个插件 | 出插件包 → 目标机二选一：后台「插件管理」上传 zip / 解压后双击「安装插件.bat」 | `docs/guide/打包部署手册.md` §3.4、`docs/design/插件独立升级方案-设计文档.md` |
| 打 APP | `android-app/InfoParse/InfoParse-APP打包手册.md` | full / lite 双 flavor |
| 目标机安装或更新 | 解压主包 → 双击 `一键安装.bat` | 会先停旧进程，再按"注册表 → 默认目录 → 源目录"探测既有安装 |
| 启动 / 停止 | 双击 `start.bat`；退出右键托盘图标「退出服务」 | 默认端口 5000 |
| 装离线组件 | 解压组件包 → 双击 `安装LibreOffice核心组件.bat`（**免管理员**）；Chrome 需管理员 | **安装组件失败不会导致安装失败** |
| 卸载 | 双击 `一键卸载.bat` 输入 Y（删程序 + 数据）；保留数据用 `install.ps1 -Uninstall -KeepData` | 绿色部署可加 `-NoRegistry` |
| 换数据目录 | 后台 → 系统设置 → 填新绝对路径 → 「更改并迁移」 | 按 `config`/`logs`/`plugins` 三子目录整体**移动** |
| 备份 | 拷走数据根**三件套**：`config/admin.json` + `config/.admin_key` + `plugins/*/data/` | `.admin_key` 与 `admin.json` 必须同迁，否则无法解密 |
| 看日志 | 数据根 `logs/access.log`（按天滚动，保留 30 天） | 启动期日志另见服务端输出 |
| 排障 | `docs/guide/打包部署手册.md` §6/§7 + `HANDOFF.md` §7 | 前者发版坑，后者运行期坑 |

### 6.2 三条运维铁律

1. **只递增版本号**：`-Version` 不传会自动递增 patch；版本不变 → 目标机判为未升级、
   **跳过配置模板同步**（新版配置不会生效）。三段式 `X.Y.Z`，脚本只认这个格式。
2. **插件升级的顺序是"先替换、后停服"**（admin ≥1.3.0 起后台上传即全自动：
   校验 → 备份 → 替换 → 按需停服重启 → 页面自动刷新）。
3. **数据根是唯一有状态的地方**：备份/迁移/排障都围绕它；程序目录可以随时整体替换。

## 8. 新手最常踩的 10 个坑（每条一句话 + 出处）

| # | 坑 | 一句话对策 | 出处 |
| --- | --- | --- | --- |
| 1 | 插件后端路由函数重名 → 启动即 `AssertionError` | 函数名一律 `<前缀>_` 开头 | §7 G1 |
| 2 | 配置模板写成 `config.json` → 被打包删掉、同步静默失效 | 一律 `.template.json` | `README.md` §10.2 |
| 3 | 新增带模板插件只登记了一处 | 两处同时登记且保持一致 | §4.2 |
| 4 | 把 `config/data_root.json` 提交/带到新机器 | 它机器相关，已 gitignore，别复制 | §5.1 |
| 5 | 归属字段从前端传参 | 一律取自会话 | §7 G6 |
| 6 | 改了插件但没递增 `?v=N` → 目标机拿旧缓存 | 纯前端改动必须戳版本 | §7 G3 |
| 7 | 依赖没登记 PACKAGES，现场 `ImportError` | 缺库登记 PACKAGES，别 `-SkipChecks` | §5.1 |
| 8 | 测试跑在真实数据根上 | 用 `test_client` 或 `JZTOOLS_DATA_ROOT` 临时目录 | §3.2 |
| 9 | 版本号没递增 → 模板同步不触发 | 出包必递增（脚本会拦同号） | §6.2 |
| 10 | 改了功能不回写文档 | 固定回写链，顺手更新文档的"最后核对" | §7 G8 |

## 9. 故障速查路由

| 现象 | 去哪 |
| --- | --- |
| 打包/校验/上线失败 | `docs/guide/打包部署手册.md` §6 坑清单 / §7 故障处置 |
| 目标机装不上、组件没生效 | `docs/guide/离线部署包说明.md` §8 已知限制 / §10 常见问题 |
| 插件在目标机升级被拒（HTTP 400） | `docs/design/插件独立升级方案-设计文档.md` §4 + `docs/guide/打包部署手册.md` §3.4 排查表 |
