# 离线部署包说明

本文说明 `deploy/JZToolsHub-v<版本>.zip`（离线部署包）的**组成、安装方式、体积与时间成本、
适用场景和已知限制**。目标是让接手者在没有任何上下文的情况下，能判断"这个包能不能用在我这台机器上"。

> 相关文档：`README.md` §3.2/§3.3（打包与安装）、`HANDOFF.md` §1.1（环境基线）、
> `runtime/README.md`（离线组件的版本、许可证与校验）。

---

## 1. 一句话

**这是一个"解压即用、目标机可完全无外网"的 Windows 部署包。** 里面除了应用本体，
还带了两样东西：目标机可能缺的浏览器（Chrome）和知识库预览要用的 LibreOffice —— 都是官方安装包，
由包内脚本在目标机就地安装/解包，全程不需要联网。

---

## 2. 包内组成

以 v1.7 为例，解压后 `deploy\JZToolsHub\` 共 **777.5 MB / 2887 个文件**：

| 路径 | 体积 | 数量 | 作用 |
| --- | --- | --- | --- |
| `_internal\` | 224.4 MB | 2558 | **Python 运行时 + 全部 pip 依赖**（Flask / waitress / cryptography / openpyxl / numpy / opencv / zfec …）。由 PyInstaller 生成，**不要手动改** |
| `JZToolsHub.exe` | 19.0 MB | 1 | 应用本体（无控制台窗口，托盘常驻） |
| `runtime\` | **517.2 MB** | 6 | **★ 离线运行组件**（见 §3） |
| `plugins\` | 16.1 MB | 244 | 11 个插件的后端源码 + 前端资源。前端可直接改、重启生效 |
| `static\` | 0.1 MB | 48 | 框架首页与外壳页前端 + SVG 图标回退 |
| `config\tools.json` | — | 1 | 工具注册清单**模板**（首次启动复制到数据根目录） |
| `wheels\` `tools\` | 0.1 MB | 9 | zfec 预编译 wheel 与重建脚本（离线补装/重建用） |
| `docs\` `*.md` | 0.4 MB | 15 | README / HANDOFF / 插件设计规范 / 移动端APP / 设计文档 |
| `install.ps1` `一键安装.bat` `一键卸载.bat` `start.bat` | — | 4 | 安装 / 卸载 / 启动入口 |
| `version.json` | — | 1 | `{app, schema, commit, built_at, python, offline}`，模板同步的触发依据 |

**不包含**（按设计排除）：

* 用户数据 —— 账号、组织架构、台账、文档、公告、大模型 Key 等全部在**数据根目录**
  （默认 `%USERPROFILE%\.jztoolshub`），与程序目录分离，升级不丢。
* 本机运行时配置与密钥 —— 插件树内精确名 `config.json`（含 API Key）在打包时被清理；
  配置**模板**另命名为 `*.template.json`，不会被误删（原因见 `docs/P0问题修复方案.md` FIX-1）。
* 插件运行数据与缓存 —— `data/`、`.task_cache/`、`__pycache__/`、`out/`、`*.pyc` 全部清掉，首启自动重建。

## 3. 离线运行组件（`runtime\`）

| 文件 | 体积 | 安装方式 | 需要管理员 |
| --- | --- | --- | --- |
| `chrome\googlechromestandaloneenterprise64.msi` | 159.6 MB | `msiexec /i … /qn` 静默全机安装 | **是** |
| `libreoffice\LibreOffice_26.8.0_Win_x86-64.msi` | 357.5 MB | `msiexec /a … TARGETDIR=…` 管理安装 → 便携目录 | 否 |
| `setup-offline-runtime.ps1` | — | 安装逻辑（`install.ps1` 会自动调用，也可单独跑） | — |
| `安装离线组件.bat` | — | 双击入口（装 Chrome 需右键提权） | — |
| `manifest.json` | — | 组件清单：版本 / 体积 / **sha256** / 来源 URL / 许可证 | — |
| `README.md` | — | 组件来源、校验与再分发说明 | — |

组件的完整 sha256：

| 组件 | 版本 | sha256 |
| --- | --- | --- |
| Chrome 企业版 MSI | stable | `7baa1a89de55e8ba68d3d0c912fe677ddd807e91fb0ee4532c6b6cc527197ddb` |
| LibreOffice MSI | 26.8.0 | `4aa6c6e1895f4055104effcb556bd3362d20c6ad707c149543304f395ef9db95` |

### 为什么 LibreOffice 用"管理安装"而不是普通安装

`msiexec /a` 是**管理安装**：把 MSI 的内容原样解包到指定目录，**不写注册表、不需要管理员、
不污染系统**，解出的目录可直接运行。这对内网受限机器很关键——很多现场账号没有本机管理员权限。
（2026-09-14 实测：退出码 0，耗时 95 秒，解出 1.52 GB，`program\soffice.exe` 直接位于目标目录根下。）

安装后应用**自动探测**，无需改任何配置：

```
插件配置 office.soffice_path  >  环境变量 XHR_SOFFICE  >  <程序目录>\runtime\libreoffice\program\soffice.exe
```

验证：启动后访问 `GET /api/knowledge-base/status`，`soffice` 字段非 `null` 即生效。

## 4. 部署流程（目标机）

```
① 把 zip 拷进内网（U 盘 / 内网文件服务）→ 解压到任意可写目录
② 双击「一键安装.bat」            ← 装到 %LOCALAPPDATA%\JZToolsHub（可用 -InstallDir 改）
                                  末尾会自动装 Chrome、解包 LibreOffice
③ 若第 ② 步提示 Chrome 需提权：右键「runtime\安装离线组件.bat」→ 以管理员身份运行
④ 双击 start.bat 启动 → 浏览器访问 http://localhost:5000
   默认管理员 admin / admin123，登录后请立即改密
```

其余动作：

| 目的 | 操作 |
| --- | --- |
| 升级到新版本 | 解压新 zip → 双击「一键安装.bat」（识别既有安装后就地更新；数据与用户配置保留） |
| 只补装/修复离线组件 | 双击 `runtime\安装离线组件.bat`，或 `... -SkipChrome` / `-SkipLibreOffice` 单独处理 |
| 只看不装（先确认） | `powershell -File runtime\setup-offline-runtime.ps1 -DryRun` |
| 卸载 | 双击「一键卸载.bat」→ 输入 Y（连用户数据一起删；保数据用 `install.ps1 -Uninstall -KeepData`） |

## 5. 体积、磁盘与时间成本

| 项 | 数值 |
| --- | --- |
| zip 包 | 约 0.6 GB（MSI 本身已是压缩格式，外层再压收益很小） |
| 解压后（部署目录） | 777.5 MB |
| 安装到 `%LOCALAPPDATA%` 后 | ≈ 1.8 GB（程序 777 MB + LibreOffice 解包 1.52 GB，另加 MSI 仍在 `runtime\` 里） |
| 峰值额外需要 | 压缩包 + 部署目录需同时存在 → 建议预留 **3 GB** 可用空间 |
| 安装耗时 | 复制文件 1~3 分钟；LibreOffice 解包 1.5~2 分钟；Chrome 静默安装 1~2 分钟 |

> 不想装离线组件：删掉 `runtime\` 即可，应用照常运行（只是目标机需自备浏览器，
> 知识库 `.doc`/`.xls` 高保真通道降级）。打包时用 `-SkipOfflineRuntime` 可直接出瘦包。

## 6. 适用场景

| 场景 | 该包是否适用 | 说明 |
| --- | --- | --- |
| **内网 / 专网目标机，无外网** | ✅ **主场景** | 依赖全部随包；Chrome 与 LibreOffice 均可离线安装/解包 |
| 完全隔离（air-gap）交付 | ✅ | 除本包外不需要任何外部资源；`.NET`/MSI 均为 Windows 自带组件 |
| 目标机无管理员权限 | ✅ **部分** | LibreOffice 免管理员解包可用；Chrome 装不了 → 用机器上已有的 Edge（基线要求同内核 ≥79）或让管理员补装一次 |
| 有外网的普通机器 | ⚠️ 可用但偏重 | 直接用瘦包（`-SkipOfflineRuntime`）更省事，Chrome/LibreOffice 在线装 |
| 只改了前端（`static\`、`plugins\<id>\frontend\`） | ⚠️ 不必重打 | 直接改目标机上的对应文件，重启 service 即生效 |
| 只改了插件后端（`backend\*.py`） | ⚠️ 不必重打 | 目标机替换该文件后**重启服务**即生效（后端不热重载） |
| Linux / macOS 目标机 | ❌ | 当前只产出 Windows x64 产物 |

## 7. 校验

```powershell
# ① 包内组件清单与实际文件是否一致（体积 + sha256），不联网
python tools\fetch-offline-bundle.py --verify-only

# ② 应用侧自检（启动后）
#    GET /api/knowledge-base/status → office_render.available / soffice
#    GET /api/tools                 → 工具列表（插件是否全部加载）
```

> sha256 只能证明"这份字节与打包时一致"，**不能证明上游来源真实性**：Chrome MSI 官方不发布独立哈希；
> LibreOffice 官方对每个 MSI 提供 `.asc` GPG 签名，如需强验证请另行用 gpg 校验。

## 8. 已知限制与未验证项

1. **Chrome 静默安装未在提权环境实测** —— 逻辑已就绪（`msiexec /i … /qn`，已装则跳过），
   但开发会话无管理员权限，只能走到"打印提权指引"这一步。
2. **"真断网机器"上的完整链路未实测** —— 开发机上已实测：`msiexec /a` 免管理员解包 ✅、
   便携 `soffice.exe` 转换回环 ✅、应用自动探测 ✅、`render_sheet(.xls)` 真实渲染 ✅。
   缺的是"从零解压 → 一键安装 → 启动"整条链路的现场走查。
3. **Chrome 组件用的是固定 URL `stable`** —— Google 会持续更新该地址内容，冻结的 `sha256`
   迟早会失配。发版前需重跑 `fetch-offline-bundle.py --pin` 刷新清单，或改用带版本号的地址。
4. **每次发版包体约 0.6 GB** —— 大部分是 MSI（已压缩，无法再减）。若带宽紧张，
   可把 `runtime\` 拆成单独介质，按需分发。
5. **LibreOffice 解包占 1.52 GB 磁盘**（MSI 的 4.26 倍）—— 这是 LibreOffice 的固有体积。

## 10. 常见问题

**Q：目标机能装但 Chrome 没装上，影响使用吗？**
A：不影响。Chrome 只关乎浏览体验；用机器上已有的 Edge（同内核）即可。LibreOffice 才是功能性的
（且它免管理员就能装）。

**Q：`runtime\` 能删吗？**
A：能。删除后应用完全正常，只是目标机要自备浏览器，知识库的 `.doc` / `.xls` 高保真通道降级
（`.xls` 走 xlrd 兜底、`.doc` 明确提示不可转换）。

**Q：为什么不在打包机上就把 LibreOffice 解包好，让目标机"零步骤"？**
A：会显著增大产物：解包后 1.52 GB，若与 MSI 同时打进包则包体接近翻倍。当前方案把"解包"放在目标机
（1.5~2 分钟、免管理员），包体更小。
**确实需要"零步骤"时**，在打包机执行一次
`powershell -File tools\offline-runtime\setup-offline-runtime.ps1 -RuntimeDir <仓库>\runtime -SkipChrome`，
让 `runtime\libreoffice\program\soffice.exe` 就位后再打包即可（此时可不带 MSI）。

**Q：升级时会不会覆盖我改过的前端？**
A：会。`一键安装.bat` 会复制整包文件。改过前端请在升级后再改一次，或把改动回写到仓库源码
（推荐：下次打包即带上）。
