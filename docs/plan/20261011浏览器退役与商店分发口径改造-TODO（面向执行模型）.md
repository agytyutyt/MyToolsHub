## 0. 需求与目标语义（2026-10-11 需求方）

**需求原文**：①彻底停用业务端浏览器访问，仅管理后台可通过浏览器访问；②插件商店「插件」类别中，A、C 类插件仅显示前端插件、点击安装也安装前端，B 类（local）插件安装完整逻辑到本地并在插件标签中注明「本地」；③A、C 类插件上架即部署（后端）包到服务器上。

**目标语义（三项落地后的终态）**：

| 面 | 终态 |
| --- | --- |
| 业务面（首页 / 工具壳页 / 插件页面 / 商店页 / 全部业务 API） | 浏览器直连一律拒绝（403 提示页）；仅桌面客户端（壳）可达。**中继直出保留**：未装前端包的 A 类插件在壳内经中继照常可用（零安装体验不变） |
| 管理面（`/login`、`/admin*`、`/api/admin/*`、`/plugin/admin/*`、登录页静态依赖） | 浏览器照常可用（原 R2 登录门、权限点门不变） |
| 商店展示 | A：单卡「前端」徽标，安装/下载=前端包；C：单卡（客户端工件，含本地逻辑）「本地」徽标 + 常显「数据出机」，安装=客户端工件；B：单卡「本地」徽标，安装=完整本地包；后端包在任何用户界面不出现 |
| 上架 | A/C 发布（审核通过）动作内自动部署后端包到服务器；C 以"客户端工件 + 服务器工件"配对一次上架、一次发布 |
| 浏览器端退役附带项 | B 类服务器侧条目停用（只留本地条目成终态，§6.1 已拍板方向的落实）；托盘「用浏览器打开」入口改造 |

## 2. 方案设计

### 2.1 服务端壳身份门（需求①）

**机制=壳标识头 + 接入密钥（共享秘密）+ 路径白名单默认拒绝。**

1. **接入密钥**（框架数据，单一写方=`jz_host/shell_gate.py`）：

```jsonc
// <数据根>\config\shell-token.json   （首启自动生成；原子写；权限尽力 0o600）
{"schema": 1, "token": "<secrets.token_hex(32)>", "created_at": "…",
 "enforce": true, "allowed_ips": []}     // enforce=false 或环境变量 JZTOOLS_SHELL_ENFORCE=0 = 紧急放行（排障）
```

2. **请求标识**：`X-JZ-Shell: <token>`；服务端 `hmac.compare_digest` 比对（常量时间）。缺头/不符 → 见 3。
3. **统一门**：`jz_host/shell_gate.py:install(app)` 注册 `before_request`，装配在 `access_log.install(app)`（`app.py:96`）之后、插件注册（`app.py:514`）之前——**运行序在 admin 登录门与 worker 反代桥之前**（Flask before_request 按注册序执行）。
4. **路径分类**（判定顺序：完全放行 → 管理面放行 → 要求壳标识；未列出的新路由自动落"要求壳标识"=默认拒绝）：

| 分类 | 路径 |
| --- | --- |
| 完全放行（浏览器可达） | `/login`、`/api/login`、`/api/logout`、`/api/session`、`/favicon.ico`、`/api/site`（管理面 logo 标题用，见卡 G1-5）、`/static/*` |
| 管理面放行（浏览器可达） | `/admin`、`/admin/<module>`、`/api/admin/*`、`/plugin/admin/*` |
| 拒绝的静态例外 | `/static/index.html`、`/static/tool.html`（业务页面本体，防直取） |
| 要求壳标识（业务面） | 其余全部：`/`、`/tool/*`、`/plugin/<业务插件>/*`、`/api/tools*`、`/api/org/tree`、`/api/llm/*`、`/api/<业务插件 id>/*`、`/plugin/store/api/*` |

5. **拒绝响应**：`/api/*` → `403 {"error":"shell_required","hint":"业务功能仅限桌面客户端访问；管理后台请访问 /admin"}`；页面 → 403 + 新增 `static/shell-required.html`（随主包）。
6. **会话不变量**：门只看头、不看会话 —— 存量会话不因本改造失效（**不**把"登录时经壳"作为准入条件；如需审计可后续加 `session["via_shell"]` 记录，本期不做）。
7. **信任模型（诚实边界）**：目标是关闭"浏览器常规访问业务面"这一路径；密钥落在客户端配置文件里（本机用户可读），**不防有技术能力的内部人员主动提取密钥**——与本仓既有内网信任域口径（catalog 不防篡改、共享盘同信任域）一致。可选加固：`allowed_ips` 白名单（内网固定 IP 场景）。
8. **发版顺序（硬约束）**：**客户端先发、服务端后发**。新客户端对旧服务端多带一个头=无副作用；旧客户端对新服务端（门控生效）会 403 → 表现为明确提示而非白屏（卡 G2-4）。排障用紧急开关回退。

### 2.2 客户端收口（需求①）

1. **标识注入三处收口**（全部从客户端配置 `remote_token` 取值，统一一个 helper）：中继 `client_headers()`（`capability_app.py:1074`）、`jz_relay.request`（`jz_relay.py:88-95`）、`plugin_source.ServerSource._headers`（`plugin_source.py:44-49`）。健康探针与身份刷新复用 `client_headers` 自动覆盖。
2. **密钥配置链**：客户端配置 `%LOCALAPPDATA%\JZClient\config.json` 增 `remote_token`；解析顺序=客户端配置 → 构建配置 `server.default_token` → 未配置。兜底页（`client/fallback.html:29-47`）地址表单增"接入密钥"输入，`POST /local-api/config/address` 扩展收 `{address, token}`（回传只给 `token_set` 布尔，不回明文）。
3. **403 区分**：能力层识别 `shell_required` → 专用提示（"接入密钥未配置或已变更，请向管理员索取并在设置中填写"），**不进"会话失效"分支**（不清会话镜像），落 `client.log`。
4. **托盘改造**：客户端「用浏览器打开」→ **「打开管理后台」**（系统浏览器打开 `<服务器地址>/admin`；未配地址则提示）；主包托盘 `jz_host/tray.py:47`「打开浏览器」→ **「打开管理后台」**（本机 `http://127.0.0.1:<port>/admin`）。
5. **本地端口防护**（防"浏览器打开客户端本地端口=拿到壳身份代理"）：壳启动经 `GET /shell-boot?_shell=<run token>&next=<path>` → 校验后种持久 Cookie `jz_shell=<run token>` 并 302 到干净 URL；能力层 `before_request` 对**全部路由**（含 `/local-api/*`；例外仅 `/static/*`、`/favicon.ico`、`/shell-boot`）要求该 Cookie，否则本地提示页。run token=进程内随机（可被环境变量 `JZCLIENT_SHELL_TOKEN` 覆盖，仅台架/验收用）。
6. **登录页文案**：现"请登录后进入管理后台"对浏览器准确、对壳内用户误导 → 中性化为"请登录后继续"（小项）。

### 2.3 商店展示口径（需求②）

**展示矩阵（「插件」页签，每插件一卡）**：

| 类 | 卡来源（catalog 条目） | 徽标 | 安装落点 | 下载工件 |
| --- | --- | --- | --- | --- |
| A（server 条目） | server 条目 | **前端** | 前端包 → `<数据目录>\server-frontends\<id>\` | 前端包（`artifact=frontend`） |
| C | **客户端工件条目**（`local-<id>`，hybrid，含本地逻辑） | **本地** + 数据出机 | 客户端工件 → `local-plugins\local-<id>\` | 客户端工件包 |
| B（local 条目） | local 条目 | **本地** | 完整本地包 → `local-plugins\local-<id>\` | 包文件 |
| 依赖（dep-slot） | dep-slot 条目（不变） | 依赖 | 组件包 → `runtime\pylibs` | 包文件 |

**去重与配对契约**：

1. **配对字段（新增，向后兼容）**：server 条目版本记录增 `client_entry`（值=配对客户端工件 id，如 `"local-file-filter"`），由配对上架（§2.4）写入；**历史条目读侧自动识别**：存在 `local-<id>` 条目且其最新版 `server_data=true` → 视为配对。
2. **投影去重**：`GET /plugin/store/api/catalog` 构建 flat 列表时，**有配对客户端工件的 server 条目不进商店列表**（`plugins/store/backend/routes.py:159-182` 侧过滤；`flat_item` 保持纯投影）。管理面 `/plugin/admin/store/list` 不过滤（配对分组展示，见卡 G3-11）。
3. **投影增字段**：flat 条目增 `kind`、`server_data`（未安装条目也能显示「数据出机」，补齐 §1.2 缺口）。
4. **后端包永不出现在任何用户面**：商店页/客户端下载路径只取客户端工件（现状保持）；浏览器路径随需求①自然消失。
5. **网格一致性**（壳内主界面）：
   - 安装/卸载 C 客户端工件时**联动本机 `hidden_tools`**：装→隐藏服务器条目卡片（本机不再下发），卸→恢复（复用 `client_config.set_hidden_tool`，零新增机制）。
   - B 类服务器侧条目**停用**（`config/tools.json` enabled=false：B-light 5 + B-heavy 3，共 8 项，其中 4 项已停用）；保留插件目录，可随时回滚启用。
6. **命名**：B/C 条目显示名去「（本地）」后缀（本地性由徽标承担；admin 元数据编辑，记 history）。

### 2.4 上架即部署（需求③）

1. **A 类（现状固化）**：发布（approve）→ 自动部署后端包 → 失败回退 pending + 告警 + history（现状已实现，本文只加不变量校验与测试）。
2. **C 类（新增配对）**：一次上架 = 客户端工件包 + 服务器后端包（+ 前端包，沿用 server 条目"前后端成对"），校验：id 映射（`local-<X>` ↔ `X`）、版本一致、各自机器校验（本地包六连 / 服务器包结构+SHA256SUMS / 前端包成对）；一次审核发布 → 出卡条目（local 条目）published + 服务器条目 published 并**自动部署**（复用 `deploy_backend_package`）；`client_entry` 字段互链。

## 7. 风险与边界

1. **升级窗口**：服务端门控生效后，未升级的旧客户端业务面全 403 → 必须"客户端先发、服务端后发"，且客户端 403 文案明确（G2-4）+ 紧急开关（G1-1）。同机自测先用 `install.ps1` 装服务端并手动填密钥。
2. **信任模型**：密钥可被本机用户读取（配置文件）；目标是关闭浏览器常规路径，不是对抗有技术能力的内部人员（与内网信任域既有口径一致）。可选 `allowed_ips` 加固。
3. **中继直出保留**：A 类"未装前端包=壳内中继直出"不变（零安装体验）；与三类适配 §6.1 曾预判的"A 类安装前端包变必选"不同——本改造不需要牺牲该兜底（门控只认壳标识，不认"是否装了前端包"）。
4. **会话存量**：门只看请求头，不做会话级标记 → 升级后无需强制重登（避免大面积会话失效）。
5. **管理面零回归**：R2 登录门、权限点门、超管门全部保持；唯一改动是 admin logo 标题改走 `/api/site`（G1-5）。
6. **商店去重只影响展示**：catalog 两条目、`packages\` 两份包、服务器部署态均不动；管理面可见/可运维。
7. **B 类服务器条目停用**：只改 `tools.json` enabled（即时隐藏清单；路由随下次重启卸载），插件目录与数据保留，回滚=重新启用。
