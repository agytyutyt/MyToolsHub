## 1. 拍板结论（**已预决；执行模型照此执行，不要再问**）

| # | 议题 | 结论（照此做） | 理由摘要 |
| --- | --- | --- | --- |
| ① | 拆分是否允许改变行为 | **绝不允许**。仅允许「移动代码 + 提取函数 + 依赖注入」三类动作；端点路径/HTTP 方法/装饰器**及其先后**/响应体字段/状态码/`set_operation()` 审计文案/日志文本一律**逐字不变** | 本轮无缺陷驱动，收益只在可维护性；任何行为变化都是净损失 |
| ② | 等价性怎么证明 | 每个卡**必须**给出「改前基线 → 改后对比」证据：D2/D3 用**输出比对**（同一输入集合，逐字节/逐字段相同）；D3 另有 `test_filter_llm` 等既有台架；D1/D4/D5/D6 用 **test_client/既有台架全绿**（§3 清单）。**拿不出等价证据 = 该卡停卡报告**，不硬拆 | 重构卡的红线是「等价」，不是「跑通」 |
| ③ | admin 子模块命名与数量 | 固定三个：`admin_org.py`（组织/账号）、`admin_plugins_api.py`（插件管理面）、`admin_store_api.py`（商店管理面）；**不再多拆**（避免碎片化） | 与既有 `store_admin.py`/`batch_io.py`/`data_migrate.py` 的粒度一致 |
| ④ | 子模块依赖注入范式 | **照抄 `batch_io.py` 既有范式**：子模块内模块级 `_deps = {}` + `def register(app, deps)`（内部 `global _deps; _deps = deps`）+ 端点内 `_deps["名字"](…)`；routes.py 侧写 `_load_admin_org()` 等加载器（**相对导入优先、按文件路径加载回退**，逐字照 `_load_batch_io()`），并在 `register()` 内调用 `_register_admin_org(app)` 那样的小函数注入 deps | 该范式已在仓内验证过（避免循环 import 的既有解法），无新机制 |
| ⑤ | 装饰器（`@login_required`）怎么进子模块 | **以 deps 键注入**：deps 里加 `"login_required": login_required`，子模块内写 `@_deps["login_required"]` —— 注意 deps 须在**模块级 `register()` 首行**完成赋值，且装饰器求值发生在**函数定义时**，因此子模块内的路由函数**必须定义在 `register(app, deps)` 内部**（照 `batch_io.register` 的既有写法），不得提到模块顶层 | 顶层定义会让装饰器在 deps 注入前求值 → `NameError`/错装饰器 |
| ⑥ | 共享辅助符号放哪 | **一律留在 routes.py**，以 deps 注入子模块；**不复制、不外移**。已确认的共享面（现码定位）：`load_registry`/`load_admin_config`/`save_admin_config`/`iter_users`/`find_user`/`find_dept`/`find_unit`/`encrypt_field`/`decrypt_field`/`_role_super_admin`/`_registered_tool_ids`/`_grant_all_tool_ids`/`set_operation`/`get_session_user`/`login_required`/`can_manage_llm`/`_session_settings` | 复制会产生第二真源（同源副本台账的教训） |
| ⑦ | `run_filter` 的四段边界 | 按代码内既有注释分界，固定四函数名：`_decide_columns(...)`（逐列决策：exclude→confirmed→remap→exact→suggested→miss 留给 LLM）、`_apply_llm_decisions(...)`（调 LLM 并回填 decide）、`_build_result(...)`（组装 kept/removed/removed_detail/replace_count/mappings_used）、`run_filter(...)` 保留为**编排壳**（含后处理与硬过滤路径）。子函数一律 `_` 前缀、不改公开名 | 报告 §5.1 原文即「按注释分界拆 4 函数」；`run_filter` 是跨插件契约名（C 类工件与 `/apply` 都调它），**不得改名** |
| ⑧ | `build_timeline` 的拆法 | 按阶段拆**纯函数**，固定名：`_segment_by_displacement(wmin,wmax,info,states,noise_m)`、`_segments_to_events(raw,info,width_s,stay_min_s)`、`_absorb_short_into_stays(events,noise_m)`、`_merge_stays_across_voids(events,noise_m)`、`_build_trips(events,stay_idx,info,states,width_s,high_m)`、`_build_report_items(events,stay_idx,info,states,wmin,wmax,width_s)`（内含 `_runs_in_span`/`_run_item` 作嵌套或同文件私有函数）；`build_timeline(...)` 保留为编排壳且**签名不变**；`window_address` 不动 | 阶段边界在代码里已有注释分节，切分即「加函数名」，零逻辑改动 |
| ⑨ | 前端拆分的尺度 | 每文件只拆**最大的 1–2 个函数**；主函数保留原名与调用方；抽取子函数统一 `_` 前缀或 `render*`/`build*` 命名；**不改 DOM 结构、不改 CSS 类名、不改事件绑定语义、不改 id/data-* 属性**；拆完必须 `node --check` + `node --check` 无法覆盖的模板内联脚本改用 `node -e` 语法校验或浏览器实跑 | 前端无自动化台架覆盖，只能靠「不动结构」降低风险 |
| ⑩ | 本地包（C 类）与服务器侧的同步口径 | **固化为：服务器插件的 `frontend/` 或 `backend/` 任一变化，同批必须重生成 + 重出本地包 + 重上架 local 条目**（本地包内含 `frontend/`，见 §4 矩阵证据）。本口径写进本文并回写台账/清单，D7 即按此纠偏 `local-qr-video-decode` | 前端改动漏同步会让**本地插件用户**长期拿旧前端（本轮已实际踩到一次） |
| ⑪ | 版本与出包口径 | 每个被改动的插件**逐卡递增一次**版本（三段式，如 `file-filter 1.6.2→1.6.3`），**一律不用 `-Force` 同号重出**（除非该版本从未出包/从未上架，且执行模型在完成表里写明证据）；先 `git status --porcelain` 为空再出包（否则 `version.json`/包内戳带 `-dirty`） | 与 §B-18 切版制、§A2 已知坑 3 一致 |
| ⑫ | 商店操作路径 | **一律**走隔离 `base_dir`（`~/.jztoolshub/tmp/<批次>-deploy-target`）部署验证后再 `review(approve)`；**禁止**在仓库根/页面点 approve；每次动商店前先备份 `catalog.json`/`index-server.json` 为 `*.bak-<批次>` | §A2 已知坑 2；误操作会覆写 git 工作区 |
| ⑬ | 主包切版时机 | **只在全部卡做完后切一次**（D1 的 admin + 任何宿主改动合并）。若过程中 `app.py`/`jz_host/*`/`jz_*.py` 有改动，PyInstaller **必须重跑**（`--clean`），不得复用 `dist/` | 打包手册 §1 时间戳比对含 `jz_host`/`jz_*.py`；漏判会复用旧 exe |
| ⑭ | 拆不动怎么办 | 任一卡若证明「拆分会改变行为」或「拆分后代码更大更绕」，**停该卡 + 写失败报告（§5 模板）+ 继续下一卡**，并回写清单为「已评估不拆（附证据）」——这属**合法结论**，不是未完成 | 避免为凑指标引入回归 |
| ⑮ | 明确不做（登记，勿当遗漏） | ① vendor 补丁**自动重放**（无上游源，无法生成权威 diff；核验脚本 `tools/e2e/kb-vendor-patch-check.py` 已覆盖"检出"半件）；② 改 `vendor/` 内第三方源码；③ P1-8 / P1-10 / P2-18 / zip 落点与 built_at（§4 S7）；④ 为拆分而改动协议/数据格式 | 见 §4 S7 与 §B-31 ⑥ |

## 8. 编排侧已知的坑（避坑，不解释）

1. **`adapt-*` 是写入型补丁器**，会 `rmtree` 本地工件目录后重拷 → 改服务器侧后必须重跑，且跑完要复核 `git status`。
2. **改副本必动台账基准**：`aggregate.py`/`filter_local.py` 等被 `tools/e2e/ledger-drift-check.py` 与 `docs/design/同源副本台账.md` §2 登记 → 动完先改**台账 §2**、再改**脚本基准表**、最后跑 `--sync-check`（顺序不可反）。
3. **C-14 行级豁免随行号漂移**：改前端已豁免文件后 `--gate` 会红，**这是设计如此**，按新行号更新 `EXEMPTIONS`。
4. **商店 approve 会部署到仓库根**（页面路径禁用）；一律隔离 `base_dir`（§1-⑫）。
5. **出包前必须 commit**；临时文件/解压冒烟目录放仓库外。
6. **E 架构（supervisor）插件**：若某插件已 worker 化，`deploy_backend_package` 会走 supervisor 控制接口；本机 `config/supervisor-units.json` 不存在即按进程内形态处理（现状如此）。
7. **台架输出含非 ASCII 标签**：新增台架一律带 `sys.stdout/stderr.reconfigure(encoding="utf-8", errors="replace")` 守护（否则 GBK 控制台抛 `UnicodeEncodeError`，把"通过"误读成"提前结束"）。
