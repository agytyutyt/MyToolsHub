## 1. 需求与概述

用户上传**原始轨迹数据（Excel）**，插件先调用「过滤器」插件完成**字段过滤**，再对过滤后的数据做
**轨迹分析**，最终产出**速写报告**（页内预览 + Excel 工作簿下载）。

| # | 需求（用户原话） | 实现要点 |
| --- | --- | --- |
| 1 | 用户提供原始轨迹数据（excel） | 支持 `xlsx` / `xls` / `csv`，≤20MB（SEC-3）；上传后先做**表头自检**再执行分析 |
| 2 | 插件调用"过滤器"插件功能，对其中的特定字段进行过滤操作 | 走 HTTP 程序化接口 `POST /api/file-filter/apply`（B-7 禁止 import 其他插件后端模块）；**不重复实现过滤逻辑** |
| 3 | 默认采用硬过滤操作，提供开关决定是否调用大模型辅助判断 | 前端开关 `模式=硬过滤 / 大模型辅助`，默认硬过滤；大模型模式复用过滤器插件的 LLM 配置，未配置时开关置灰并给出引导 |
| 4 | 特定字段由"轨迹速写"插件的配置文件决定 | 数据根目录 `plugins/trajectory-sketch/config.json` 的 `filter.keep_columns`（**本插件自己的配置**，与过滤器插件的名单解耦）；仅管理员在插件页维护 |
| 5 | 完成过滤操作后，对数据进行轨迹分析，并形成速写报告 | 内置**可插拔轨迹分析引擎**（§5），产出停留点 / 出行段 / 报告正文；页内预览 + 下载 `.xlsx` 工作簿 |
| 6 | 轨迹分析参考 `D:\SQLRewrite`，后续分析算法会更新，相关代码要充分解耦 | 引擎为**独立包**：零 Flask 依赖、零框架依赖、纯标准库；算法版本走**注册表**；参数全部外置到配置；报告模板与检测算法分离（§5） |
| 7 | 符合 material design；采用 emoji 图标时须同时绘制 SVG 以兼容 Win7 | 页内图标一律使用**插件自带 SVG**（`frontend/icons/`，不依赖系统 emoji 字体）；首页卡片 emoji 选 `✍️`（框架 `static/js/jz-icon.js` 已内置 `270d.svg` 回退，**无需改框架**） |

### 1.1 已确认的关键决策（2026-09-11）

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| 分析引擎依赖 | **纯标准库重写**（不用 pandas / numpy） | JZToolsHub 打包清单 `JZToolsHub.spec` 无 pandas/numpy；引入将 +约 50MB 且需重验 Win7 打包链路。算法复杂度为 O(n)，纯标准库足够 |
| 报告交付形态 | **页内预览 + Excel 工作簿下载** | 与 SQLRewrite 的「输出_轨迹报告.xlsx」口径一致，报告正文可直接复制粘贴 |
| 保留字段名单维护者 | **仅管理员在插件页配置** | 与需求 4「由插件配置文件决定」一致；普通用户只做「上传 + 切换过滤开关」 |

## 2. 业务流程

```
① 上传       用户拖拽/点选 xlsx / xls / csv（≤20MB）
                 │
                 ▼
② 表头自检    后端读原始表头 → 展开保留字段别名 → 调 /api/file-filter/apply(mode=hard)
   （同步）       → 返回：真实表头 / 过滤后字段（保留 & 删除）/ 必需列自检表 / 行数
                 │  ← 前端展示「字段自检」卡片；缺必需列时红字提示，不进入下一步
                 ▼
③ 生成速写    用户确认（可切换「大模型辅助判断」开关）→ POST /analyze → 立即返回 task_id
   （异步）      后台线程池：调 /apply(选定 mode) → 得到过滤后二维表
                 → 标准化适配（列名 → 规范列）→ 轨迹分析引擎（簇→停留点→出行段→报告）
                 → 生成 Excel 工作簿落 .task_cache/
                 ▼
④ 轮询取结果  轮询 /result/<task_id> → 速写摘要 / 报告正文 / 停留点 / 出行段 / 数据质量
                 ▼
⑤ 下载        /download/<task_id> → 轨迹速写报告.xlsx（5 个 sheet）
```

**为何拆成「自检 + 分析」两段**：字段过滤是本插件的**前置依赖**，缺列（如没保留经度列）会导致分析
必然失败。自检前置后，用户能在**发起分析之前**就看到缺哪一列、该去配置里补什么，而不是等一个异步
任务跑完再报错。自检同步执行（读表头 + 过滤，毫秒~秒级），符合 8.5「预计超过 3 秒才异步」的门槛。

路由、过滤桥接、Excel 读写、前端全部不需要修改（§5 给出可替换性论证）。

### 4.3 保留字段的"别名展开"规则（本插件核心机制之一）

过滤器插件的硬过滤是**表头字面精确匹配**（规整后），而真实轨迹表的表头千差万别
（规范列名 / 中文 / 缩写）。因此本插件在调用 `/apply` 之前做一次展开：

```
配置 filter.keep_columns = ["时间", "号码", "经度", "纬度", "地址"]
  │  ① 每个条目先按 column_map 反查：命中某规范列的别名表？
  │       是 → 取该规范列的**别名全集**        例：「时间」→ [BEGINTIME, BEGIN_TIME, 开始时间, 时间, 起始时间, 上报时间]
  │       否 → 保留原文（允许管理员直接写自定义列名）
  ▼
传给 /apply 的 columns = 去重后的别名全集
  ▼
过滤器插件在真实表头上做精确匹配 → 命中任一别名即保留该列
```

好处：① 同一份配置可适配多种来源的轨迹表；② 大模型模式下的语义匹配基准更丰富；
③ 配置里写中文更贴近管理员直觉。**自检卡片会把"命中了哪个真实表头"回显给用户**，规则透明可验。

### 4.4 与「过滤器」插件的边界（B-7）

- **只走 HTTP**：`POST /api/file-filter/apply`，请求 `{rows, mode, columns, post_rules}`，
  响应 `{rows, kept, removed, replace_count, mode}`。**禁止** `import jztools_file_filter.core`
  （规范反模式 #9）。
- **调用实现**（`filter_bridge.py`）：
  1. **首选：进程内派发**——用当前 Flask 应用的 `app.test_client()` 发内部请求，并把当前请求的
     `Cookie` 原样带入，使 admin 插件的登录鉴权与工具访问控制在内部调用上同样生效；
     不经过网络、不依赖监听地址，开发 / 测试 / 打包运行三种场景行为一致（**可被 test client 回归测试**）。
  2. **兜底：HTTP 回环**——进程内派发失败时，用 `requests` 请求 `request.host_url + api/file-filter/apply`，
     同样带上 Cookie，超时 120 秒（SEC-6）。
  3. 过滤器插件被下线（`enabled: false`）或接口 404/403 → 返回**可读错误**：
     「过滤器插件不可用，请联系管理员在首页启用"过滤器"并授予本工具对应权限」，而不是晦涩堆栈。
- **确定性**：`post_rules` 默认传本插件自己的配置（`filter.post_rules`，默认空），**不继承**
  过滤器插件的管理员配置，避免"过滤器改配置导致速写结果漂移"；需要复用时由管理员显式打开
  `use_filter_plugin_rules`（此时 `post_rules` 不传，由 `/apply` 回退取过滤器插件配置）。

## 5. ★ 分析引擎解耦设计（需求 6 的落点）

### 5.1 分层与依赖方向

```
routes.py ──┐
            ├─► filter_bridge.py ──HTTP──► 过滤器插件 /apply
excel_io.py │
            └─► engine.analyze_rows(rows, params) ──► 纯数据结果（dict，JSON 可序列化）
                     │
                     └─► algorithms/v2/{cluster,staypoint,trip,report}.py
```

**单向依赖，引擎在末端，且不知道外面存在什么**：

| 约束 | 内容 | 目的 |
| --- | --- | --- |
| D-1 | `engine/` 下**禁止** import `flask` / `requests` / `jztools_data` / 插件其他模块（`config_store`、`excel_io`、`routes`） | 引擎可整体复制到任何 Python 项目；算法更新不会牵动业务层 |
| D-2 | `engine/` 只依赖**标准库**（`math` / `statistics` / `datetime` / `dataclasses` / `collections`） | 无依赖包袱；与"纯标准库重写"决策一致 |
| D-3 | 输入 = **过滤后的二维表 + 参数字典**；输出 = **纯 dict**（§5.2 契约） | 边界稳定；换算法不改外部；换外部不影响算法 |
| D-4 | 算法版本经 `registry` 注册，`routes.py` 只按 `analysis.algo` 取值 | 新增算法 = 新增一个模块 + `register()` 调用，**不动路由与前端** |
| D-5 | 所有阈值 / 开关从 `params` 读取，引擎代码内**不出现魔法数字** | 参数调整无需改代码（沿用 SQLRewrite 的配置化传统） |
| D-6 | 报告**文案模板**独立在 `report.py`（`entry_text` / `summary_text`），与几何判定分离 | 改文案不改算法；改算法不改文案 |
| D-7 | `engine/selftest.py` 提供无 Flask 的自测入口 | 算法可独立验证、可回归对拍 |
| D-8 | 模块划分与 SQLRewrite `src/` **1:1 对齐**（cluster / staypoint / trip / report / geo / time_utils / config） | 上游算法更新时可按模块搬运，移植成本最小 |

### 5.2 引擎对外契约（`engine/__init__.py`）

```python
def analyze_rows(rows, params=None, algo=None, meta=None) -> dict
    """rows   : 二维表（首行表头，单元格可为 str / int / float / datetime）
       params : config.json 的 analysis + report 节（缺省用内置默认值）
       algo   : 算法版本；缺省取 params["analysis"]["algo"]，再缺省 "v2"
       meta   : 透传信息（如过滤摘要 kept/removed），原样回填到结果的 filter 字段
       返回   : {
         "ok": True,
         "algo": "v2",
         "schema":  {"matched": {"BEGINTIME": "BEGINTIME", ...}, "missing_required": [...],
                     "missing_optional": [...]},          # 列映射结果（自检阶段复用同一函数）
         "quality": {...},                                # 数据质量（§6.1）
         "stays":   [...],                                # 停留点
         "trips":   [...],                                # 出行段
         "users":   ["15700000007"],                      # 出现的号码（含无有效数据的）
         "report":  {"text_by_user": {...}, "entries": [...], "summary": {...}},
         "warnings":["..."]
       }
       # 失败时抛 engine.contract.AnalysisError（信息为**面向用户的中文描述**，不含堆栈）
```

`routes.py` 拿到 dict 后只做两件事：把 `report/stays/trips/quality` 塞进任务结果给前端、
调 `excel_io.write_report_workbook()` 落盘。**路由里没有任何几何/时间/判定逻辑**。

### 5.3 新增/替换算法的最小步骤（只为证明解耦成立）

```
① 新建 engine/algorithms/v3/（cluster3.py / … / report3.py）
② 在其 __init__.py 里 registry.register("v3", run)
③ 在 algorithms/__init__.py 里 import 该包
④ 管理员把配置 analysis.algo 改成 "v3"
```
—— 不动 `routes.py`、`config_store.py`、`filter_bridge.py`、`excel_io.py`、前端任何一行。

## 6. v2 算法设计（引擎首个内置实现）

> 完整推导与实测见 `D:\SQLRewrite\轨迹报告优化方案.md`；此处只记录**移植到本插件时的实现形态**。

### 6.1 阶段划分

| 阶段 | 模块 | 职责 |
| --- | --- | --- |
| A 适配与质控 | `adapter.py` | 列映射（别名，忽略大小写与首尾空白）→ 类型规整 → 经纬度数值化（脏值转缺失并计数）→ 过滤无效行（经度 ≤ `min_longitude` / 纬度 ≤ `min_latitude` / 时间缺失 / 坐标缺失）→ 输出轨迹点序列 + 丢弃原因分布 |
| B 清洗去重 | `adapter.py` | 按（号码, 时间, 经度）稳定排序 → 三键去重 → 5 分钟网格 + 3 位小数位置指纹去重（组内保留最早）。`Δt=0` 的重复点**合并**而非丢弃 |
| C 地点簇 | `v2/cluster.py` | 并查集：地址相同 → 合并；坐标距离 < `co_site_meters` → 合并；双向切换次数 ≥ `handover_min_count` 且距离 ≤ `handover_max_meters` → 合并。簇属性：加权质心（按上报次数）、众数地址、小区数、抖动半径 |
| D 停留点 | `v2/staypoint.py` | 自适应噪声估计（低速样本位移的 `noise_percentile` 分位）→ `D_thr`（聚类时用 `fixed_radius_meters`，否则 `clamp(noise × factor, min, max)`）→ `T_thr = max(min_stay_minutes, factor × 中位采样间隔)` → 双指针「点到质心距离 ≤ D_thr」扫描（乒乓切换被吸收） |
| E 出行段 | `v2/trip.py` | 相邻停留点间：净位移（质心间）+ 累计位移 + 直线度 + 回访次数 → 不达标则**合并停留点**（trip chaining）→ 达标按 `high_conf_factor × 噪声` 分级为「有效出行 / 位置变动」；首末未纳入停留点的时段也构成出行段 |
| F 报告 | `v2/report.py` | 条目拼装（停留 / 有效出行 / 位置变动 / 无数据）→ 时间轴闭合 → 单位自适应（<1km 用米）→ 速写摘要 → 抬头落款 |

### 6.2 时间与数值健壮性（相对 SQLRewrite 的增强）

| 项 | SQLRewrite | 本插件 |
| --- | --- | --- |
| 时间解析 | 字符串为主（pandas） | 三类输入：字符串（多格式尝试）/ Excel 序列号（float，1899-12-30 基准）/ `datetime` 对象；解析失败率 > 5% 时进 `warnings` 并附样例 |
| 大整数号码 | `string` dtype 防 float 化 | 单元格转字符串时：float 且为整数 → `str(int(v))`（防 `15700000007.0`） |
| 脏坐标 | `to_numeric(coerce)` | `float()` 包裹 + 正则容错（如 `111.5526(aaa)` 先截取首个数字串），失败计为缺失并统计 |
| 无号码列 | 必需 | **降级**：视为单号码「（未提供号码）」，正常出报告（`warnings` 提示） |
| 无 LAI/CI | 必需 | 降级：簇以「地址」为键；地址也缺 → 逐点即一"簇"（退化为纯几何模式） |
| 单号码/短数据 | 阈值标定样本不足 | `warnings` 提示「样本偏少，阈值可能不适配」；阈值全可配，管理员可改 |

## 10. 异常与边界

| 场景 | 行为 |
| --- | --- |
| 过滤器插件已下线 | `/upload` 返回 503 + 「过滤器插件不可用，请联系管理员启用"过滤器"」 |
| 过滤后缺必需列 | 自检阶段即拦截（`missing_required` 非空），分析接口 400 + 列出缺失规范列与**建议做法**（在配置中补充对应别名） |
| 保留字段名单为空 | `/upload` 400：「保留字段名单为空，请管理员在配置中设置」 |
| 大模型模式但 LLM 未配置 | 开关置灰 + 提示；后端 `mode=llm` 前置 400（`llm_configured=false`），不排入队列 |
| 表格无表头 / 空表 | 400「表格为空或缺少表头（首行）」 |
| 全部为脏数据 | 分析正常完成，报告为「无。」，数据质量说明丢弃原因（不报错） |
| 只有 1 行数据 | 正常完成：0 停留点 0 出行段，报告列出单点/无数据说明 |
| 时间解析失败率高 | `warnings` 提示 + 数据质量列出样例；不中断 |
| 无号码列 / 无 LAI·CI 列 | 降级处理（§6.2），`warnings` 如实说明 |
| CSV 编码 | utf-8-sig 读取，失败退 gbk（同过滤器插件口径）；写出统一 xlsx |
| 任务过期（>30 分钟） | 404「任务不存在或已过期」；`staged_id` 同样 TTL 30 分钟 |
