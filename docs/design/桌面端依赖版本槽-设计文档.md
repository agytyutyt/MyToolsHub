## 0. 结论速览

1. **物理约束**（方案 §6.6 存档，本文沿用）：Python 单进程一个顶层包只有一个生效版本 → 版本槽只对**子进程形态**（类 B worker、被降格的类 C）生效；类 C 进程内不能双版本，只能灰显或一键降格。
2. **布局定稿建议**：槽挂 `runtime/pylibs/.slots/<import名>__<版本>/`，每槽带 `slot.json`——与存档 `pylibs/<name>__<version>/` 的差异仅在**挂到点目录下**：共享槽注入器 `setup_dep_components` 会把 pylibs 根下**每个子目录**加进 DLL 搜索路径（`jz_plugin_host.py:62-74`）、状态摘要会把子目录当已装组件列出（`jz_plugin_host.py:95-96`）；点目录对两者天然不可见，**内核零改动**（红线 4），导入解析上点目录同样惰性（`.slots` 不是合法顶层包名）。`<import名>__<版本>` 命名约定照旧。
3. **解析口径**：插件声明 → 共享槽满足即用（零安装）→ 不满足查版本槽（取满足声明的最高版）→ 仍缺 = 三态「缺」。声明写法仍是 `>=x.y.z` / 精确 `x.y.z`，**不做深层依赖求解器**（与服务器现状对齐）。
4. **注入口径**：执行器 spawn 时按插件解析结果给 `plugin_host.py --slot <dir>`（可重复），槽目录插到 `sys.path` 首位（先于 pylibs 根=遮蔽共享槽）并加 DLL 目录——只影响本插件子进程。
5. **前置补课（已落地 2026-10-08）**：客户端已产出 `installed-deps.json`——`tools/client/build-client.py` 出包时用同源 `tools/gen-installed-deps.py` 按冻结目录采集，落 `_internal/kernel/config/installed-deps.json`（jz_deps 三态判定数据源；B-heavy 的 flask 在此记为已装）。**O1 版本槽本身仍未实施、待拍板**，多版本共存与共享槽口径见本文 §2 起。
6. **商店联动**：槽包（`kind: dep-slot`）作为一种分发物接入 O2 商店的 `install(pkg_source)` 单入口与目录 schema（`runtime: "dep-slot"`），不另修安装通道。

## 3. 总体设计

### 3.1 槽布局与命名

```
<程序目录>\runtime\pylibs\              ← 共享槽（现状不动）
├── manifest.json                       ← 组件清单（真源：装了什么组件、什么版本、modules 映射）
├── cv2\  numpy\  zfec\ …
└── .slots\                             ← 版本槽区（新增；点目录对内核注入器/状态摘要不可见）
    ├── cv2__4.9.0.80\
    │   ├── slot.json                   ← 槽元数据（§4.1）
    │   └── cv2\  cv2\...pyd  dist-info\…  ← wheel 解包产物（site-packages 内容）
    └── requests__2.31.0\
        ├── slot.json
        └── requests\ …
```

- 目录名 = `<import名>__<版本>`（import 名与 `requires.python_packages[].name` 同口径，如 `cv2`；版本=wheel 精确版本，仅数字与点，文件系统安全）。
- **同 import 名同版本只允许一个发行包来源**（slot.json.dist 不同即拒装）——内网分发可控，出现真实冲突再议 dist 消歧目录。
- 与方案 §6.6 存档（`pylibs/<name>__<version>/`）的差异仅为**多一层 `.slots/`**：换来 C1（内核零改动）与 C5（状态/校验口径不混入共享组件清单）。命名约定不变，「按约定查找」的解析逻辑与存档一致。

### 3.2 解析与判定扩展（新建 `client/dep_slots.py`）

```
resolve(manifest, program_dir, pylibs_dir, allow_slot: bool) -> {"slots": {name: dir}, "patched_rows": [...], "unresolved": [...]}
```

1. 先跑 `jz_deps.evaluate(...)` 原样求值（内核行为零变化）；
2. `allow_slot=False`（hybrid 进程内形态）：不解析槽，verdict 照旧——mismatch → blocked + 灰显提示（附「一键降格为子进程」入口，§3.5）；
3. `allow_slot=True`（worker 形态：`kind:"local"` 带 backend，或 hybrid 已降格）：对 detail 里 `kind=python_package` 且 state∈{missing, mismatch} 的行，扫 `.slots/*/slot.json`：
   - 共享槽已满足（state=ok/unknown）的行**不动**（去重收益优先）；
   - 候选槽须满足声明（复用 `jz_deps.version_satisfies`），取**最高版本**；命中 → 行改写 `state="ok"`、`actual=<槽版本>`、`note="版本槽 <名>__<版本>"`；
   - 无候选 → 保持 missing/mismatch → blocked，提示文案追加「可安装版本槽 <名>__<声明版本>」与安装入口；
4. 解析是**纯函数**：能力层（状态展示/门控）与执行器（spawn 前实算）各调一次，结果必然一致（槽区只增删不改写）。

### 3.3 注入路径（`plugin_executor.py` / `plugin_host.py` 增量）

- `PluginExecutor._spawn`：spawn 前对 manifest 跑 `dep_slots.resolve(allow_slot=True)`，命中的槽目录以 `--slot <dir>`（可重复）追加 argv；
- `client/plugin_host.py` main()：`setup_dep_components` 之后，把各槽目录 `sys.path.insert(0, …)`（先于 pylibs 根 → 同名包槽版遮蔽共享版）并对槽目录 `os.add_dll_directory`（槽内 .pyd 的依赖 DLL）；
- 影响面仅该 worker 子进程；能力层进程不碰槽（C1）。常驻 worker 换槽即被收割替换，天然走 L3（§3.4）。

### 3.4 槽包：安装、占用与 GC

- **包形态**：`JZToolsHub-依赖槽-<import名>-v<版本>.zip`（命名族与依赖组件包 `JZToolsHub-依赖-…` 同风格）：`slot.json` + `payload/`（wheel 解包产物，**含其传递依赖**——声明级口径下由出包工具保证完整性，不做运行期求解）；`requires_components` 沿用组件包字段（如 cv2 槽声明需 numpy 槽/共享组件）。
- **wheel tag 预检**：出包与安装两道都查——只收 `cp314-cp314-win_amd64` / `py3-none-any`（embeddable Python 基线），其余 tag 拒收并给出 §3.6 三选一文案。
- **安装动作**：解包到 `.slots/.pending-<名>__<版本>/` → 校验 slot.json 与 tag → 原子改名就位 → 写审计。就位前若同名槽存在且被**常驻 worker**持有（DLL 句柄），先收割该插件常驻 worker 再改名（升级=换槽，L3）；装完调用 `dep_slots` 相关插件状态刷新（L1 即时）。
- **GC**：卸载/停用插件后跑一次引用清点（扫描已装本地插件 manifest 的 requires + 其他槽的 `requires_components`），无引用的槽整目录删除；GC 也提供 `/local-api/deps/gc` 手动入口。动作记 `plugin-audit.log`。

### 3.5 类 C 一键降格（同源码零迁移）

- 客户端配置 `local_exec: {<pid>: "auto" | "worker"}`（`config.json` 新键，缺省 auto；与既有 `local_state` 启停开关并存）。
- `auto` 且 verdict 因 python 依赖 mismatch → blocked：管理页该插件卡片显示灰显提示 + **「以子进程方式运行」**按钮（写 `local_exec[pid]="worker"` + rescan）；
- 降格后 `_refresh_local_states` 对该插件走 `allow_slot=True` 解析；`local_plugin_api` 派发改走执行器（`client/capability_app.py:281-289` 的 worker 分支）——hybrid 的 `register(app)` 源码与 mini-WSGI 派发完全同构（`client/plugin_host.py:29-44`），**插件代码零改动**；`jz_relay` 门面经 `sys.modules` 注入对子进程形态同样生效（plugin_host 已插 `_ROOT` 进 `sys.path`）。
- 切回（`auto`）恢复进程内挂载语义（hybrid 升级=秒级重启口径）。
- 代价提示（安装时/降格时明示）：worker 每请求冷启动 spawn 100–300 ms + import 开销；`resident: true` 可声明常驻摊平。

### 3.6 cp314 硬边界与出路

槽包 wheel tag 预检失败（目标版本无 cp314 wheel）时，按 §6.6 存档给三选一，客户端 UI 文案照此口径：

1. **插件升版适配**共享槽已有版本（首选）；
2. **exe 例外通道**：插件自带运行时（entry.backend 指向 .exe，T20 已有通道）——跨运行时共存的终极形态；
3. **客户端基线降档**：涉及 GD8 同源内核双基线，**默认不做**（旋钮留构建配置，缺省关闭）。

## 4. 数据与接口契约

### 4.1 `slot.json`（每槽一份，扫描即得，无中央注册表）

```jsonc
{
  "schema": 1,
  "name": "cv2",                    // import 名（与目录名前缀一致）
  "dist": "opencv-python",          // 发行包名（信息性；同名同版不同 dist 拒装）
  "version": "4.9.0.80",
  "modules": ["cv2"],               // 本槽提供的 import 名（解析键）
  "python": "cp314",                // wheel 基线（安装时与运行时解释器核对）
  "requires_components": [],        // 组件级依赖（如 cv2 槽 → numpy），沿组件包口径
  "installed_at": "2026-10-04T10:00:00+08:00",
  "source": "store|share|local"     // 安装来源（审计用；格式同 O2 商店）
}
```

### 4.2 `/local-api` 增量（能力层）

| 接口 | 方法 | 语义 |
| --- | --- | --- |
| `/local-api/deps` | GET | 共享槽组件清单（pylibs manifest）+ 槽清单（扫 `.slots`）+ 各插件解析结果摘要（via: shared/slot/missing） |
| `/local-api/deps/install` | POST | 安装版本槽包（zip 上传；复用 O2 `install(pkg_source)` 收口后为其中一种 `pkg_source`） |
| `/local-api/deps/gc` | POST | 引用清点 + 清理无引用槽；返回删除清单 |
| `/local-api/plugins/exec-mode` | POST | `{id, mode: "auto"\|"worker"}`：类 C 一键降格/切回（写 `local_exec` + rescan） |

### 4.3 管理页增量（`client/local_admin.html`）

「依赖组件」页签：共享组件与版本槽两节列表（名称/版本/被哪些插件引用/来源）+ 安装槽包 + GC 按钮；插件卡片：依赖徽标显示 `via`（共享/槽版本/缺失），hybrid 冲突卡片出「以子进程方式运行」按钮。

| A3 | 声明既无共享也无槽 | blocked + 提示含槽安装入口；装槽后 L1 即时转 ok |
| A4 | hybrid 钉旧版（共享不满足） | 进程内 blocked 灰显 → 一键降格 → 同源码 worker 跑通；切回 auto 恢复进程内语义 |
| A5 | 升级槽（同 import 名新版就位） | 常驻 worker 被收割替换，新请求即新版；审计留痕 |
| A6 | GC | 卸载最后一个引用插件后槽被清；仍被引用/被 `requires_components` 依赖的槽保留 |
| A7 | 主包零改动证明 | `git diff jz_deps.py jz_plugin_host.py app.py` 为空；`verify-package --smoke` 绿 |
| A8 | 出包校验 | `verify-client.py` 含锁清单断言与 `.slots` 口径全过 |
| A9 | tag 预检 | 非 cp314/py3-none-any wheel 构建与安装两道均拒收，文案给三选一出路 |

## 7. 风险与开放问题

| # | 项 | 口径 |
| --- | --- | --- |
| R1 | 槽内传递依赖与共享槽同名冲突（槽内 numpy 旧版 + 共享 numpy 新版，worker 内以槽为准） | 声明级口径的既定取舍：槽包由出包工具保证自洽；文档明示「槽内嵌套依赖优先于共享槽」 |
