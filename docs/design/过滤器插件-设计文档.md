## 1. 需求与概述

对用户上传的表格文件进行**字段脱敏（列过滤）**与**合规性检查**：

| # | 需求 | 实现要点 |
| --- | --- | --- |
| 1 | 页面左右两块：左侧输入区（虚线方框上传控件），右侧输出结果区（提供过滤后文件下载） | 前端 grid 布局（`.layout`，上传卡片横跨两栏），上传后即时预览字段 |
| 2 | 上传文件限制 `xlsx` / `xls` / `csv` | 后端 SEC-3 白名单 + 大小上限 20MB |
| 3 | 两种过滤模式：硬过滤 / 大模型过滤 | 单选；大模型模式复用插件级 LLM 配置 |
| 4 | 硬过滤：按固定字段名保留列，其余删除（精确匹配） | `core.filter_columns()` |
| 5 | 大模型过滤：提取全部字段（标题）交大模型判断与保留字段名是否关联（如「时间」↔「开始时间」），匹配保留、其余去除 | `llm_client.match_columns()`，批量一次调用；名单内同名字段直接保留（见 §2.2） |
| 6 | 后处理：管理员预设文本规则，检测并去除单元格/表头中的相应文本；支持正则（如内容「开始时间」+ 规则「开始」→「时间」） | `core.post_process()`，规则含 `is_regex` 开关 |
| 7 | 符合插件规范；主要功能（过滤、后处理）提供接口供其他插件调用 | `POST /api/file-filter/apply`（同步 JSON-in/JSON-out，不落用户文件） |
| 8 | **办案员上传后先看到"识别到的列名"与硬过滤的预计结果**（胶囊展示，要删的列画删除线） | `POST /api/file-filter/preview`（同步）+ `build_preview()`；逐列 `keep/matched/post_name/replace_count` |
| 9 | **点胶囊自定义这一列是否过滤**（用户决定优先于模式判定） | `/filter` 的 `columns`（点开的列）+ `exclude`（点掉的列）；`run_filter(exclude=...)` |
| 10 | **展示后处理规则，由用户决定是否启用（默认开启）** | 规则明文展示（含"文本/正则"与"已停用"徽标）+ `post_process` 开关（缺省 1） |

## 2. 业务流程

```
用户上传文件（xlsx/xls/csv，≤20MB）
   │
   ▼
[⓪ 删除背景图片]（在过滤流程开始前，自动执行；见 §2.1）
   - 识别文档里嵌入的「工作表背景图片」（Excel「页面布局 → 背景」）
   - 命中则摘掉 <picture> 引用 + Relationship + 不再被引用的图片本体
   - 未命中 → 原字节返回（不改写文件）
   ▼
[① 上传预览 /preview]（同步，见 §2.2）—— 上传件落盘暂存 → staged_id
   - 解析为二维表（csv 标准库 / xlsx openpyxl / xls xlrd）
   - 识别全部列名 → 逐列给出硬过滤预判（keep/matched）与后处理预判（post_name/replace_count）
   - 页面渲染为胶囊：命中的列正常显示，其余**画删除线**（= 将被删除）
   - 用户点胶囊逐列切换保留/删除；决定是否启用后处理（默认开启）
   ▼
[② 提交过滤 /filter]（异步任务；可带 staged_id 复用上传件，不必重复上传）
[模式一 硬过滤] 用户点开的列（columns）− 用户点掉的列（exclude）→ 精确匹配保留
[模式二 大模型过滤] 名单内同名直接保留；其余交 LLM 判定语义关联（「时间」↔「开始时间」）
   │  （LLM 未配置/调用失败 → 任务 error，可回退用硬过滤结果提示用户）
   │  两种模式下 exclude 都是最终否决：用户点掉的列一定删除
   ▼
[③ 后处理 post_process]（默认开启；用户在页面上关掉则整段跳过）
   - 文本替换规则：{pattern, replacement, is_regex, enabled}
   - 作用于：表头 + 数据单元格（字符串值）
   ▼
生成输出文件（保持原格式 xlsx/xls→xlsx；csv→csv 带回车换行与 BOM 兼容；列序 = 文档原列序）
   │  落盘 <数据根>/plugins/file-filter/.task_cache/{task_id}_output.<ext>（平铺，TTL 30 分钟；backend/routes.py:568）
   ▼
右侧结果区：保留字段列表 / 删除字段列表 / 替换处数 / 后处理是否关闭 / 文档预处理（背景图片结论）/ 下载按钮
```

### 2.2 上传预览与按列开关（v1.3）

**为什么预览要同步**：只读表 + 逐列预演，毫秒~秒级（与轨迹速写 `/upload` 同口径），进任务队列反而
让前端多实现一种轮询。预览阶段就把上传件**落盘暂存**并返回 `staged_id`，`/filter` 带 `staged_id`
即可复用——用户在预览里反复调整字段时不必重复上传文件（暂存 TTL 30 分钟，过期后前端自动改传文件重试一次）。

**预判口径**（`build_preview()`，逐列）：

| 字段 | 含义 |
| --- | --- |
| `name` / `index` | 列名（规整后；空表头为空串）/ 原列序号 |
| `keep` / `matched` | **硬过滤预判**：是否会被保留、匹配到名单里的哪个字段 |
| `post_name` / `replace_count` | 按当前规则预演的表头新名 / 该列替换处数（仅字符串单元格，与 `post_process` 同口径） |
| `locked` | 空表头列：无法按字段名保留，前端不给切换 |
| `dup` | 同名重复列：同名必然同判，前端点击时一起切换并标 `×N` |

**用户决定优先于模式判定**（关键契约）：

- `columns`（点开的列）既是硬过滤的保留名单，也是大模型模式的语义匹配基准；
- `exclude`（点掉的列）在**两种模式下都是最终否决**——大模型认为该保留、但用户点了删除，就删除；
- 大模型模式下，名单内**同名字段直接保留**：那是用户点名要的列，不把判断权交给模型
  （模型偶发返回空值会让用户"明明开着却被删"，且与硬过滤口径不一致）；
- `columns` **显式传空数组**（用户把字段全关）→ 400「未选择任何保留字段」，**不静默回退**管理员名单
  （静默回退会让"我明明全删了"变成"怎么全保留了"）；完全不传才回退配置（老调用方口径不变）。

**后处理开关**：规则在页面上明文展示（查找内容 → 替换为 + 「文本/正则」徽标 + 「已停用」徽标），
用户用「启用后处理规则」开关整体关闭（**默认开启**）；关闭时 `post_process=0` → 后端传空规则列表，
本次不改写任何文本，列过滤照常生效，结果区标注「已关闭」。逐列预演让前端能对"当前保留的列"
实时求和出「预计替换 N 处」，不必为每次点击再问后端。

### 2.1 删除背景图片（`backend/bg_image.py`）

**为什么放在流程最前**：背景图片（Excel「页面布局 → 背景」插入的图）不属于数据，却会跟着文档一起流转，
常被用来夹带水印/机构标识/来源标记。先摘掉再过滤，"落盘暂存 → 过滤 → 出产物"全程只面对干净的文档；
放在最前也让结论能随任务结果回传（用户能看到"这次上传删了什么"）。

**识别与删除的落点**：`.xlsx` 本质是 zip（OOXML 包），工作表背景图片由三个部件构成，删除即三件套一起摘掉：

| 部件 | 内容 | 处理 |
| --- | --- | --- |
| `xl/worksheets/sheetN.xml` | `<picture r:id="rIdK"/>` | 摘掉该元素 |
| `xl/worksheets/_rels/sheetN.xml.rels` | `rIdK → ../media/imageM.png` | 删掉该 Relationship；关系清空则整个 `.rels` 部件一起删 |
| `xl/media/imageM.png` | 图片二进制本体 | **不再被任何关系引用**时才删；仍被别处引用（同一张图既当背景又当浮动 logo）则保留本体 |

除这三处外，包内其余部件**逐字节原样搬运**（不重排、不重压、不改时间戳）：样式、批注、宏、数据透视表、
非背景图片一概不受影响。实现要点：

- 界面改动只发生在**已确认命中**的部件上，其余部件连解码都不做（`_rewrite_zip` 直接搬运原始字节）；
- 引用目标解析支持 `../media/x.png` 与 `/xl/media/x.png` 两种写法，`TargetMode="External"` 视为"本体不在包内"；
- 图片本体是否仍被引用，靠**全包 `.rels` 扫描**判定（工作表 / 绘图 / 图表 / VML 的引用都走关系）；
- 被删部件在 `[Content_Types].xml` 里的 `Override` 登记一并清掉（`Default` 按扩展名无需处理）。

**报告结构**（随 `/filter` 响应与 `/result` 回传，前端渲染为「文档预处理」一行）：

```json
{"ext": "xlsx", "scanned": true, "found": 1, "removed": 1, "bytes": 7417,
 "images": [{"part": "xl/media/image1.png", "bytes": 7417, "rel": "rId1",
             "sheets": ["Sheet1"], "kept": false}],
 "other_images": 0, "kept_parts": 0,
 "note": "已删除背景图片 1 张（7.2 KB），来自工作表 Sheet1"}
```

**边界与失败姿态**（重要：本环节是增值步骤，不该让畸形文件卡死业务链路）：

| 情形 | 行为 |
| --- | --- |
| 未发现背景图片 | **原字节返回**，连 zip 都不重写（对存量文件零风险） |
| 发现但本体被别处引用 | 只解除背景引用，保留图片本体，报告里说明 |
| 背景指向文件外（外部链接） | 解除引用，报告说明"本体不在文件内" |
| 非有效 zip / 已加密压缩包 / 解压后 > 256MB / 解析异常 | **不改写文件、照原样继续流程**，原因写进 `note`（`scan` 置 false） |
| `.csv`（无图片容器）、`.xls`（BIFF 二进制流，本模块不解析） | 不检测，`note` 里说明；两者在本插件里的输出都是**重新生成**的文件，天然不含背景图片 |

**双份副本约定**：规范 B-7 禁止插件间 import，`trajectory-sketch` 也需要同一能力，故该模块在两个插件内
**各存一份逐字节相同的副本**（纯标准库，零插件依赖）。改动必须两处同步，`test_bg_image.py` 会断言两份一致。

## 4. 数据与配置（9.1 数据归属）

- 运行数据：数据根目录 `plugins/file-filter/.task_cache/`（任务产物 + 上传暂存件，TTL 30 分钟清理；
  内存表 `TASKS`（过滤任务）与 `STAGES`（上传暂存）同锁同 TTL、同归属校验）。
- 管理员配置：数据根目录 `plugins/file-filter/config.json`：
  ```json
  {
    "keep_columns": ["时间", "地点", "人员"],
    "post_rules": [{"pattern": "开始", "replacement": "", "is_regex": false, "enabled": true}]
  }
  ```
- `config.json` 只含保留字段名单与后处理规则，**不含任何密钥**（统一大模型落地后本插件不再保存 / 回传 API 地址与 Key，也不再读取历史 `llm` 段——该段由启动迁移收编并幂等清除，见 `backend/routes.py:422-441`）；
  模板同步由 `jztools_data.sync_plugin_templates()` 自动发现（应用侧无需登记 `_TEMPLATE_SYNC`），安装器侧仍须在 `install.ps1` 的 `Sync-ConfigTemplates`（`$cfgPairs`）登记。
- 过滤任务产物属临时文件，非「用户产生的数据」记录，不含归属四字段（与 trajectory-convert 同口径，
  但沿用其 R6 纵深防御：任务记录 `created_by`，轮询/下载校验任务归属——非创建者且非超管 404）。
- 自学习字段映射（P0）：数据根目录 `plugins/file-filter/mappings.json`——表头→名单字段的两级信任
  映射（confirmed 用户确认 > suggested 大模型建议）、rejected 否决拦截表、运行统计 stats；
  `target=""` 为负映射（确认删除）；名单变更后指向已删除目标的条目失配（orphan）不参与匹配；
  原子写（tmp + `os.replace`）+ 进程内锁。详见 `docs/design/过滤器自学习字段映射-设计文档.md`。

## 5. 后端接口设计（B-2 前缀 `/api/file-filter`）

| 接口 | 方法 | 说明 | 权限 |
| --- | --- | --- | --- |
| `/api/file-filter/status` | GET | 依赖自检（openpyxl/xlrd/requests + LLM 是否已配置） | 登录 |
| `/api/file-filter/config` | GET | 读取配置（`keep_columns` / `post_rules`）+ `llm_configured` / `llm_source` / `llm_source_label` / `llm_reason` + `can_manage`；**不回传 API 地址与 Key** | 登录 |
| `/api/file-filter/config` | POST | 保存配置——**仅管理员/超管**（只接受 `keep_columns`、`post_rules`；接入信息不再受理） | 管理员 |
| `/api/file-filter/config/test` | POST | LLM 连通性测试（经 `jz_llm.test_connection(plugin_id=…)`，不接受表单传入的地址 / Key） | 管理员 |
| `/api/file-filter/preview` | POST | multipart `file` → **同步**返回 `staged_id` / `columns`（逐列 `name/keep/matched/post_name/replace_count/locked/dup`）/ `summary` / `post_rules` / `rows` / `sanitize`；上传件同时落盘暂存供 `/filter` 复用 | 登录 |
| `/api/file-filter/filter` | POST | multipart：`file` **或** `staged_id` + `mode`(hard/llm) + `columns`(JSON 数组，可选缺省用配置) + `exclude`(JSON 数组，可选) + `post_process`(1/0，缺省 1)；**异步**返回 `task_id` | 登录 |
| `/api/file-filter/result/<task_id>` | GET | 轮询 `{status, kept, removed, removed_detail, mappings_used, replace_count, rows, llm_used, post_enabled, sanitize, download, filename}`；`kept` 每项带 `source`（exact/confirmed/suggested/llm），`mappings_used` 供结果页映射复核区（P1 前端）；任务归属校验 | 创建者/超管 |
| `/api/file-filter/download/<task_id>` | GET | 下载过滤后文件（SEC-1：ID 白名单正则防穿越） | 创建者/超管 |
| `/api/file-filter/apply` | POST | **程序化调用接口（供其他插件）**：JSON `{rows, mode, columns, exclude?, post_rules?, post_process?, use_suggested?}` 同步返回 `{rows, kept, removed, mappings_used, replace_count}`；`post_rules` 不传时用管理员配置；`use_suggested` 缺省 false（程序化调用没有把关环节，只吃已确认映射）。不落盘 | 登录（插件间经前端/后端 fetch，鉴权走框架 session） |
| `/api/file-filter/mappings` | GET | 字段映射列表（`status`=confirmed/suggested/orphan 过滤、`q` 模糊）+ 运行统计 + 当前名单 | 管理员 |
| `/api/file-filter/mappings/confirm` | POST | 确认/改指映射 `{items:[{key,target,sample?}], force?}`；同 key 已有不同 confirmed 且未带 force → 409 + conflicts 交前端弹窗处置 | 登录（操作员把关） |
| `/api/file-filter/mappings/reject` | POST | 否决映射对 `{key, target}`：进拦截表防回锅，同名同目标条目删除 | 登录（操作员把关） |
| `/api/file-filter/mappings/delete` | POST | 删除单条 `{key}`（不用 DELETE 路径：表头可能含 "/"） | 管理员 |
| `/api/file-filter/mappings/clear` | POST | 清空全部映射与拦截表（保留运行统计） | 管理员 |
| `/api/file-filter/mappings/export` | GET | 导出黄金评测集 `?format=csv\|jsonl&status=confirmed\|suggested\|all`（失配 orphan 条目一律剔除） | 管理员 |

> `/filter` 的响应与 `/result` 的 done 载荷都带 `sanitize`（删除背景图片结论，结构见 §2.1）；
> `/apply` 是 JSON-in/JSON-out、不接触文件，故不涉及背景图片。
> `/preview` 暂存件与任务表同 TTL（30 分钟）、同归属校验（非创建者且非超管一律 404）；
> `staged_id` 过期/越权时 `/filter` 返回 404 + `code=staged_expired`（前端据此自动改传文件重试一次）。

### 5.1 核心纯函数（core.py，本插件内部复用）

> B-7 允许其他插件通过框架动态加载机制按 `jztools_file_filter.core` 方式引用吗？
> ——**规范 B-7 禁止 import 其他插件后端模块**。因此「供其他插件调用」统一走 **HTTP 接口 `/apply`**：
> 其他插件后端用 requests 带 session 调用，或其前端直接 fetch。core.py 只服务本插件。

```python
read_table(path, filename) -> (headers, rows)     # csv/xlsx/xls 自适应；单元格转字符串（保留数字）
filter_columns(headers, rows, keep) -> (headers2, rows2, kept, removed)   # 硬过滤：精确匹配（clean 后）
post_process(headers, rows, rules) -> (headers2, rows2, count)            # 文本/正则替换（整表）
post_process_columns(headers, rows, rules) -> [(new_header, count)]       # 同上口径，但**逐列**回报（供上传预览）
write_table(path, ext, headers, rows)                     # xlsx(xlsx)/csv；xls 输出转 xlsx
match_columns(headers, keep_columns, session=None, timeout=LLM_TIMEOUT) -> {header: matched_keep or ""}
    # ↑ 定义在 llm_client.py（非 core.py）；session 由调用方在请求线程内 jz_llm.resolve(PLUGIN_ID) 取得后传入
```

> `post_process` 与 `post_process_columns` **必须同口径**（表头 + 字符串单元格；非字符串原样跳过）：
> 前者算全表总数，后者按列回报——上传预览据此展示「这一列会被改成什么、预计替换多少处」，
> 并让前端在用户点胶囊时直接求和，不必为每次点击再问后端。`test_filter_preview.py` 钉住两者一致。

`bg_image.py`（§2.1）同样是纯函数层，不依赖 Flask / openpyxl：

```python
strip_background_images(blob: bytes, ext: str) -> (clean_blob: bytes, report: dict)
```

### 5.2 LLM 字段匹配协议

- 一次调用传入全部表头与保留字段名单，要求输出 JSON：
  `{"mappings": {"表头": "对应保留字段或空", ...}}`（temperature=0.1）。
- HTTP 由框架模块 `jz_llm` 统一发起（支持 openai/anthropic/ollama/custom 四种格式），
  本插件 `llm_client` 只做提示词拼装与防幻觉校验，不再自带 HTTP 调用与 API Key。
- 匹配后校验：返回值必须 ∈ keep 名单（或空），否则视为未匹配（防模型幻觉映射到不存在字段）。
- **自学习复用（P0）**：大模型只接「缓存未命中的表头子集」；判定回写为建议级映射
  （`mapping_store.record_suggestions`，含 model + prompt_ver 归因），下次同表头直接查表
  ——已确认映射免问，建议级映射交互路径可用、程序化路径（/apply）缺省不用。管线与把关
  口径详见 `docs/design/过滤器自学习字段映射-设计文档.md` §3.1/§3.3。

## 8. 异常与边界

- 空表/无表头：400 `{"error": "表格为空或缺少表头（首行）"}`（`/preview` 与 `/filter` 同一套读表校验；
  预览失败立即回收暂存件，不占 TTL）。
- 硬过滤零匹配：正常执行（结果全删），结果区明确提示「没有匹配任何保留字段」。
- 用户把字段全关（`columns` 显式传空数组）：400「未选择任何保留字段」——不静默回退管理员名单；
  前端在点光所有胶囊时也会先拦一次（「请至少保留一个字段」）。
- 空表头列：无法按字段名保留（`locked`），预览里不可点击、一律删除。
- 同名重复列：按字段名匹配必然同判，预览里标 `×N` 且点击一起切换（避免"看着删了其实还在"）。
- `staged_id` 过期/越权/伪造：404 + `code=staged_expired`（归属校验与任务表同口径，不暴露资源存在性）；
  前端自动改传文件重试一次。
- LLM 未配置：任务直接 error，detail 提示去配置面板（前端引导；`/filter` 前置 400 不进队列）。
- LLM 返回非法映射：未在保留名单中的映射值按未匹配处理（不中断）；名单内同名字段由本插件直接保留。
- CSV 编码：utf-8-sig 读取（兼容 BOM/GBK 场景退回 gbk 重试）；写出 utf-8-sig（Excel 打开不乱码）。
- .xls 输出：统一转 .xlsx（xlrd 只读）；前端下载名提示格式变化。
- 大表防护：行数 ≤ 100000、列数 ≤ 256，超限 400（该 400 仅适用于 `/preview` 与 `/apply`；
  `/filter` 为异步任务，超限以任务 error 状态返回，HTTP 仍为 200+task_id）。
