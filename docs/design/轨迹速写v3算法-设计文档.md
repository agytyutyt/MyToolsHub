## 1. 需求与概述

### 1.1 背景与动机

v2（1.2.7）修复漏报事件后仍有两个结构性特点：判定链条长（簇合并 → 停留检测 → trip chaining），
中间结论难以逐段向非技术方解释；部分阈值随数据自适应，行为虽已可控但不可"手工复算"。
需求方提出以**固定 5 分钟窗口 + 速度分态 + 三票表决**为核心的透明算法：时间轴每个 5 分钟
都有可查证的状态与依据，失联显式成态，阈值全部固定可复算。v3 与 v2 **并列**而非替代，
共用同一数据底座与报告形态，由管理员按 `analysis.algo` 选择。

### 1.2 原始需求 → 评审决议对照（决策留痕）

| # | 原始要点（2026-09-29） | 定稿口径（本文） | 修改原因 |
| --- | --- | --- | --- |

### 1.3 目标与非目标

- **目标**：时间轴无缝（每个 5 分钟格有态）、逐窗可查证、阈值固定可复算、与 v2 共享底座与报告形态、
  对 LAI/CI 缺失不敏感（§5.2 实测）。
- **非目标**：不替代 v2 的地点语义（v3 的停留/出行条目由聚合层产出，粒度与叙事方式与 v2 有差异，见 §5.5）；
  不做多窗口空洞还原（>1 窗的断档如实显示失联）。

## 2. 状态与术语

### 2.1 五态（单票取值域）

| 票值 | 状态 | 判定条件（按序） | 报告文案 |
| --- | --- | --- | --- |
| 0 | 失联 | 窗内无点（或对票无法计算） | 无数据 |
| 1 | 静默 | 位移 ≤ 噪声门限（自适应，v2 同源） | 静默 |
| 2 | 缓行 | 速度 ≤ `creep_kmh`（10 km/h） | 缓行 |
| 3 | 快速 | `creep_kmh` < 速度 ≤ `fast_kmh`（150 km/h） | 移动 |
| 4 | 极速 | 速度 > `fast_kmh` | 高速移动 |

> 静默门限用**距离**而非速度判定（位移 ≤ 噪声即静默，与时间无关）；噪声复用 v2
> `estimate_noise` 的自适应值（本测试数据 194 米），可经 `noise_floor_m` 固定覆盖。

### 2.2 三票与赋权码

每个 5 分钟窗口接收三次赋值：**左对票**（与前一窗的速度）、**自身票**（窗内首末位移）、
**右对票**（与后一窗的速度）。码序固定 **[左对， 自身， 右对]**（判定与顺序无关，顺序仅用于
报告逐窗展示，如 `1·2·2`）。头尾窗口仅两票（缺的一侧记 0）。

## 3. 运行机制

### 3.1 流水线总览

```
过滤后的二维表
  → 底座（复用 v2）：adapter 清洗去重 → cluster 地点簇 + attach   ← 位置一律取簇质心
  → 窗口化 windows.py：5 分钟墙钟网格（逐用户）→ 窗口位置/首末位置
  → 三票 votes.py：自身票 + 左/右对票（含单空窗桥接）→ classify 四行判定 → 状态
  → 聚合 aggregate.py：位移锚定切分 → 停留段/移动段/无数据段 → 出行段提取
  → 报告：与 v2 同构的 entries / text_by_user / user_summaries + 质量区增补
```

### 3.2 底座（复用 v2）

直接调用 `adapter.build_dataset`（清洗、网格去重）与 `cluster.build_clusters/attach_clusters`
（地点簇）。**v3 不重新发明去抖**：驻留同一簇 → 位移精确为 0 → 静默判据天然成立；
乒乓切换在簇层已被吸收，不会涌入窗口票。噪声半径复用 `staypoint.estimate_noise`。

### 3.3 窗口化

- 窗口按墙钟对齐：`w = ts // 300`，逐用户独立；窗口表覆盖数据首末点之间的**全部**窗口（含空窗）；
- 窗口平均位置 = 窗内各点**簇质心**的经纬度平均；
- 首末位置 = 窗内**首点/末点**的簇质心（严格窗内取点，不向邻窗借点）；
- 单点窗口：首末同位 → 自身票按位移 0 处理（静默）。

### 3.4 三票计算

**自身票**（窗内首末）：距离 ≤ 噪声 → 1；否则实际间隔 < `guard_seconds`（60 秒）→ 2
（短跨度守卫：突发上报 30 秒 200 米不得凭空产生快速票）；否则按 ÷实际间隔 的速度分带
（≤10 → 2，≤150 → 3，>150 → 4）。空窗 → 0。

**对票 (i, i+1)**：

| 两窗数据情况 | 规则 |
| --- | --- |
| 均有数据 | 质心距离 ÷ 5 分钟（名义窗宽），套分带（≤噪声 → 1） |
| **恰一窗空** | **单空窗桥接**：取空窗两侧最近非空窗质心，距离 ÷ **实际间隔**（约 10 分钟），套分带。两侧任一侧再无非空邻窗（跨 ≥2 空窗）→ 0 |
| 均空 | 0 |

桥接的语义：停留中的软件闪断/隧道 → 空窗判静默（101 类）；行驶中过隧道 → 空窗继承真实
速度（[3,0,3] → 快速）；多窗信号丢失 → 000 真失联。**数据质量区同步列出全部断档区间**，
桥接不掩盖"曾经无数据"这一事实。

### 3.5 判定（四行计数规则，不枚举码表）

按序判定（5³=125 个码全覆盖）：

1. 三票全 0 → **失联**；
2. 值 4 的个数 ≥ 2 → **极速**；
3. 值 3 与值 4 的个数合计 ≥ 2 → **快速**（341、431、334、330 归此）；
4. 只含 0/1（非全 0）→ **静默**；
5. 其余 → **缓行**（确认缓行 222/221 与单高票矛盾码 311/411 同类，见 §7）。

实测码分布（两票同规则适用于头尾）：失联 1 码、静默 7 码、极速 13 码、快速 10 码、缓行 94 码。

### 3.6 头尾窗口

只有自身票 + 一侧对票（两票）。套用同一规则，"≥2"即两票同时：00 → 失联；44 → 极速；
33/34 → 快速；只含 0/1 → 静默；其余（31、30、32）→ 缓行。头尾窗口**必有状态**，
时间轴首尾不留洞。

### 3.7 聚合（停留/出行/无数据条目的来源）

窗口状态只负责栅格叙事；**条目由位移切分**，不按状态切分（否则短途出行会被缓行窗吞掉，
与 v2 已修复的缺陷同型）：

1. **位移锚定切分**：按时间扫非失联窗；开段时记锚点（首窗位置），后续窗口位置偏离锚点
   ≤ 噪声 → 延续段；> 噪声 → 闭段开新段。**桥接空窗（有态无位置）延续当前段并计入时长**；
   失联窗（000）闭段并累计无数据段。
2. **停留段**：段时长 ≥ `stay_minutes`（15 分钟）；代表位置 = 段内窗位置均值；条目时间取
   段内**实际首末点时刻**（非窗口边界，避免 0 分钟出行条目）。
3. **跨断档合并**：相邻两停留段之间仅隔无数据段/短段、且位置差 ≤ 噪声 → 合并为一次停留
   （段内断档在质量区注记次数与总时长）。
4. **出行段**：相邻两停留段之间（含其间短段与未桥接空窗）净位移 = 两停留位置差；
   净位移 ≤ 噪声的移动已在上一步并回；出行段含未桥接空窗时注记"含无数据 N 分钟"。
5. 数据首尾未成停留段的窗口 → 移动段（同出行段口径）。

### 3.8 报告（按状态聚合叙述；2026-09-29 二次修订）

`run(dataset, params)` 返回键与 v2 同构：`quality / stays / trips / report /
clusters / cluster_stats / warnings`（`stays/trips` 仍为结构化停留/出行数据，字段
与 v2 相同，`trips` 增补 `含无数据_分钟`）。

**报告正文不输出逐窗状态与断档统计附录**，改为按窗口状态聚合叙述：

- 时间轴按窗口状态扫描，**同状态连续窗口聚合为一条**；跨段边界的相邻同态移动窗
  亦合并；停留段前后缘的出发/到达过渡窗拆出为移动叙述（不被静默行吸收）；
- 运动状态以五态命名：**失联 / 静默 / 缓行 / 快速 / 极速**；
- 句式：
  - 静默——"静默 X，在【地址附近】"，跨断档合并的停留加"其间失联 Y 分钟"；
  - 移动——"缓行/快速/极速 X，从【A附近】到【B附近】，距离 D，平均速度 V 公里/小时"，
    V = 净位移 ÷ 实际时间（**与窗口票同口径，速度计算方式不变**）；
  - 失联——"失联 X"；单点过渡窗（位移不可估）如实标注；
- `quality` 增补：`v3_状态分布` / `v3_断档区间数` / `v3_桥接次数` 等；
  `report.summary` 保留 v2 键名并按状态语义映射（停留点数=静默段数、有效出行次数=
  快速段数、位置变动次数=缓行段数），另增 `极速段数` / `失联段数`。

## 4. 落地方式

### 4.1 目录与模块（纯标准库，延续 D-1/D-2）

```
plugins/trajectory-sketch/backend/engine/algorithms/v3/
├── __init__.py      # 编排 run(dataset, params)：底座 → 窗口 → 三票 → 判定 → 聚合 → 报告
├── windows.py       # 窗口化：分窗、平均位置、首末位置、空窗表
├── votes.py         # 自身票/对票（含桥接）/classify——纯函数，便于单测
└── aggregate.py     # 位移锚定切分、停留/出行/无数据条目
```

`engine/algorithms/__init__.py` 增 `import v3`（导入即注册 `registry.register("v3", run)`）；
**在批次 2 完成前不接入**（避免 `algo=v3` 暴露未实现分支）。

### 4.2 参数（全部外置，D-5；归 `params["v3"]`）

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `window_minutes` | 5 | 窗口宽（分钟） |
| `creep_kmh` | 10.0 | 缓行上限 |
| `fast_kmh` | 150.0 | 快速上限（超过为极速） |
| `stay_minutes` | 15.0 | 停留段最短时长 |
| `guard_seconds` | 60.0 | 自身票短跨度守卫 |
| `noise_floor_m` | 0（=自动） | >0 时固定静默门限；0 复用 v2 自适应噪声 |
| `merge_void_into_stay` | true | 相邻停留（位置 ≤ 噪声）跨无数据段合并 |

逐项功能与调整预期 → 插件 README「分析参数逐项说明 · ⑤ v3 专属」。
`params.py`：`DEFAULT_V3` + `_clamp` 夹取（窗宽 ≥1、速度 >0、守卫 ≥0）+ `validate` 提示；
`config.template.json` 的 `analysis` 增 `"v3": { ...同默认... }` 节。

### 4.3 注册与选择

- `registry.versions()` 自动含 "v3"，`/status` 的算法列表随之出现；
- 管理端 `analysis.algo: "v2" | "v3"`，**缺省仍 v2**；
- 前端：确认设置区算法下拉是否直接渲染 `/status` 返回的版本列表（TODO 批次 3 验证项，缺则补）。

### 4.4 性能

全流程 O(n) 单遍（n=去重后点数），8884 窗实测探针毫秒级；无新依赖。

## 7. 风险与边界（已知取舍）

1. **短途机动在窗口层最高只到"缓行"**（三票降噪的本性），出行结论完全依赖聚合层位移切分；
   聚合实现若有偏差会复现"吞短途"（v2 的历史缺陷），TODO 批次 4 的 9/23 对拍即为此设。
2. **缓行是兜底类**（含单高票矛盾码如 411），报告文案用"缓行"，避免语义过载。
3. **多窗空洞不还原**：≥2 空窗的断档如实显示失联（桥接只跨单空窗），条目以"含无数据 N 分钟"注记。
4. **极速可能是数据异常**（坐标跳变 >150km/h），报告中不作真实性背书，仅如实呈现。
5. **失联占比高的数据**（间歇上报）报告以停留段 + 断档注记为主，出行段少——这是口径的
   保守性，不是漏报；§5.4 已量化。
6. 引擎零第三方依赖约束不变（v3 纯标准库）；插件间独立铁律不涉及。
