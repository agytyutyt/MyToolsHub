## 1. 需求与边界

### 1.1 需求

- 管理员（管理员角色/超管）可上传 PDF / OFD / Word / Excel / Markdown 等文档，文件保存在插件数据目录中，可**分级分类**管理（多级分类树 + 文件归档）。
- 普通登录用户可浏览分类、点击阅读。
- 阅读界面 Material Design 风格，与站点一体；**仅阅读 + 复制**，禁止修改/编辑。

### 1.2 明确的边界（不做）

| 不做 | 理由 |
| --- | --- |
| 不使用浏览器内置 PDF 播放器 / Adobe 等浏览器控件 | 需求红线；全部由纯 JS 库在前端渲染 |
| 不提供在线编辑、批注、协作 | 需求明确只读 |
| 不提供下载按钮 | "仅阅读、复制等基础功能"；后端也不提供 attachment 下载端点 |
| 不做全文检索（第一版） | 低性能需求，仅分类过滤 + 文件名搜索 |
| 旧版 `.doc`/`.xls` | 上传时服务端自动转换为 `.docx`/`.xlsx`（纯 Python：olefile+python-docx / xlrd+openpyxl，见 `backend/doc_convert.py`），数据保真、样式/图片不迁移；依赖缺失或解析失败 422 明确提示 |

## 2. 可复用调研结论（GitHub）

全部选型为 **纯前端 JS 渲染库**（无浏览器插件/控件依赖），统一 vendor 到 `frontend/vendor/`（规范 F-7：内网部署库文件进自己插件目录，禁止运行时 CDN 依赖）。

| 格式 | 库 | 仓库 / Star | 许可证 | 使用方式 |
| --- | --- | --- | --- | --- |
| PDF | **pdf.js**（pdfjs-dist **legacy** 构建，兼容老 Chrome） | mozilla/pdf.js ★53.8k | Apache-2.0 | Canvas 逐页渲染 + `getTextContent()` 实现"复制本页文字" |
| OFD | **easyofd**（Canvas 渲染 + 内置文本选择层，页码/缩放/取文本 API 齐备） | easyofd npm 1.2.1（张新攀，执行 GB/T 33190） | Apache-2.0 | `new EasyOFD(id, el)` → `loadFromBlob()`；`GetPageText()` 实现复制；自带工具栏/水印以 CSS 隐藏，统一用本插件 Material 顶栏驱动 |
| Word `.docx` | **mammoth.js**（mammoth.browser.min.js，含依赖单文件） | mwilliamson/mammoth.js ★6.3k | BSD-2-Clause | `convertToHtml({arrayBuffer})` → DOMPurify 清洗后渲染 |
| Excel `.xlsx/.xls` | **SheetJS CE**（xlsx.full.min.js） | SheetJS/sheetjs | Apache-2.0 | `XLSX.read()` → `XLSX.write(_, {type:'string', bookType:'html'})` 按 sheet 渲染表格 |
| Markdown | **marked**（UMD 单文件）+ **DOMPurify** | markedjs/marked ★37.1k；cure53/DOMPurify | MIT；Apache-2.0/MPL-2.0/GPL | `DOMPurify.sanitize(marked.parse(text))`（marked 官方推荐组合） |
| 纯文本 | 无需库 | — | — | `textContent` 渲染（天然无 XSS） |

> 版本锁定与获取方式见 §11 阶段 1；**vendor 文件入库**（它们是插件源码的一部分，不含密钥，符合 SEC-2）。
> mammoth 安全提示：不清洗源文档 → 必须过 DOMPurify 后再 innerHTML；pdf.js/ofd/mammoth 的输出同样先消毒。

## 3. 架构设计

```
外壳页 /tool/knowledge-base（iframe 隔离）
└── plugins/knowledge-base/frontend/index.html   ← 单页双视图：库视图 / 阅读视图
    ├── 库视图：左侧分类树（分级）+ 右侧文件卡片列表 + 搜索 + 上传（仅管理员）
    └── 阅读视图：Material 顶栏（返回/标题/翻页/缩放/复制）+ 只读渲染区

plugins/knowledge-base/backend/routes.py        ← /api/knowledge-base/*
    ├── 分类 CRUD（仅管理员写）
    ├── 文件上传/删除（仅管理员写，SEC-3 校验）
    ├── 文件列表（所有登录用户）
    └── 文件内容流 /files/<id>/raw（Flask send_file，支持 Range 断点，
        attachment 头不设置 → 仅内联供渲染）

数据根目录 plugins/knowledge-base/
├── data/categories.json    # 分类树（单库文件，带 RLock 写）
├── data/files.json         # 文件元数据索引（单库文件）
└── data/files/<file_id>.<ext>   # 上传的原始文件（服务端生成 ID 命名，SEC-3）
```

### 3.1 前后端职责

- **后端只做"存与管"**：鉴权、校验、落盘、元数据；不理解文档内容（解析渲染全在前端）→ 后端零重依赖（无 python-docx/pdf 库），`requirements.txt` 为空。
- **前端只做"读"**：按扩展名分派渲染器；所有库文件惰性按需 `<script>` 注入（打开 PDF 才加载 pdf.js），降低初始体积 → 低性能需求。

### 3.2 权限模型

| 动作 | 谁 | 实现点 |
| --- | --- | --- |
| 上传文件 / 新建·改名·删除分类 / 移动·删除文件 | 管理员角色（`role-admin` / 角色名「管理员」）或超管 | 仿 notice-board `_can_publish()` 判定，后端强校验 |
| 浏览分类、阅读文件、复制 | 全体登录用户 | tools.json 登记 `grant_all: true`；前端入口仅按角色隐藏管理按钮 |
| 未登录 | 一律被框架 302/401 拦截 | SEC-4，插件不另开白名单 |

### 3.3 数据归属（规范 9.2 铁律）

- 分类、文件元数据落盘记录 `created_by` / `created_by_name` / `unit_id` / `department_id` 四字段，**一律取自服务端 session，禁止接收请求体传入**。
- 阅读属"全站公共资源"：不做按单位/部门过滤（列表对所有登录用户可见）；归属四字段仅用于审计与排序展示（"上传人"）。

## 5. 数据模型

### 5.1 categories.json（单库文件 + 全局 RLock）

```jsonc
{
  "version": 1,
  "categories": [
    {
      "id": "cat-xxxxxxxx",        // 服务端生成 "cat-" + 8位hex，正则 ^[A-Za-z0-9_-]+$
      "name": "培训资料",           // ≤40 字符，同层不重名（后端校验）
      "parent_id": null,           // null=根；支持多级（前端限制展示缩进深度≤4，超深层照样可用）
      "order": 1,
      "created_by": "admin",
      "created_by_name": "管理员",
      "unit_id": null,
      "department_id": null,
      "created_at": "2026-09-08T10:00:00"
    }
  ]
}
```

### 5.2 files.json（单库文件）

```jsonc
{
  "version": 1,
  "files": [
    {
      "id": "f-xxxxxxxx",                // 服务端生成；同时是落盘文件名主键
      "name": "某某培训课件",             // 展示名（可改名），≤80 字符
      "original_name": "培训课件.pdf",    // 原始文件名（仅展示，禁止用于拼路径，SEC-3）
      "ext": "pdf",                      // 归一化小写扩展名 = 类型分派依据
      "size": 1234567,                   // 字节
      "category_id": "cat-xxxxxxxx",
      "created_by": "admin",             // ↓ 归属四字段（铁律一）
      "created_by_name": "管理员",
      "unit_id": null,
      "department_id": null,
      "created_at": "2026-09-08T10:00:00",
      "updated_at": null                 // 改名/移动时刷新
    }
  ]
}
```

### 5.3 落盘文件

`data/files/<id>.<ext>`——`<id>` 必须匹配 `^[A-Za-z0-9_-]+$`（SEC-1 目录穿越防线同款正则），扩展名白名单二次确认后才落盘。

## 6. API 设计（前缀 `/api/knowledge-base`，全部 B-2 合规）

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/status` | 登录 | 依赖自检（本插件后端无第三方依赖，恒 ok；报告 vendor 库清单供前端诊断） |
| GET | `/config` | 登录 | `{can_manage}`（管理员判定，前端据此显示/隐藏管理 UI） |
| GET | `/categories` | 登录 | 分类树（数组，前端组树） |
| POST | `/categories` | 管理员 | `{name, parent_id?}`；同层重名 409；父分类不存在 404 |
| PUT | `/categories/<id>` | 管理员 | `{name?, parent_id?, order?}`；parent 不得指向自身/自身子孙（防环） |
| DELETE | `/categories/<id>` | 管理员 | 分类下有子分类或文件时 409 拒绝（要求先清空） |
| GET | `/files?category=&q=` | 登录 | 文件列表：category 为分类 id（或 `root`）；q 模糊匹配展示名/原始名；均不传=全量。返回含上传人姓名、大小、时间 |
| POST | `/files` | 管理员 | multipart：`file` + `name` + `category_id`。校验：扩展名白名单、大小 ≤ 20MB（SEC-3）；落盘用服务端 ID 重命名 |
| PUT | `/files/<id>` | 管理员 | `{name?, category_id?}` 改名 / 移动分类 |
| DELETE | `/files/<id>` | 管理员 | 删元数据 + 删落盘文件（不存在 404） |
| GET | `/files/<id>/raw` | 登录 | **内联**返回文件内容（`send_file`，`conditional=True` 支持 Range；不设 attachment 头 → 不可"另存为下载"）。不可读（不存在/ID 非法）一律 404 |

错误风格统一 `{"error": "..."}` + 4xx（8.4）；越权写 403、资源不存在一律 404（不暴露存在性）。

**支持上传的白名单**：`pdf, ofd, docx, doc, xlsx, xls, md, markdown, txt, csv`。超过 20MB / 白名单外 → 415/413 明确提示；其中 `doc`/`xls` 在落盘前由服务端转换为 `docx`/`xlsx`（转换失败 422、转换产物超限 413），响应附 `converted_from`，元数据记 `original_ext`（前端三处提示：上传 Snackbar / 卡片角标 / 阅读页说明条）。

## 7. 前端设计（Material Design）

### 7.1 视觉体系

- 复用站点 Material 风格语言（参考 shared-docs 的 CSS 变量模式）：`:root` 定义 `--accent/--bg/--card/--text/--border/--shadow/--radius`；accent 取 `#5C6BC0`（Indigo 400，与既有插件不撞色）。
- Material 组件自绘（零框架，与站点一致）：顶栏（elevation 阴影 + 返回箭头）、卡片（圆角 12px + 投影 + hover 抬升）、FAB（管理员上传，右下角）、 chips（类型徽标：PDF 红/Word 蓝/Excel 绿/OFD 青/MD 橙/TXT 灰）、Snackbar（操作反馈）、对话框（上传/删除确认/新建分类）。
- 全屏按钮沿用站点 `.btn-fullscreen` 模式。

### 7.2 库视图（index.html + app.js）

```
┌──────────────────────────────────────────────────────┐
│ 知识库  [搜索框]                          (全屏) (＋上传)│
├──────────────┬───────────────────────────────────────┤
│ ▾ 全部        │ [卡片] 名称        [PDF] 1.2MB · 张三    │
│   ▾ 培训资料   │        2026-09-01          (阅读)      │
│   ▸ 规章制度   │ [卡片] ……                             │
│              │                                       │
│ (管理员: +分类 │  空态：分类下暂无文件                   │
│  重命名/删除) │                                       │
└──────────────┴───────────────────────────────────────┘
```

- 分类树可折叠（details/summary 或自绘），选中态高亮；文件列表按 `created_at` 倒序。
- 管理员专属操作按 `config.can_manage` 显隐（前端隐藏仅是体验，后端强校验兜底）。
- 上传对话框：选择文件 + 展示名 + 目标分类（默认当前选中分类），逐个上传显示进度（fetch 不支持上传进度 → 以"上传中…"状态即可，低性能需求）。

### 7.3 阅读视图（reader.js）

```
┌──────────────────────────────────────────────────────┐
│ ←  课件名称.pdf        [第 2/38 页][－ 100% ＋] [复制] │
├──────────────────────────────────────────────────────┤
│                 （只读渲染区，居中纸张样式）             │
└──────────────────────────────────────────────────────┘
```

**渲染器分派矩阵**（按元数据 `ext`）：

| ext | 渲染方式 | 复制实现 |
| --- | --- | --- |
| `pdf` | pdf.js：**流式连续布局**（全部页纵向排列，占位框预留尺寸，IntersectionObserver 视口附近按需渲染），页码随滚动更新 + 缩放（重渲染，保持滚动比例） | 「复制本页」按钮：`page.getTextContent()` 拼接文本 → 剪贴板 |
| `ofd` | ofd.js：`parseOfdDocument` 后逐页 `renderOfdByIndex` 注入 SVG；页码导航（宽度取容器宽） | OFD 文字层不可靠 → 「复制本页」从解析出的文本节点提取（尽力而为，提取不到提示不支持复制） |
| `docx` | mammoth → HTML → **DOMPurify 清洗** → 纸张样式渲染；表格/图片内联 | 原生选区 + 「复制全文」（取 `innerText`） |
| `xlsx/xls/csv` | SheetJS → 每 sheet `bookType:'html'` 表格；sheet 标签页切换；横向滚动 | 原生选区（表格文本天然可复制） |
| `md/markdown` | marked → **DOMPurify 清洗** → 文档样式渲染 | 原生选区 + 「复制原文」（MD 源文本） |
| `txt` | `textContent` 渲染（等宽保留换行） | 原生选区 |

### 7.4 通用约束

- **只读保障**：渲染容器不用 `contenteditable`；无任何写接口调用；`user-select` 保持可用（复制是需求）；右键菜单不禁用。
- **惰性加载**：库视图仅加载 app.js；进入阅读视图按 ext 动态注入对应 vendor `<script>`（带加载失败降级提示"渲染库缺失"）。
- **资源版本**：所有 vendor 引用从第一天起带 `?v=1`（HANDOFF §6.6 教训）。
- **会话超时**：fetch 包装器对 401/302 统一跳转登录（对齐框架行为）。
- PDF 大文件：流式按需渲染（视口附近页才渲染）+ `render_task.cancel()` 防缩放连点堆积；worker 用同目录 `pdf.worker.min.js`。
- **PDF 画布清晰度**：位图按 `Math.round(视口宽×scale×dpr)` 取整、CSS 尺寸由位图反推，并用
  `<1 设备像素` 的边距补偿把画布校到设备像素网格上（相位 0），合成器才 1:1 贴图；否则居中/
  A4 自动高度算出的小数位置会引入整页双线性重采样（清晰度实测 -36%）。详见阶段 10。
- **内容缩放**：dock 常驻缩放组（－/输入框/＋）对所有格式生效——PDF/OFD 走引擎原生缩放（重渲染/自带 API），其余格式对**背景卡片 `.reader-frame`** 设 CSS `zoom`（0.5~3.0 步进 0.1，随内容重排、滚动条正确，不改浏览器页面缩放）。缩放对象是卡片而非内容元素：`width:100%` 的渲染件（如 Excel 表）只缩内容会溢出白底卡片，缩卡片则全部格式观感一致。
- **百分比输入**：dock 中间的显示框是可编辑输入框（`#zoom-input`），可直接键入 50~300 后回车生效；越界值按当前格式引擎上限钳制（HTML 0.5~3.0，PDF/OFD 0.4~3.0），非法输入失焦回显当前值。**居中始终交给 `margin:0 auto`，JS 不干预对齐**：卡片比视口窄时正常居中；比视口宽时 auto 边距自动收窄（Chrome 实测为均分残留边距）+ `#view-reader` 横向滚动，内容全部可达——不要在 zoom>1 时强行去掉居中（1.2.0 踩坑：卡片仍小于视口时会被错误推到左边）。

## 8. 安全清单对照

| 规范 | 落实 |
| --- | --- |
| SEC-1 目录穿越 | 文件 ID 白名单正则 `^[A-Za-z0-9_-]+$`；落盘路径仅 `DATA_DIR/files/<id>.<ext>`（ext 二次白名单）；raw 接口拒绝一切路径参数 |
| SEC-3 上传 | 扩展名白名单 + 20MB 上限 + 服务端生成 ID 重命名；原始文件名只进元数据字段 |
| SEC-4 匿名 | 框架全局拦截，插件不设白名单；所有接口第一步取 `get_session_user()`，取不到 401 |
| SEC-5 泄漏 | 404/403 不区分"不存在"与"无权"；异常不回堆栈 |
| XSS | mammoth/marked 输出必过 DOMPurify；txt 用 textContent；文件名等插值一律转义 |
| 9.2 铁律 | 归属四字段 session 取值；列表接口对所有登录用户开放为本插件明确设计（§3.3） |
| B-8 日志 | 不自落日志；`set_operation("上传知识库文件" / "删除分类" 等)` 标记写操作 |

## 9. 性能策略（低性能需求）

1. **无后端解析**：后端零第三方依赖，不做文档解析；CPU 消耗全部在客户端、且仅阅读时发生。
2. **惰性 vendor**：按格式注入脚本，库视图初始 JS < 100KB。
3. **单库 JSON + RLock**：分类/文件元数据各一个 JSON 文件，读写加全局锁（量级：百级文件，无性能问题）；文件字节流由 `send_file` 直出（etag/Range/304 由框架处理）。
4. **PDF 逐页渲染**：同一时刻仅渲染当前页，翻页取消上一个渲染任务。
5. gzip：`.md/.txt` 与 API JSON 走框架统一 gzip（app.py 中间件），无需插件处理。

### 阶段 10：PDF 预览清晰度——设备像素对齐 ✅ 2026-09-15（用户反馈"分辨率低、模糊"）

> 根因**不是** dpr 没处理（PDF/OFD 渲染一直按 `scale × devicePixelRatio` 出图，
> 实测位图/显示比值 1.0 / 1.2497 / 1.4993 全部正确），而是**画布没落在设备像素网格上**：
> 页面居中（`margin:0 auto`）与 A4 自动高度（841.89pt × 1.25 = 1052.36px）都会算出小数
> 位置，乘 dpr 后相位是小数（实测左相位 0.375），合成器随即对整张画布做双线性重采样。
> 同位置截图实测：修复前屏幕合成只保留画布位图 **64%** 的边缘对比度、文字最暗像素 8 级
> （发灰）；修复后保留 **99%**、最暗 0 级（纯黑），整体锐度 **+72%**。
