## 1. 需求与概述

| # | 需求 | 实现要点 |
| --- | --- | --- |
| 1 | 框架**本地内置** LLM 能力，统一大模型 API / Key 调用接口 | 主体模块 `jz_llm.py`（框架级，插件 import 即用） |
| 2 | 插件**只拟定、保存 prompt**；把参数与 prompt 推给 LLM 模块 | `jz_llm.load_prompt/save_prompt/render` + `chat/chat_json/chat_text` |
| 3 | LLM 模块负责与大模型交互，并把结果回推插件 | `chat()` 返回 `{text, json, usage, format, model, source}` |
| 4 | 两种模式，由管理员或超级管理员确定：① 管理员定 API 地址/格式/Key；② 用户单独设置 | `llm.json` 的 `mode = admin / user`；后台「大模型设置」页切换 |
| 5 | 用户可在**主界面右下角「三个点」**里自助设置；管理员未开启则**不显示该选项** | 入口由 `static/js/llm-settings.js` 按 `/api/llm/settings` 的 `can_self_config` 动态注入 |
| 6 | 点击后以**悬浮卡片**形式展示设置界面 | 居中对话框 + 背景调暗/模糊（`.llm-overlay` / `.llm-card`，见 §5.3） |
| 7 | 界面允许设定**多种 API 调用格式** | openai / anthropic / ollama / custom 四种（§3.2） |
| 8 | 用户须填写**完整 API 地址**（如 OpenAI 格式要填到 `chat/completions`） | 一律"完整接口地址"，框架不做任何路径拼接（§3.2 末尾的踩坑说明） |

### 1.1 为什么要有这个模块

迁移前，三个业务插件各自复制了一份 `llm_client.py`（HTTP 调用、JSON 解析、连通测试几乎逐行相同），
**API Key 也各存各的**——插件之间禁止互相 import（规范 B-7 / 解耦设计文档 D-9），于是只能复制：
三处口径、三处漏改风险，管理员换一个 Key 要改三个地方。

本模块把这部分能力**提升为主体模块**（与 `jz_api` / `jz_deps` / `jztools_data` 同一层），
一次性解决三件事：

1. **凭据集中**：Key 只存一处（全局配置或用户账号），插件不再持有任何凭据；
2. **口径统一**：格式适配、错误文案、连通测试、JSON 容错解析全项目一套；
3. **可自助**：管理员可把接入配置下放给用户各自维护（"用户各自设置"模式），
   而不必为每个插件、每个用户各配一遍。

## 2. 架构与调用链

### 2.1 分层

```
┌──────────────────────────── 主体（框架） ────────────────────────────┐
│  jz_llm.py        统一大模型模块：配置解析 / 格式适配 / 调用 / 提示词存取   │
│  app.py           /api/llm/*（用户自助设置，外壳用，与插件无关）           │
│  jz_api.py        provider 接缝：用户级配置读写（实现由 admin 注册）       │
└──────────────────────────────────────────────────────────────────────┘
        ▲ import（框架 API 面，白名单放行）        ▲ provider 注入
        │                                          │
┌───────┴────────┐  ┌──────────────────┐  ┌────────┴─────────┐
│ case-report    │  │ character-graph  │  │ file-filter      │   ← 业务插件
│ 只拟定/保存     │  │ 只拟定/保存       │  │ 只拟定/保存       │
│ prompt + 领域   │  │ prompt + 领域     │  │ prompt + 防幻觉   │
│ 后处理          │  │ 后处理            │  │ 校验              │
└────────────────┘  └──────────────────┘  └──────────────────┘
        ▲ 配置界面                                    ▲ 配置界面
┌───────┴──────────────────┐            ┌─────────────┴──────────────┐
│ 管理后台 → 大模型设置      │            │ 首页右下角 ⋯ → 大模型设置     │
│ （管理员/超管：模式+全局）  │            │ （用户：自己那一份，可选）    │
└──────────────────────────┘            └────────────────────────────┘
```

### 2.2 一次调用的完整链路

```
插件路由（请求线程）
   │  ① session = jz_llm.resolve(PLUGIN_ID)      ← 读会话，解析出"用哪一份配置"
   │  ② prompt  = jz_llm.load_prompt(...)        ← 插件拟定并保存的提示词
   │  ③ 把 session 交给后台线程（线程纪律，见 §2.4）
   ▼
插件 llm_client（薄适配层：领域提示词 + 领域后处理）
   │  ④ jz_llm.chat_json(system, user, session=session, plugin_id=...)
   ▼
jz_llm
   │  ⑤ 按 format 构造请求（§3.2）→ 发 HTTP → 取正文 → 可选解析 JSON
   ▼
返回 {text, json, usage, format, model, source} → 插件继续业务处理
```

### 2.3 配置解析顺序（`resolve()`）

| 顺序 | 条件 | 来源（`source`） |
| --- | --- | --- |
| 1 | 模式 = user 且当前用户已配置且可用 | `user`（用户自己配置） |
| 2 | 模式 = admin，或模式 = user 且 `fallback=true` | `global`（管理员统一配置） |
| 3 | 都没有 | 未配置（`source=""`，`reason` 给出可执行的下一步） |

> 插件历史 `config.json` 的 `llm` 段**已不再被读取**（兼容桥于 2026-09-23 移除，
> 见 §8.1）：那些旧 Key 由 admin 插件的启动迁移收编进统一配置（加密）后清除插件侧副本。

未配置时的提示语按模式分岔，直接告诉用户去哪儿配：

- 管理员模式：`尚未配置大模型：请联系管理员在「管理后台 → 大模型设置」中填写`
- 用户模式：`尚未配置大模型：请点击主界面右下角「⋯」→「大模型设置」填写`

### 2.4 线程纪律（**最容易踩的坑**）

`resolve()` 要读会话（当前登录用户），而 Flask 的会话只存在于**请求线程**。插件的
大模型调用普遍跑在线程池里（case-report / character-graph / file-filter 都是后台任务），
后台线程里 `resolve()` 读不到用户 → 在"用户各自设置"模式下会被**误判为未配置**，
表现为"我明明配好了却说没配"。

因此约定：

```python
# 请求线程内（路由函数里）
session = jz_llm.resolve(PLUGIN_ID)
task_id = _submit_parse(text, session, prompt)     # 把 session 传进任务

# 后台线程内
jz_llm.chat_json(system, user, session=session, plugin_id=PLUGIN_ID)
```

`LLMSession` 是不可变快照，**可跨线程传递**；`test_llm_module.py::test_session_crosses_thread_boundary`
钉住这条契约。

## 3. 插件调用契约

### 3.1 模块 API（`import jz_llm`）

| 分类 | API | 说明 |
| --- | --- | --- |
| 调用 | `chat(system, user, *, messages=None, session=None, plugin_id=None, model=None, temperature=None, max_tokens=None, timeout=None, json_mode=False)` | 返回 `{text, json, usage, format, model, source}` |
| | `chat_text(...)` / `chat_json(...)` | 只要正文 / 只要 JSON（`json_mode=True` 的便捷形式） |
| | `test_connection(session=None, provider=None, plugin_id=None, timeout=15)` | 连通性测试，返回 `(ok, detail)` |
| 配置 | `resolve(plugin_id=None)` → `LLMSession` | 解析当前生效配置（**仅请求线程**） |
| | `normalize_provider(raw)` / `provider_usable(p)` / `provider_problem(p)` | 规整与判定（供插件回显状态） |
| | `mode()` / `user_mode()` / `load_global()` / `save_global()` | 模式与全局配置（后台页用） |
| | `formats_public()` | 格式清单（前端渲染下拉框用） |
| 提示词 | `load_prompt(plugin_id, defaults)` / `save_prompt(plugin_id, prompt)` | 存 `<数据根>/plugins/<id>/prompt.json` |
| | `render(template, values=None, **kw)` | `{name}` 占位符替换（只替换给定键） |
| 异常 | `LLMError` | 所有失败都抛它，`str(e)` 可直接展示给用户 |

### 3.2 四种调用格式

| format | 认证 | 报文 | 正文取值路径 |
| --- | --- | --- | --- |
| `openai` | `Authorization: Bearer <key>` | `{model, messages[system,user], temperature, stream:false}` | `choices.0.message.content` |
| `anthropic` | `x-api-key: <key>` + `anthropic-version: 2023-06-01` | `{model, system, messages[user], max_tokens}`（system 顶层、max_tokens 必填） | `content.0.text` |
| `ollama` | 可选 Bearer | `{model, messages, stream:false, options:{temperature}}` | `message.content`，取不到再试 `response`（兼容 `/api/generate`） |
| `custom` | 自定义请求头模板 | 自定义请求体模板（JSON） | 自定义 `text_path`（`a.b.0.c` 或 `a.b[0].c`） |

**自定义格式的占位符**（双花括号，避免与 JSON 自身的 `{}` 冲突）：
`{{model}}` `{{system}}` `{{user}}` `{{temperature}}` `{{max_tokens}}` `{{api_key}}` `{{messages_json}}`。
字符串值替换前按 JSON 字面量**转义**（引号/反斜杠/换行），所以提示词里的引号与换行不会把 JSON 打坏——
字符串占位符写在引号内即可：

```json
{"model": "{{model}}", "prompt": "{{system}}\n{{user}}", "n": {{max_tokens}}}
```

> ⚠ **地址一律填完整接口地址，框架不做任何路径拼接**。历史插件允许填 `base_url`（框架补
> `/chat/completions`），结果"少写 `/v1`"与"多写一次 `chat/completions`"都会 404，而报错信息
> 与真实原因无关（排查成本极高）。统一后口径只有一个：OpenAI 兼容就填到 `…/chat/completions`，
> Anthropic 填到 `…/v1/messages`，Ollama 填到 `/api/chat`。唯一例外是 §8.1 的**一次性收编迁移**
> ——它把历史插件配置里的 `base_url` 补全后写进统一配置，此后一切按上面的唯一口径走。

### 3.3 各插件保留了什么

插件**不再**持有：API 地址、API Key、模型名、HTTP 调用、JSON 容错解析、连通测试。
插件**保留**（属于业务，不该进框架）：

| 插件 | 保留内容 |
| --- | --- |
| case-report | 五要素提示词、"输出必须是键值对 JSON"的领域约束、五要素规整 |
| character-graph | 人物/关系提示词、"关系必须引用已识别人物"的自洽过滤 |
| file-filter | 字段匹配提示词、"模型只能返回名单内字段"的防幻觉映射 |

三个插件的 `llm_client.py` 因此变成**薄适配层**（保留原有函数名，插件内调用点零改动）。

## 4. 配置与存储位置

| 内容 | 位置 | 归属 | 加密 |
| --- | --- | --- | --- |
| 全局配置（模式 / 回退 / 全局接入信息） | `<数据根>/config/llm.json` | `jz_llm` 自己读写 | `api_key` 用 Fernet 加密 |
| 用户配置（每人一份接入信息） | `<数据根>/config/admin.json` 的 `units[].departments[].users[].llm` | admin 插件（经 `jz_api` provider 存取） | 同上 |
| 提示词 | `<数据根>/plugins/<id>/prompt.json` | 各插件（经 `jz_llm` 读写） | 明文（不含凭据） |
| 加密密钥 | `<数据根>/config/.admin_key` | 与 admin 共用同一把 | — |

**为什么不另立一份用户配置**：账号数据归 admin 插件所有，`user.llm` 已经在
`admin.json` 里（加密、后台人员管理可编辑、批量导入导出已覆盖）。再开一个
`llm_users.json` 会出现"同一用户两处配置"，是典型的不一致来源。故用户侧经
`jz_api` 的 `get_user_llm` / `save_user_llm` 两个 provider 取用（依赖倒置，
与 `get_session_user` 同一手法）。

### 4.1 `llm.json` 结构

```json
{
  "mode": "admin",            // admin = 管理员统一配置；user = 用户各自设置
  "fallback": true,           // user 模式下，用户未配置时是否回退全局配置
  "provider": {
    "format": "openai",
    "url": "https://api.deepseek.com/chat/completions",
    "api_key": "gAAAAA…（密文）",
    "model": "deepseek-v4-flash",
    "temperature": null,      // 留空 = 用默认 0.2
    "max_tokens": null,       // 留空 = 用服务默认
    "timeout": 120,
    "headers": {},            // custom 专用
    "body": "",               // custom 专用
    "text_path": "",          // custom 专用
    "error_path": ""          // custom 专用
  }
}
```

字段钳制：`temperature` 钳到 `[0, 2]`；`max_tokens` / `timeout` 为 0 或负数时视为
**未设置**（而不是钳成 1——那会让模型只输出一个 token，用户看不出原因）。

## 5. HTTP 接口清单

### 5.1 框架级（`app.py`，供外壳/用户自助）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/llm/settings` | 模式、格式清单、**本人**配置（脱敏）、当前生效来源；`can_self_config` 决定首页是否出现入口 |
| POST | `/api/llm/settings` | 保存**本人**配置；管理员模式下 403（避免"我配了怎么没生效"） |
| POST | `/api/llm/test` | 连通性测试（测表单里这套，缺省测已保存的） |

### 5.2 后台（admin 插件，管理员 / 超级管理员）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/admin/llm` | 大模型设置页（管理员或超级管理员；否则 302 回后台首页） |
| GET/POST | `/api/admin/llm-settings` | 读/写全局配置（模式、回退、接入信息）；Key 只回掩码。**POST 按字段局部更新**：只改传进来的字段，未传的保持原值——界面两张卡因此各存各的：「调用模式」卡改模式/回退开关即**自动保存**（只提交 `mode`/`fallback`，页面无保存按钮），「全局接入配置」卡的保存按钮只提交 `provider`，**不影响调用模式**（全量提交也照常工作，向后兼容） |
| POST | `/api/admin/llm-test` | 连通性测试（测表单里这套） |

鉴权口径：`can_manage_llm(info)` = 超级管理员 或 `role-admin`/`管理员`——与各业务插件里
`_can_manage()` 的判定同一对角色常量。比"仅超级管理员"的敏感操作（数据目录、插件管理）放宽一档，
因为需求口径是"由管理员或超级管理员确定"。

### 5.3 外壳入口（首页右下角 ⋯）

- `static/js/llm-settings.js`：拉 `/api/llm/settings`，`can_self_config=false` 时**什么都不做**
  （"管理员未开启 → 该选项不显示"由数据驱动，不需要后端渲染开关）；
- 为真时把「💡 大模型设置」项注入既有悬浮球菜单（`#fab-pop`）；
- 点击打开**居中对话框**（`.llm-overlay` 遮罩 + `.llm-card` 卡片）：背景调暗
  `rgba(32,33,36,.45)` + 模糊 `blur(6px)`（与框架既有 `.modal` 同一调暗口径；模糊需
  Chrome ≥76，旧内核自动退化为"仅调暗"）；
- 卡片三段式：**头部固定**（标题 + ✕）/ **主体滚动**（格式下拉、完整 API 地址、API Key、
  模型名称；选 `custom` 时展开"额外请求头 / 请求体模板 / 正文取值路径 / 错误信息取值路径"）/
  **底部固定**（状态说明 + 保存 / 测试连通）——按钮与状态不随内容滚走；
- **滚动条放在内层主体**（`.llm-card-body`），卡片本身只 `overflow: hidden`：卡片自带圆角时，
  压在卡片上的内部滚动条会盖住右侧两个圆角，看起来像"圆角失效"（同类缺陷见 HANDOFF §7.3 第 22 条）；
- 对话框常驻 DOM（`hidden` 切换），打开时给 `body` 加 `llm-card-open`：锁页面滚动 +
  收起悬浮球菜单（否则菜单从遮罩下透出）；点遮罩 / Esc 关闭；
- 遮罩 `z-index: 66` = 悬浮球（60）之上、轻提示 toast（70）之下——保存后的提示条必须能
  浮在调暗层之上，否则用户看不到"已保存"；
- 状态区说明"本人配置是否可用"与"当前实际生效的是哪一份"（回退到管理员配置时用中性文案，
  不用红字——那不是错误）。

## 6. 插件迁移口径

| 项 | 迁移前 | 迁移后 |
| --- | --- | --- |
| 接入信息 | 各插件 `config.json` 的 `llm` 段（明文 Key） | 统一配置（`llm.json` / 账号数据） |
| `GET /api/<id>/config` | 回传 `base_url` / `api_key_masked` / `model` | 只回 `llm_configured` / `llm_source` / `llm_source_label` / `llm_reason` |
| `POST /api/<id>/config` | 可写接入信息 | 兼容占位：本插件已无接入信息可写（历史 `llm` 段由启动迁移收编并清除，见 §8.1） |
| `POST /api/<id>/config/test` | 测表单/插件配置 | 测统一大模型当前生效的配置 |
| 解析/过滤接口 | 前端可传 `base_url`/`api_key`/`model` | 只传业务参数；凭据由 `resolve()` 解析 |
| 前端配置卡片 | 地址 / Key / 模型 三个输入框 | 一行状态（可用性 + 来源 + 去哪儿改） |
| `requests` 可用性 | 插件各自保护性 import | 转发 `jz_llm.REQUESTS_AVAILABLE`（标记名不变，`/status` 与 `jz_deps` 刷新零改动） |
| `manifest.requires` | 声明 `requests` | **保留声明**（依赖门控语义不变；出包只提示"声明了但实测未 import"，属正常） |

提示词文件位置**不变**（`<数据根>/plugins/<id>/prompt.json`），因此**不产生数据迁移**；
file-filter 原先硬编码在函数里的用户消息也提为模板常量并接入 `load_prompt`，
三个插件自此口径一致。

## 7. 安全

| 项 | 措施 |
| --- | --- |
| Key 落盘 | 全局配置与账号数据里的 Key 一律 Fernet 加密（`config/.admin_key`） |
| Key 回显 | 所有接口只回固定掩码 `••••••••`（含后台「人员管理」的账号列表——2026-09-23 起不再回明文，原先那里是唯一例外）；掩码/留空回传 = 不修改已保存的 Key；明文 Key 只存在于服务端与落盘密文里 |
| Key 泄漏面 | 插件接口不再回传任何凭据字段（`test_llm_module.py` 断言响应里不含 `api_key`/`base_url`/明文 Key） |
| 越权 | 个人设置只写自己的账号（用户名取自会话，不信任请求体）；全局设置需管理员角色；`/admin/llm` 非管理员 302 |
| 模式一致性 | 管理员模式下个人保存直接 403，不让用户以为自己的设置生效了 |
| 错误信息 | 接口错误只回可读文案（HTTP 状态 + 服务端 message 截断 300 字），不透出堆栈/路径 |
| SSRF 面 | 地址由管理员或用户本人填写（与插件时代一致），无新增面；超时钳制 `[1, 3600]` 秒 |

## 8. 遗留与后续

### 8.1 插件历史配置的收编与清除（兼容桥已移除）

**现状（2026-09-23 起）**：`jz_llm.resolve()` **不再**回退读取插件 `config.json` 里的
`llm` 段；插件侧也不再保存任何接入信息（`llm_client` 是薄适配层，配置项已从
`DEFAULT_CONFIG` 与 `config.template.json` 中删除）。`source` 只剩 `user` / `global` / 未配置三种。

**历史 Key 怎么办**：升级前三个插件各存了一份**明文** Key（同一把重复三份）。直接删掉会让
老部署的大模型功能一夜失效，所以由 admin 插件在启动时做一次**先收编、再清除**的迁移
（`migrate_plugin_legacy_llm()`，幂等）：

| 步骤 | 动作 |
| --- | --- |
| ① 收编 | 统一配置还没有可用接入信息时，把插件那份搬进 `<数据根>/config/llm.json`（**加密**落盘；历史语义即 OpenAI 兼容，`base_url` 省写时补全为完整接口地址） |
| ② 清除 | 无论是否收编，都删除插件 `config.json` 里的 `llm` 段（原子写），消除明文副本 |
| ③ 记账 | 多份重复副本只收编第一份，其余丢弃并记日志（三份本来就是同一把 Key） |

日志会写明"从哪个插件收编、清除了哪几个插件的副本"。若某次清除失败（文件被占用等），
该文件保持原样并记 warning，下次启动重试——不会留下"删了一半"的中间态。
