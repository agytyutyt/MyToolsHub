# 管理后台：单位 / 部门 / 人员 批量导入导出 设计文档

> 状态：**已实现并实测通过** · 设计版本 v1.0 · 2026-09-11
> 归属：核心插件 `admin`（`plugins/admin/`）· 新增同包子模块 `backend/batch_io.py`
> 依据：《插件设计规范.md》· 项目 README · HANDOFF.md §4.5

---

## 1. 需求与概述

管理后台的组织架构为 **单位(units) → 部门(departments) → 用户(users)** 三层，
此前只能逐条手工录入。批量初始化、系统迁移、人员名册同步都需要导入导出通道。

| # | 需求 | 实现要点 |
| --- | --- | --- |
| 1 | 单位、部门、人员三处都要有批量导入导出 | 统一模块 `MODULE_SPECS` 描述三套列规格，接口按 `<module>` 复用 |
| 2 | 导入前必须能看清会改什么 | **两步式**：`dry_run=1` 预览逐行结果（新增/更新/跳过/错误 + 原因），确认后才写盘 |
| 3 | 要能处理"已存在"的记录 | 三种导入方式：`upsert`（默认）/ `insert`（仅新增）/ `update`（仅更新） |
| 4 | 不能因为一行写错就污染整库 | 默认 `on_error=abort` 整批回滚（可切 `skip` 跳过错误行） |
| 5 | Excel 用户要能直接用 | `.xlsx`（模板附「填写说明」工作表）+ `.csv`（UTF-8-SIG / GBK 自适应） |
| 6 | 导入部门/人员时上级可能还没建 | 可选「自动创建上级组织」（`auto_create_parent=1`） |
| 7 | 敏感数据不能跟着导出乱跑 | 密码列恒为空；大模型 API Key 默认留空，需 `?sensitive=1` 才导出明文 |
| 8 | 权限与现有模块权限一致 | 批量接口分别要求 `unit` / `department` / `user` 模块权限 |

**非目标**：不改动 `config/admin.json` 的数据结构（批量写入完全复用现有三层结构）；
不引入新的前端框架或第三方前端库。

## 2. 业务流程

```
                   ┌── 模板下载  GET  /api/admin/batch/<module>/template?format=xlsx|csv
   管理页头部三按钮 ─┼── 导出      GET  /api/admin/batch/<module>/export?format=xlsx|csv
                   └── 批量导入  POST /api/admin/batch/<module>/import
                                      │
   ① 选择文件（.xlsx/.csv）            │  FormData: file + mode + dry_run + auto_create_parent + on_error
      选择导入方式 / 错误行策略        │
                                      ▼
   ② 预览校验  dry_run=1 ──▶ _parse_table（表头宽松匹配 → 逐行取值）
                                      │
                                      ▼
                        _run_import(module, cfg, items, mode, auto_create_parent)
                            在 copy.deepcopy(cfg) 上推演 → work, rows[]
                                      │
              ┌───────────────────────┴────────────────────────┐
              │ dry_run=1：仅回传 rows（create/update/skip/error）│ 不落盘
              │ dry_run=0：summary.error>0 且 on_error=abort      │
              │            → blocked=true，不落盘                 │
              │            否则 save_admin_config(work)           │ 原子写盘
              └──────────────────────────────────────────────────┘
                                      │
   ③ 确认导入（复用②的选项）──▶ 完成面板（新增/更新/跳过/错误 汇总）──▶ 列表自动刷新
```

```
plugins/admin/

│   ├── batch_io.py            # 新增：模块规格、解析、推演、导出、模板（本次全部后端逻辑）

│   └── requirements.txt       # + openpyxl>=3.1（缺库时自动降级为仅 CSV）
├── frontend/
│   ├── js/admin-common.js     # + batchImport()（两步式浮窗）、download()（Blob 下载）
│   ├── js/admin-{unit,dept,user}.js
│   ├── admin-{unit,department,user}.html
│   └── css/admin.css          # + .batch-* / .admin-head-actions
└── manifest.json              # 版本 1.1.0 → 1.2.0，features +「批量导入导出」
```

**为什么单独放 `batch_io.py`**：《插件设计规范》允许"`backend/routes.py` 及同包模块"。
`routes.py` 已 1300 行，批量导入导出自带约 700 行（规格 + 解析 + 推演 + 导出），
独立成包内模块更易维护。

**依赖注入而非反向 import**：`batch_io` 若 import `routes` 会与 `routes` 顶部
`from . import batch_io` 形成循环导入。改为 `routes._register_batch_io(app)` 显式注入
12 个依赖（配置读写 / 层级查找 / 加解密 / 角色判定 / 工具集 / 会话 / 操作标签），
`batch_io` 只依赖注入进来的接口，便于单独测试。

## 4. 列规格（三维度）

表头**宽松匹配**：归一化（去空白与 `_ - . ( ) / :` 等）后先精确匹配，再按别名「包含」兜底
（长别名优先，避免「单位」抢走「所属单位」）。未识别的列忽略并在结果里回传 `ignored_columns`。

### 4.1 单位（`module=unit`，唯一键 = 单位名称）

| 列名 | 必填 | 说明 |
| --- | --- | --- |
| 单位名称 | ✓ | 系统内唯一；已存在则按导入方式处理 |
| 描述 | — | 单位职责说明 |

### 4.2 部门（`module=department`，唯一键 = 所属单位 + 部门名称）

| 列名 | 必填 | 说明 |
| --- | --- | --- |
| 所属单位 | ✓ | 单位名称或单位 ID；勾选自动创建时不存在则建 |
| 部门名称 | ✓ | 同一单位内唯一 |
| 描述 | — | 部门职责说明 |

### 4.3 人员（`module=user`，唯一键 = 登录名）

| 列名 | 必填 | 说明 |
| --- | --- | --- |
| 登录名 | ✓ | 唯一，仅字母/数字/`_`/`.`/`-`，创建后不可改 |
| 姓名 | ✓ | |
| 密码 | 新增时 ✓ | ≥6 位；更新时留空表示不改密码 |
| 所属单位 | ✓ | 名称或 ID |
| 所属部门 | ✓ | 该单位下的名称或 ID |
| 角色 | — | 角色名称或 ID（如「办案员」）；留空不修改，`-` 表示不分配 |
| 身份证号码 | — | 加密存储；留空不修改，`-` 清空 |
| 大模型BaseURL / 大模型APIKey / 模型名称 | — | 留空不修改，`-` 清空；API Key 加密存储且导出默认留空 |
| 权限点 | — | 工具 ID 或工具名称，多值用顿号/分号/空格分隔；新增留空 = 默认全部工具（不含管理后台） |

## 5. 接口契约

### 5.1 模板下载

`GET /api/admin/batch/<module>/template?format=xlsx|csv`
→ `Content-Disposition: attachment; filename*=UTF-8''单位导入模板.xlsx`
xlsx 含两个工作表：`单位`（表头 + 一行示例）与 `填写说明`（每列必填性与填写规则 + 通用说明）。

### 5.2 导出

`GET /api/admin/batch/<module>/export?format=xlsx|csv[&sensitive=1]`
列结构与模板**完全一致**，因此导出文件改完可直接回导。密码列恒为空。
身份证号明文导出（`/api/admin/users` 本就返回，保持可回导）；大模型 API Key 默认空，
仅 `sensitive=1` 时导出明文。

### 5.3 导入

`POST /api/admin/batch/<module>/import`（`multipart/form-data`）

| 字段 | 必填 | 取值 |
| --- | --- | --- |
| `file` | ✓ | `.xlsx` / `.xlsm` / `.csv`（`.xls` 明确提示另存） |
| `mode` | — | `upsert`（默认）/ `insert` / `update` |
| `dry_run` | — | `1`（默认，仅预览）/ `0`（写盘） |
| `auto_create_parent` | — | `1` / `0`（默认，上级缺失即报错） |
| `on_error` | — | `abort`（默认，整批回滚）/ `skip`（跳过错误行） |

返回：

```json
{
  "ok": true, "module": "unit", "label": "单位",
  "mode": "upsert", "mode_name": "存在则更新，不存在则新增",
  "dry_run": true, "applied": false, "blocked": false,
  "summary": {"total": 3, "create": 2, "update": 0, "skip": 0, "error": 1},
  "rows": [
    {"row": 2, "action": "create", "label": "一大队", "message": "新增单位"},
    {"row": 4, "action": "error", "label": "（未填写单位名称）", "message": "单位名称不能为空"}
  ],
  "ignored_columns": [], "missing_columns": [], "total_rows": 3
}
```

`action` ∈ `create` / `update` / `skip` / `error`；`row` 为 **Excel 行号**（表头为第 1 行），
便于用户直接定位。

## 6. 校验与语义规则

| 规则 | 说明 |
| --- | --- |
| 唯一键命中 | 视为"更新"；`insert` 模式下改为跳过，`update` 模式下不存在即跳过 |
| 留空语义 | **不修改**（避免用空值误清数据） |
| `-` 语义 | 「清空该字段」（角色 / 身份证 / 大模型三项 / 权限点均适用） |
| 幂等 | 内容与现状一致时统一回 `skip`（不写盘、不报"更新"）；加密字段先解密再比对 |
| 文件内重复 | 同一文件内重复唯一键 → 该行报错（不静默合并） |
| 必填缺列 | 直接 400：「缺少必需列：单位名称（请使用下载的模板填写）」 |
| 行数 / 体积 | ≤3000 行、≤10 MB，超出直接拒绝 |
| 整批回滚 | `on_error=abort` 且存在错误行 → `blocked=true`、`applied=false`，一个字节都不写 |
| 超级管理员护栏 | 超管账号的角色 / 权限点**不可**通过批量导入修改（其余字段可同步），防止误降权后无人能进后台 |
| 归属调整 | 人员行的单位/部门与现状不同 → 自动从原部门移除并挂到新部门（消息中标注） |

## 7. 前端交互（两步式浮窗）

`AdminCommon.batchImport({module, label, allowAutoParent, onDone})` 三态状态机：

1. **选择文件**（`stepPicker`）：模板/导出快捷入口 + 拖拽或点击选择文件 + 导入方式 +
   自动创建上级（部门/人员页）+ 错误行策略（默认整批回滚）+ 前端预校验扩展名。
2. **预览结果**（`stepPreview`）：汇总胶囊（共 N 行 / 新增 / 更新 / 跳过 / 错误）+
   逐行明细表（结果着色：绿=新增、橙=更新、灰=跳过、红=错误）+ 未识别列提示 +
   回滚时禁用「确认导入」并给出橙色警示条。
3. **完成**（`stepDone`）：汇总 + 「完成」按钮，关闭后 `onDone()` 刷新列表。

要点：
- 预览时的选项存进 `state.opts`，确认导入原样复用 → **预览所见 = 执行所得**；
- 「返回修改」可退回第 1 步改策略后重新预览，不必重新选文件；
- `download()` 用 `fetch + Blob` 而非直接跳链接，这样会话过期能走 401 跳登录、
  后端 JSON 错误能弹 toast，并可从 `Content-Disposition` 解析中文文件名（优先 `filename*`）；
- 拖拽区内的 `input.click()` 必须判断 `e.target === input` 再返回，否则 click 冒泡会无限递归。

## 8. 安全与异常

- **权限**：三个批量接口分别要求 `unit` / `department` / `user` 模块权限。
  由于路由在 `/api/admin/` 下而 `_enforce_tool_access` 对 `admin` 前缀直接放行，
  **必须在视图内自行校验**（`batch_io._check_access`：未登录 401 / 无模块权限 403）。
- **登录**：`_enforce_login` 统一拦截，未登录一律 401，与后台其它接口一致。
- **敏感字段**：密码不导出；API Key 默认不导出；身份证号明文导出（与 `/api/admin/users`
  的既有可见性一致，保证可回导）。导入值一律经 `encrypt_field` 加密后落盘。
- **审计**：所有批量操作走 `set_operation("批量导入单位" / "导出人员清单" / …)`，
  访问日志可识别具体操作。
- **降级**：缺 `openpyxl` 时 xlsx 相关请求返回明确错误并提示改用 CSV，不影响登录鉴权等核心功能。

**实测拦截的真实缺陷**（均已修复）：

| # | 缺陷 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 导入接口一律 400「文件解析失败：'required'」 | 列规格中 `description` 等列没有 `required` 键，却用 `c["required"]` 下标访问 | 改 `c.get("required")` |
| 2 | 导出后原样回导，admin 账号被判"不支持批量修改角色/权限点" | 护栏只看"文件里有没有填角色/权限点"，没比较是否真的变化 | 只在值确实不同时才拦截 |
| 3 | 默认"整批回滚"下仍可点「确认导入」，点了显示"导入完成"但实际未写入 | 前端 `blocked` 判定写成"错误数 = 总行数"，且未读后端 `blocked` 字段 | 直接用后端 `blocked`，禁用按钮并给橙色警示 |
| 4 | 单位/部门/身份证/大模型字段未变也报"已更新" | 更新分支未比对现值 | 逐字段比对，未变回 `skip` |

## 10. 单元格格式与文件结构健壮性（2026-09-11 加固）

用户交上来的表格什么格式都有。解析层按「结构层」与「值层」两层做了兜底，
每一条都有对应回归用例（见 §11，格式套件 64 项）。

### 10.1 结构层

| 输入情形 | 不处理会怎样 | 现在的行为 |
| --- | --- | --- |
| 表头上方有标题行/说明行/空行 | 把标题行当表头 → 整表数据错位或误建"单位名称"这种垃圾记录 | 向下探测前 8 行，按「必填列齐全 > **精确匹配列数** > 匹配列数」择优；`header_row` 回传并在界面提示。用精确匹配数做次级排序，可避免「单位名称与描述说明」这类标题行抢走表头 |
| 数据不在第一张工作表 | 读空表 → "未解析到任何数据行" | xlsx 的**每个工作表**都作为候选，按表头匹配度择优；`sheet` 回传并在界面提示 |
| 纵向合并单元格（如"所属单位"合并 3 行） | openpyxl 只在左上角给值，其余行为空 → 下方全部报"所属单位不能为空" | 按合并区域把左上角值补全到区域内（`_fill_merged`），提示补全了几个单元格。**注意：只读模式下拿不到 `merged_cells`，因此改用普通模式加载**（文件已限 10MB） |
| 横向合并的标题行 | 可能被误判为表头 | 同「表头定位」：合并后各列值相同，精确匹配数低于真表头，自然落选 |
| 重复表头行（复制表头造成） | 多建一条名为"单位名称"的记录 | 整行非空值都等于对应表头文本的行自动忽略并提示 |
| CSV 用分号/制表符/竖线分隔 | 整行挤成一列 → "缺少必需列" | 逗号/制表符/分号/竖线各解析一份作为候选，按表头匹配度择优；`.tsv` 优先按制表符 |
| 超行数（>3000）或超体积（>10MB） | 读全表才发现超限，大文件吃内存 | 读取阶段即按行数上限截断（`_GRID_ROW_LIMIT`），解析阶段给出明确 400；体积在读取前校验 |
| 损坏/伪装文件（截断 zip、二进制伪装 csv、空字节） | 可能直接 500 | 全部转成 400 明确提示；模糊测试 73 次请求 0 个 5xx |

### 10.2 值层

| 单元格格式 | 取到的值 | 现在的行为 |
| --- | --- | --- |
| 百分比（0.00%） | 底层 `0.5`，不带 `%` | 原样取值（**显示格式不影响取值**，已在填写说明中告知） |
| 日期 / 时间 | `datetime` 对象 | 转可读文本：纯日期 `2026-09-11`，含时间 `2026-09-11 10:30:00` |
| 布尔 | `True/False` | 转「是 / 否」 |
| 科学计数 / 大数 | 浮点还原 | 整数型浮点去掉 `.0`，`1.5e20` → `150000000000000000000` |
| **数字型长数字（≥16 位，如身份证）** | 末尾被 Excel 静默改写（Excel 数字仅 15 位有效数字） | **阻断该行并说明原因**，附上被改写后的值，要求把该列设为「文本」后重填或用 `-` 占位。不能只提示——否则会把错的身份证号存进系统 |
| 全角字母/数字/空格（登录名、身份证、权限点） | 原样 | 标识类字段做全角转半角 + 去掉全部空白；权限点做半角化后再按分隔符拆分（全角逗号"、"也能拆） |
| BOM / 零宽空格 / 换行 / 全角括号（表头） | 匹配失败 | 表头归一化时清除不可见字符与分隔符号，「\ufeff单位名称\n（必填）」仍可匹配 |
| XML 非法控制字符（`\x00`、`\x07`，CSV 常见） | 污染入库数据 | 取值时清除（保留 `\t` `\n` `\r`，描述的多行文本不受影响） |
| **公式且未保存计算结果** | `data_only` 读出来是空 | 用第二遍 `data_only=False` 加载比对，精确定位坐标：必填列 → 阻断并说明"请先用 Excel/WPS 打开另存"；非必填列 → 提示后按空处理。有缓存值的公式不会误报（见 §11 单元测试） |
| 首尾空白（含全角空格 U+3000） | 原样 | 统一 trim |
| 超长文本（数千字） | — | 原样保留，不截断 |
| `bytes` / `nan` / `inf` 等异常类型 | 可能抛异常 | 统一转字符串，不抛异常 |
| CSV 字段内含逗号 | 被错切列 | 标准 CSV 引号规则已支持（`"a,b"`）；模板说明中提示含逗号时加双引号 |
| CSV 引号内换行 | — | 标准库 csv 正确处理，描述保留换行 |

### 10.3 已知限制（不改，但写清楚）

- **表头必须是单行**：两行表头（如第一行分组、第二行字段）不支持，请合并成一行。合并的**多行**表头中，第二行的内容会被当成数据行。
- **前导零无法挽救**：`00123` 若被 Excel 存为数字，取到的就是 `123`。这是 Excel 的存储行为，系统无法还原；预览里的"对象"列会显示实际登录名，可据此发现。解决方案是把该列设为文本格式。
- **`.xls`（旧版二进制）不支持**，明确提示另存为 `.xlsx` / `.csv`。
- **`.xlsm` 按 xlsx 读取**（宏不保留、不执行）。
- **导入值全部按文本入库**，不做数字/日期语义转换（描述字段写"2026-09-11"就是字符串）。
