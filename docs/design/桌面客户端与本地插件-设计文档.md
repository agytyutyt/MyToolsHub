## 0. 一页速览

1. **拓扑（现状）**：远程主包是业务权威（类 A 插件、鉴权、数据、统一大模型配置）；桌面客户端为**单进程**——壳（pywebview 窗口 + pystray 托盘，主线程）+ 客户端能力层（本地 Flask+waitress，后台线程，127.0.0.1 随机端口）+ 内置 Python 运行时（`runtime\python`，worker 子进程解释器）；类 B/C 插件由能力层承载，类 A 页面/API 经中继透传。
2. **路由只有一份裁决**：`client/capability_app.py` 装配时按「本地直出 / 商店前端包直出 / 清单合并 / 本地插件 API / 中继远程 / 客户端自有接口（永不中继）」六类分区（§1.2），业务逻辑禁入此层。
3. **存量插件三类已定稿**：A×6 / B×8（B-light×5 + B-heavy×3）/ C×3（§2.1）；本地包一律由出包工具从服务器插件源码**派生**（单一真源），C 类客户端工件新写于 `client-plugins/local-<id>/`。
4. **本地插件契约**（《插件设计规范.md》§16 为权威）：`runtime:"local"` + `kind`（local/hybrid）+ `entry{frontend,backend,mount}` + `server_data`/`resident`/`timeout_ms`/`idle_ttl`；装包走 pkg_install 六连校验。
5. **宿主内核同源双包**：T06 冻结清单（正面 `jz_deps`/`jz_api`/`jztools_data` + `jz_plugin_host`，禁带业务插件/admin/`jz_llm`/数据根），客户端 spec 与主包 spec 各自组装（§4.1）。
6. **程序 / 内核 / 组件三分件**：程序包（exe+`_internal`+static）、内核包（`runtime\webview2`）、组件包（`runtime\pylibs`）+ 插件 worker 运行时（`runtime\python`）独立分发，程序更新不触碰 `runtime\` 子树（§4.2）。
7. **fixed 内核为占位状态**：构建配置版本号仍是占位符，部署目录只有 `KERNEL_MARKER`（无 `msedgewebview2.exe`），壳恒回落系统常青内核；取包/裁剪/分件与目标机装载脚本已就绪（`tools/client/build-webview2-kernel.py` + `install.ps1`），版本定版待拍板（§4.3，遗留）。
8. **商店=主包第二核心插件（随包）**：`store` 读面 + admin 商店管理写面 + `数据根\store\` 数据契约；客户端经 `/local-api/store/*` 拉包安装，生命周期主入口在商店页（§5）。

## 1. 三层拓扑与路由分区

### 1.1 拓扑（现状）

```
远程服务器（业务权威：类 A 插件、admin/鉴权、数据、统一大模型配置；主包 Flask+waitress）
   ▲ HTTP 中继（纯 REST，无 WS/SSE；上传 spool 临时文件按确切 CL 转发、响应流式回传）
   │
桌面客户端进程（单进程，内嵌 Python 运行时）
├─ 壳 / UI 层：pywebview 窗口（WebView2，占主线程）+ pystray 托盘（后台线程）
├─ 客户端能力层：Flask+waitress（后台线程，127.0.0.1 随机端口，threads=8）——
│    路由分区 + 会话镜像/中继 + 本地插件注册表 + 类 B/C 承载 + 客户端自有接口
├─ 内置 Python 运行时：runtime\python（embeddable cp314 + Flask 栈）——worker 子进程解释器
└─ 子进程（按需）：类 B worker（stdio-json；超时即杀 / resident 常驻 / idle_ttl 空闲回收）
```

与 GLM 原三层口径（UI 层 / 能力层 / 运行时）的对应：壳=UI 层，能力层=本地服务线程组，运行时=内嵌 Python。能力层与主包**同构**：类 C hybrid 走进程内 `register(app)` 子应用，类 B 走子进程 worker——插件开发模型与服务器插件一致（§3）。

启动序列（`client/client_main.py:109-188`）：单实例互斥（`client/single_instance.py`，命名 mutex）→ 读构建配置（`tools/client/client-build-config.json`，单源）/ 客户端配置（`%LOCALAPPDATA%\JZClient\config.json`）→ 解析远程地址 → `JZTOOLS_DATA_ROOT` 指向客户端数据根 → 起 waitress（后台线程）→ `webview.start()` 占主线程。`--stop`（带镜像名校验防误杀）与 `--await-pid`（重启接棒）为运维/自升级入口。

### 1.2 路由分区表（能力层唯一流量裁决，`client/capability_app.py`）

| 请求 | 处置 | 落点 |
| --- | --- | --- |
| `/local-api/*` | **客户端自有接口，永不中继**：配置/健康/本地插件管理/商店 preflight·install·download | `capability_app.py:239-266/370-548/594-1049` |
| `/`、`/tool/<id>`、`/local-admin`、`/plugin/local-*/…` | **本地直出**（客户端自带 static 副本、本地插件前端）；页面导航受匿名探针门控（`GET /login`，2s 超时、5s 缓存），远程挂死→兜底页 503 | `capability_app.py:207-230/271-309` |

### 1.3 壳契约（`client/shell_window.py`）

- **窗口**：最小 720×560（`:24`）；几何记忆 300ms 防抖落盘 + 启动屏幕内钳制（最小化上报的异常尺寸/离屏坐标不落盘，`:68-99/196-216`）。
- **关窗=隐藏到托盘**（GD5）：`closing` 返回 False 取消关闭（`:170-172`），首次关窗气泡一次；托盘菜单 4 项——刷新页面 / 打开窗口 / 本地插件管理 / 退出（2026-10-11 二次调整：浏览器/后台入口移除，后台入口仅服务器端文档标注）。
- **导航锁定**：仅放行 127.0.0.1，外链转系统浏览器；`loaded` 守卫兜底 JS 跳转漂移；WebView2 profile（`storage_path` + `private_mode=False`）落客户端数据目录，会话跨重启持久（`:139-144/178-193/269-274`）。
- **桥**：`window.jzShell`（`version`/`engine`/`openExternal` 三项）+ `html.jz-shell` 结构类（`static/js/shell-bridge.js`）；浏览器路径判空无感（红线 2），但 A 类 iframe 内页面桌面专属操作须自判（规范 L-16）。

## 2. 存量插件三类（A / B / C）

### 2.1 分类总表（2026-10-06 定稿，逐插件取证；明细 → `存量插件三类适配-设计文档.md` §1.2）

| 类别 | 成员（6/5/3/3） | 承载方式 | 商店条目 | 适配模式 |
| --- | --- | --- | --- | --- |
| **类 A** 服务器插件 | admin、store（核心）；knowledge-base、shared-docs、notice-board、case-report | 逻辑在服务器；页面中继直出（可装前端包本地直出）；离线不可用 | admin/store 不进商店；其余 server 双工件 | M-A 原样双包（零代码改动） |
| **类 B-light** 纯前端 | base64、color-picker、json-formatter、md5-generator、map-marker | 客户端本地直出，无后端；离线完全可用 | local 单包 | M-B1 派生（零源码改动） |
| **类 B-heavy** worker | info-transfer、trajectory-convert、qr-video-decode | 本地直出 + 源码包子进程 worker（重依赖走组件包）；离线完全可用 | local 单包 + 依赖 | M-B2 派生（源码零改动 + manifest 变体 + 懒加载/任务态外置） |
| **类 C** 混合 | file-filter、trajectory-sketch、character-graph | 本地直出 + 本地简单逻辑（hybrid/hybrid-worker）；复杂/敏感操作经 `jz_relay.own()` 交服务器工件；离线降级可用 | server 双工件 + local 客户端工件 | M-C 双包拆分 |

分类判据（按序问、命中即停）：① 承载服务器数据权威 → A；② 零服务器交互 → B（有后端=worker，纯前端=B-light）；③ 其余 → C（计算本地化、密钥/共享状态留服务器）。核心插件例外：admin/store 落 A 但走 `CORE_PLUGINS` 白名单随主体分发（可单独升级、不可卸载、不进商店目录）。

### 2.2 三类 manifest 要点（字段权威 → 《插件设计规范.md》§16.1）

| 类别 | manifest 判定字段 | 要点 |
| --- | --- | --- |
| A | 无 `runtime` 字段 | 服务器 `plugins/<id>/`；出包链自动产前端包工件（同版本成对） |
| B-light | `runtime:"local"` + `kind:"local"`，无 `entry.backend` | 纯前端；派生时 `--api-rewrite` 空转无害 |
| B-heavy | `runtime:"local"` + `kind:"local"` + `entry.backend` | backend 为末段文件名（如 `routes.py`）；`resident:true` + `timeout_ms`（长任务）；重依赖须懒加载（L-14）+ 任务态外置后按需 `idle_ttl` |
| C | `runtime:"local"` + `kind:"hybrid"` + `entry.mount`（`/api/local/<id>` 开头）+ `server_data:true` | 服务器工件取同 id 去 `local-` 前缀，API 型无页面；前端复用 `plugins/<id>/frontend/`（`-FrontendFrom`） |

四条通用改造模式（M-A/M-B1/M-B2/M-C）与逐插件端点拆分见 `存量插件三类适配-设计文档.md` §2–§3；前端 API 基址差异由出包工具**构建期改写**承担（`--api-rewrite`），书写纪律 = 规范 §16.10 **L-13**（硬性，违反即出包红）。

## 3. 本地插件契约

### 3.1 包与 manifest 校验（装包六连，`client/pkg_install.py:69-129`）

zip 完整性 / 路径安全（防 `../`）/ manifest 可解析 / `runtime=local` + `kind∈{local,hybrid}` + `id` 以 `local-` 前缀（`^local-[A-Za-z0-9_-]+$`）/ `mount` 冲突检查（双方非空才比）/ 前端文件存在（hybrid 另须 backend 存在）。升级=整目录覆盖替换；服务端 `frontend-manifest.json`（`install_frontend_zip`，`:165-220`）与依赖组件包 `.pending` 语义（`install_component_zip`，`:280-337`，纯 Python 立即应用 / DLL 下次启动）各走单入口。

### 3.2 挂载与派发（`client/capability_app.py:317-366`）

- 显式 `entry.mount` 优先，未声明则剥规范前缀 `/api/local/<id>`；查询串随派发透传。
- **hybrid（类 C）**：每个插件独立 Flask 子应用，装卸/升级=字典操作——Flask 2.3+ 禁止首请求后 `register_blueprint`，故用**子应用派发**（`test_client`）实现真热插拔（L1/L2/L3）；`bp` 或 `register(app)` 双形态兼容（`client/plugin_host.py:33-48` 同款）。
- **worker（类 B-heavy）**：`executor.call()` → stdio-json-v1 往返（`client/plugin_executor.py:202-232`）；响应体上限 8MB（L-3，超限 502 提示写临时文件）。
- 依赖三态判定（`jz_deps`）：`blocked` → 503 + 缺失清单；缺失组件包经 `jz_plugin_host.setup_dep_components` 注入 `runtime\pylibs`（装完即生效）。

### 3.3 worker 生命周期与热插拔（`client/plugin_executor.py`）

| 语义 | 实现 |
| --- | --- |
| 拉起 | 默认「用完退出」；`resident:true` 常驻复用；`.exe` 走例外通道（同协议） |
| 超时/崩溃 | `timeout_ms` 超时即杀 → 504；崩溃 → 502 + 自动拉起（常驻表弹出，不炸页面） |
| 空闲回收（F6） | `idle_ttl`（秒）>0 时收割线程干净收回（下次请求静默重启，不弹崩溃）；**前置=任务态已外置 `.task_cache`**（L-14 续） |
| 审计与日志 | `plugin-audit.log`（插件 id/真实登录身份/耗时/结果）；stderr 归 `plugin-logs/<id>.log`；`CREATE_NO_WINDOW` 防黑窗 |
| 隔离 | 进程级（依赖/崩溃全隔离）；类 C 升级=能力层秒级重启（会话镜像 DPAPI 持久化免重登，`/local-api/restart` 新实例 `--await-pid` 接棒） |

### 3.4 `jz_relay` 门面与安全边界（`client/jz_relay.py` + `client/relay_whitelist.json`）

- 类 C 访问服务器数据的**唯一通道**：`import jz_relay`（能力层注册 `sys.modules`）；`get/post` 自动附镜像会话（DPAPI 加密落盘，仅会话 Cookie，凭据不落盘）。
- 白名单现值 = 框架级只读面：`GET /api/tools*`、`GET /api/org/tree`；`/api/llm/` 预留（主包无 HTTP 推理面）。`own(<自身 id>)` 走 `own_namespace`：仅自身插件服务器端点（id 去 `local-` 前缀），其他插件端点仍 `RelayError`（跨插件禁调用铁律）。
- `server_data:true` 安装时明示数据出机；类 B 不上传用户数据；Key 不落本机；身份注入（F1）= hybrid 走 `jz_api.register_providers`、worker 走本地回环 `X-JZ-User` 头（免签名，不进中继/服务器链路）。

## 4. 客户端能力层与宿主内核

### 4.0 壳身份与接入密钥（2026-10-11 需求①，权威落点）

客户端对服务器的**全部请求**（中继 `client_headers` / `jz_relay` / 商店源三链收口）附加 `X-JZ-Shell: <接入密钥>`；密钥解析=客户端配置 `remote_token` → 构建配置 `server.default_token` → 未配置。服务器壳身份门（`jz_host/shell_gate.py`）凭它放行业务面，管理面浏览器照常。配套：本地端口壳自证（`/shell-boot?_shell=<run token>` 种 Cookie，业务路由全要求；run token 经自重启环境变量传新实例）、兜底页升级「连接设置」（地址+密钥，`/connection`）、托盘浏览器/后台入口整体移除（**二次调整 2026-10-11：管理后台入口不对用户展示**，只标注在服务器端文档）、壳门 403（`X-JZ-Gate: shell_required`）给密钥指引横幅不进会话失效分支（页面与 JSON 契约均不露 /admin）。契约与逐卡证据 → `plan/20261011浏览器退役与商店分发口径改造-TODO（面向执行模型）.md` §2.2。

### 4.0.1 账号上下文与数据隔离（2026-10-11 账号级安装批次，已实施）

客户端引入**进程级账号上下文**（单实例互斥保证同一时刻只有一个登录账号，`client/single_instance.py`）：

- **账号同步**：登录/续期（`/api/session` 回包）缓存 `username` 并拉取账号安装登记（`GET /plugin/store/api/installs`，60s TTL）；登出/401（会话镜像清空信号）清空——数据根切 `users/_anonymous`、停常驻 worker，网格空 + 登录引导（快照保留不展示）。
- **离线快照**：账号 + 登记全量落 `<客户端数据目录>\account-state.json`；启动时按快照恢复显示与数据根（断网可用），联网后刷新覆盖。
- **数据根注入（对插件零感知，D5 阶段一）**：插件可见数据根 = `<客户端数据目录>\users\<账号>\`（目录名 `quote(username, safe='')` 防穿越，D20）；能力层在账号确定/变化时改写 `JZTOOLS_DATA_ROOT`（`jztools_data` 每次现读即时生效）并重挂 hybrid 子应用；worker 由执行器 spawn 时显式注入同款 env + 切号停常驻（`PluginExecutor.stop_residents`）。能力层自有文件（session.bin/config.json/downloads/local-plugins/server-frontends 等）保持机器级。
- **网格合成与可用性门**：`/api/tools` 以账号登记为显示全集（登记 ∧ 账号 enabled ∧ 本机副本在 ∧ A 类在服务器可见清单）；登记而副本缺 → 云卡（灰蒙版 + 「从云端下载」，main.js）；未登记插件的本机资源（`/tool/<id>`、`/plugin/<id>/*`、`/plugin/local-*`、`/api/local/*`）一律 404「未安装」（D7，服务器中继面不拦）；旧服务器（installs API 404）降级机器级行为（G2-7）。
- **升级迁移**：遗留 `<数据目录>\plugins\` 数据 move 给首个登录账号（`.legacy-migrated` 幂等标记）；登记补种=本机 local-plugins/* + server-frontends/*（尊重 hidden_tools，`.legacy-seeded` 一次性，消费后清 hidden 键）。

逐卡设计与决策 D1–D22 → `plan/20261011账号级插件安装与本地数据隔离-TODO（面向执行模型）.md`；台架 → `tools/e2e/account-store-tests.py`。

## 5. 插件商店（随主包 store + 生命周期）

- **形态**：商店 = **主包第二核心插件**（`plugins/store/`，随包；`CORE_PLUGINS=["admin","store"]`，`tools/verify-package.py:35-36/151-157` 断言「主包 plugins/ 仅含核心插件」）。写面=admin 商店管理页（上架/下架/审核/统计），读面=store 只读 API + 页面 + 下载；两插件唯一交互面是 `数据根\store\` 数据契约（catalog.json/packages/stats.jsonl，单一写方；权威定义 → `桌面端插件商店-设计文档.md` §3.4/§4.1）。
- **客户端安装闭环**（`client/capability_app.py:594-949`）：商店页（经中继直出）→ `/local-api/store/preflight`（依赖三态预检 + 缺依赖映射可装依赖包）→ `/local-api/store/install`（能力层独立取 catalog、拉包、sha256 必校验 → `pkg_install` 单入口 → 落位）→ rescan 热插拔。安装按 runtime 分派：`local`=完整本地插件、`server`=前端包落 `server-frontends\`（页面本地直出、API 照旧中继）、`dep-slot`=依赖组件包。
- **更新源抽象**（`client/plugin_source.py`）：`ServerSource`（默认，商店 API）与 `ShareSource`（共享盘 index.json 兜底），客户端配置免重启切换；catalog schema 2 与共享盘 index.json 同构。
- **生命周期**（下载 / 安装 / 升级 / 停用 / 卸载）：停用=只置 `local_state`（包与数据保留，本地 API 404、网格隐藏）；卸载=删包目录（数据默认保留；server 条目另记本机 `hidden_tools`，被动回退中继直出）；升级=覆盖替换（worker 即时；hybrid 走秒级重启口径）。语义矩阵 → 商店设计文档 §3.5/§3.5.1。
