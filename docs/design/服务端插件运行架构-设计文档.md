## 1. 拍板历程与威胁模型（决策留痕）

**三轮收敛（2026-10-05，完整论证见对话留痕）**：

| 轮次 | 方案 | 结论 |
| --- | --- | --- |
| ① | 进程内 register(app)（初评推荐：部署链/鉴权/mount 全现成） | **否决**——无进程隔离，插件崩溃连坐主应用不可接受（需求⑩前提） |
| ② | D 主应用内嵌执行器（子进程，客户端 executor 移植） | **否决**——崩溃隔离达成，但生命周期/部署/熔断全长在主应用，主应用自升级仍靠 `--wait-restart` 自举 |
| ③ | **E 管理进程 + 并列进程（定稿）** | 业界 supervisor 形态（systemd/supervisord 同构；参照架构 dsh「壳管理本地服务」同款）；生命周期外置，主应用自身也成受管对象 |

**威胁模型校准**（为什么隔离是必要的）：Python 层异常 Flask 可接住（单请求 500、进程存活）；真正连坐主应用的是 **native 段错误（cv2/numpy 级）、OOM、失控循环拖死线程池、模块级状态污染**——Python 进程内对前两类无任何可靠隔离手段，这是进程隔离的根本理由，不是工程偏好。

**前提事实**：会话为签名 Cookie 且 `SECRET_KEY` 持久化于配置（`routes.py:974`）→ **重启不掉登录**；重启的真实代价 = 秒级窗口 + 在途请求被打断。

## 2. E 架构总图与 supervisor 契约

```
supervisor（轻量 Python：stdlib+psutil，不 import 任何重库；Windows 服务化=NSSM/最小包装）
├─ 受管① 主应用（主包 Flask+waitress）——唯一 HTTP 入口
├─ 受管②…⑩ 插件后端包 worker（每插件一个自有 Flask 实例进程，register(app) 契约保留）
└─ 职责：启动编排 / 健康探针 / 崩溃拉起+熔断（连续 N 次失败自动下线+告警）/
        升级=停旧→替换→健康→起新（失败回滚） / 停用清理 / 孤儿收割（Job Object） / 日志归集
```

- **受管单元**：主应用与全部 server 后端包 worker 并列注册；单元描述=名称/启动命令/健康探针 URL/重启策略/依赖环境（shared 或 venv 路径）。
- **控制接口**：主应用 → supervisor，localhost + 独立令牌（或命名管道 ACL）；动作=`status / start / stop / restart / apply(包) / rollback(单元)`；admin 商店管理页的部署运行面板是该接口的薄客户端。
- **升级编排**：停旧 → 替换（复用 inspect/apply 校验+备份逻辑）→ 健康探针 → 起新；失败自动回滚到备份并告警。**主应用升级同口径**（supervisor 编排，插件 worker 存活）。
- **熔断**：连续 N 次（建议 3）崩溃/健康失败 → 单元下线（主应用对失败插件兜底 503），告警 + 管理页可见，人工/管理页恢复。
- **孤儿收割**：子进程纳入 supervisor 的 Job Object（kill-on-close）；supervisor 由服务管理器拉起，自身升级最后执行。
- **服务化**：NSSM 或 pywin32 最小包装注册为 Windows 服务；注意服务账户的共享盘映射等环境差异。

## 3. 身份与通信

- **反代拓扑**：客户端/浏览器 → 主应用（鉴权管线：admin 鉴权门照常）→ 主应用反代 → worker（端口仅绑 127.0.0.1）。
- **身份 = 共享 `SECRET_KEY` + Cookie 原样透传 + worker 会话自验**：worker 侧实现「会话自验版 session_user provider」（验签名 Cookie 得身份）——业务插件经 `jz_api.get_session_user()` **零改动**（实测 `session` 直摸仅 admin 一家，身份读取已收敛 `jz_api` 门面——解耦设计 FC-3/K-3 的现成红利）。滑动续期（`session["last_active"]`）经反代 Set-Cookie 回传，照常生效。
- **R2 简化**：共享密钥不扩大信任面（进程内插件本就读得到 SECRET_KEY，同信任域）；自建签名信任头方案废弃，降级为「端口绑定 + 会话自验」。
- **Flask 上下文盘点**：

| 上下文成员 | 本项目实际用途 | E 形态下 |
| --- | --- | --- |
| `request` | 全部插件的数据入口 | 原样可用（worker 自有 Flask 收到转发请求） |
| `session` | 仅 admin 直摸；业务插件走 `jz_api` | 原样可用（共享密钥 + Cookie 透传） |
| 主应用级 `before_request` | admin 鉴权门 | 留主应用；worker 自验会话兜底 |
| `g` / `current_app` / `config` | 插件内少用 | worker 复制同一份配置 |
| `url_for` / 模板 | 前端零硬编码 origin 纪律 | 无损 |
| `jz_api` / `jz_deps` / `jztools_data` / `jz_llm` | 框架门面与数据根约定 | 前三者随包可 import；**`jz_llm` 接入为唯一适配工作项**（provider 注入或经主应用 /api/llm 中转） |

- **契约固化**：插件规范增补「禁用主应用全局钩子/全局单例，一切经 register(app) 收到的 app + jz_api」；构建期扫描直摸 `session`/`current_app` 的写法（C 系检查扩展）。

## 4. 依赖与 venv（拍板口径）

- **默认共享运行时**：主包解释器 + `runtime/pylibs` 共享槽 + 内核库（与现状同构）。
- **venv = 可选项**：要求特殊依赖版本的插件允许 venv 拉起（worker 以 `venv\Scripts\python.exe` 启动，supervisor 按单元描述指定解释器），**商店目录条目标注**（catalog 条目 `deps_mode: shared|venv`）。后端包上架时携带依赖 wheel 清单，部署时 `pip --no-index --find-links` 离线建环境（机器校验含依赖闭包完整性 + wheel tag 预检——O1 文档同款设计）。
- **venv 不是沙箱**：隔离版本、不隔离行为；行为防线 = 审核 + 鉴权管线。
- **与客户端 O1 slots 的分化**：服务器求官方标准（磁盘宽裕、进程已隔离），客户端求省盘（embeddable + `.slots`，已拍板零内核改动）；`requires` 三态判定两端共用。
- **注意**：Python 基线升级 = 全部 venv 重建（策略：解释器基线随主包，venv 随包重建）；venv 不改善 import 冷启动（0.5–2s）。

## 5. 热插拔语义（按形态，插件改造选型参考）

| 形态 | 装载/卸载/停用 | 升级生效 |
| --- | --- | --- |
| 服务器后端包（E：独立 worker 进程） | supervisor 启停，**热**（主应用与其余插件零影响） | supervisor 停该 worker→替换→健康探针→起新版；**该插件秒级窗口，其余零影响**；纯前端变更本就热（静态每请求伺服） |
| 服务器既有进程内插件（16 插件迁移前现状） | 需重启 | 优雅重启（`--wait-restart` 页内自重启现成 `app.py:1159`；`requires_restart` 构建期自动判定，纯前端 `-Hot` 不停服——升级方案 §5.2/§5.7） |
| 客户端类 B（worker） | 全热（L1/L2 即时） | 全热（L3：按需 spawn/常驻收割，T20） |
| 客户端类 C 客户端工件（hybrid） | 装卸/停用即时（子应用派发） | 能力层秒级重启（会话镜像持久化免重登；模块级 reload 不可靠、不做） |
| 客户端类 A 前端包 | 即时（本地伺服路由开关） | 即时（装新版即生效） |

## 6. 16 插件改造影响与主应用兜底

- **E 形态 worker 保留 register(app)（自有 Flask 实例）**：业务插件零改动（身份已收敛 jz_api）；`jz_llm` 接入点适配一项。改造形态分配（转 B/A/C）与热插拔语义（§5）联动：高频迭代轻逻辑放客户端工件（热/秒级），稳定重逻辑放服务器后端包（supervisor 替换，秒级窗口）。
- **主应用兜底责任（现状缺失，列为补课项）**：统一 errorhandler——插件异常 → 该插件 503 + 其余照常（与进程隔离互补：native 崩溃/OOM 由进程边界隔离，Python 异常由 errorhandler 兜底）；熔断下线 + supervisor 自动拉起。
- **懒启动（可选策略）**：worker 首请求拉起 + 空闲回收，轻插件不常驻；venv 不改善 import 冷启动，取舍留运维。
