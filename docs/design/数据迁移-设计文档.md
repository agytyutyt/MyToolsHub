## 1. 需求与概述

| # | 需求 | 实现要点 |
| --- | --- | --- |
| 1 | 为后台管理模块添加**数据迁移**功能：对当前已安装插件进行数据**导出 / 导入** | 后台新增「数据迁移」页（仅超级管理员）+ `/api/admin/migrate/*` |
| 2 | 导出的数据**按插件分类、打包、保存** | 包内布局 `plugins/<插件id>/…`，一个插件一段；另有框架三段（账号 / 大模型 / 工具注册） |
| 3 | 为用户数据**添加加密功能**，防止直接读取数据包后获得用户 LLM 的 Key | ① 整包口令加密（无口令连文件名都读不到）；② 账号/大模型配置里的密文字段**改封**为口令信封；③ 机器密钥 `config/.admin_key` 永不进包 |

### 1.1 为什么不能"直接拷数据根目录"

| 直接拷贝的问题 | 本功能的做法 |
| --- | --- |
| 容易漏：漏了 `config/` 就丢了账号与权限，漏了 `prompt.json` 就丢了大模型提示词 | 分段盘点 + 一键打包（默认全选），漏不了 |
| 容易多带：`logs/`（访问日志）、`.task_cache/`（任务缓存）、`backups/`（插件包备份） | 打包排除易变与本机状态文件（§3.2） |
| **换了机器解不开**：账号里的密码哈希、身份证、用户/全局 LLM Key 都是用**本机密钥**加密的 | 导出时改封为口令信封，导入时改封为目标机密钥（§2.2） |
| **明文泄漏**：数据包直接可读 → LLM Key、案件数据一览无余 | 整包口令加密（§2.1） |

## 2. 加密与改封口径（本功能的核心）

### 2.1 整包加密（口令容器）

`.jzdata` 文件 = 二进制容器：

```
magic "JZDATA1\0"   8 B     便于识别"这不是普通 zip"，并给出可读报错
迭代次数            4 B     大端；写在包头便于以后提高强度
盐                  16 B    随机；与口令一起派生密钥
密文                …       Fernet(zip 字节)（AES-CBC + HMAC，认证加密）
```

- 口令经 **PBKDF2-HMAC-SHA256**（200,000 次迭代）派生**两把**子密钥：整包密钥、字段信封密钥
  （同口令、不同 `info` 域分离，互不通用）；
- 认证加密：口令错误或包被篡改 → 解密直接失败并给可读提示，**不会解出半截数据**；
- 口令策略：**至少 8 位**；界面上明确"这是打开数据包的唯一凭据，遗失后无法恢复"（不做找回，也不落盘）。

### 2.2 字段信封（跨机器可用 + 多一层保护）

账号数据（`config/admin.json`）与大模型配置（`config/llm.json`）里的敏感字段本来就用
**本机密钥** `config/.admin_key` 加密。若原样打包会有两个问题：

1. **换机器导入后解不开**——新机器密钥不同，用户密码、身份证、LLM Key 全成乱码
   （admin 的 `decrypt_field` 对解不开的值"原样返回"，表现为登录永远失败）；
2. **少一层保护**——口令一旦泄露，拿到包的人只需再拿到 `config/.admin_key` 就能读出 Key。

所以：

```
导出：能用**本机密钥**解开的字符串  →  用**口令信封密钥**重新加密，加前缀 "JZMIG1:"
导入：带 "JZMIG1:" 前缀的字符串      →  用**口令信封密钥**解出明文 → 用**目标机密钥**重新加密
```

**识别"哪些字段是密文"不靠字段清单，而是"能否用本机密钥解开"**（`_try_local_decrypt`）。
这样将来任何新增的密钥字段——包括插件自己用 `jz_llm.encrypt_secret()` 加密的配置——都自动被覆盖，
不需要维护一份一定会漏的清单。字段清单法在这个仓里已经吃过亏：插件配置里至今还留着历史明文
LLM Key（统一大模型落地前的旧数据），清单法根本列不全。

不变量：**`config/.admin_key` 永不进包**，导入也不改写目标机的密钥文件（单测钉住）。

> ⚠ 字段信封密钥与容器的盐绑定（同口令 + 同盐才派生同一把）。因此
> `encrypt_container()` 只能用于**新建**包；拿它重封一个已含字段信封的包会让那些字段解不开
> （会报"口令与包不匹配"）。换口令重打包请用 `build_package()`。

### 2.3 体积与条目上限

| 项 | 上限 | 说明 |
| --- | --- | --- |
| 导出包体积 | 300 MB | 与插件包 PU-3 同口径；超限给可读提示 |
| 解压后总量 | 1 GB | 防 zip 炸弹 |
| 条目数 | 50,000 | 插件数据是"一记录一文件"，上限放宽但仍设防 |

## 3. 包结构与分段

### 3.1 布局（解开容器后的 zip）

```
manifest.json            清单：格式版本 / 来源机器 / 导出时间 / 程序版本 / 各段文件数与体积与密钥数
config/admin.json        账号与权限数据（单位/部门/人员/角色；敏感字段已改封为口令信封）
config/llm.json          统一大模型全局配置（同上）
config/tools.json        工具启停 / 排序 / 可见性
plugins/<插件id>/…       各插件的运行数据（config.json / prompt.json / data/…）
```

段 id：`accounts` / `llm` / `tools` / `plugin:<插件id>`。导出与导入都以**段**为勾选粒度。

### 3.2 打包排除项（不进包）

| 类别 | 具体 | 为什么 |
| --- | --- | --- |
| 机器密钥 | `config/.admin_key` | 安全底线（见 §2.2） |
| 本机状态 | `config/.app_state.json` | 模板指纹与插件版本登记；带过去会**压制目标机的配置模板同步** |
| 可重建 | `config/installed-deps.json` | 构建期生成 |
| 易变/缓存 | `.task_cache/`、`out/`、`__pycache__/`、`*.tmp`、`*.bak*`、`*.pyc`、`*.log` | 无价值、体积大、可能含中间产物 |
| 全局目录 | `logs/`、`.staging/`、`backups/` | 日志与运行态，不属于"用户数据" |

> 与 `tools/plugin-payload-rules.json`（插件包）的排除规则**同精神但不同清单**：那条链路要排除
> 含 API Key 的运行时 `config.json`，而迁移**必须带上**插件配置（保留字段名单、提示词等就是用户数据）。

### 3.3 已安装插件的判定

- 以**程序目录** `plugins/<id>/manifest.json` 为准（这才是"已安装"）；
- 数据根里仍有数据的插件（如已卸载但数据留着）也会列出并标注"插件未安装"，避免用户以为数据"不见了"；
- 段名（中文）在导出时写进清单，让包**自描述**；导入预览优先显示**本机** tools.json 的称呼（权威）。

## 4. HTTP 接口清单

全部**仅超级管理员**（与数据目录 / 插件管理同一档：可覆盖全部数据，风险最高）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/admin/migrate` | 数据迁移页（非超管 302 回后台首页） |
| GET | `/api/admin/migrate/plan` | 导出前盘点：可导出分段 + 体积 + 数据根 + 程序版本 |
| POST | `/api/admin/migrate/export` | `{passphrase, sections[]}` → 直接下载 `.jzdata`（口令太短 / 空选段 → 400） |
| POST | `/api/admin/migrate/inspect` | 上传包 + 口令 → 解密校验 + 预览（**不写数据**），返回一次性 `token` |
| POST | `/api/admin/migrate/import` | `{token, sections[]}` → 写入数据根（覆盖前备份），返回结果报告 |

两步导入的衔接：**口令派生的信封密钥只在服务端内存里活 30 分钟**（`_MIGRATE_STAGE`，按 token 索引），
所以"解析预览 → 确认导入"之间不必让管理员重复输入口令；密钥材料**不回传前端**，
服务重启则该 token 失效（重新解析即可，包还在本地）。上传的包落在 `<数据根>/.staging/migrate/`，
导入完成后立即删除（包本身已加密，落盘不泄漏）。

### 4.1 导入的写入规则

| 规则 | 说明 |
| --- | --- |
| 白名单 | 只允许 `config/<框架三者>` 与 `plugins/<已声明插件id>/…`；拒绝绝对路径、盘符、`..`、含冒号（与插件包同一套 zip 安全口径） |
| 只写勾选段 | 未勾选段的条目一律跳过（计数进 `skipped`） |
| 幂等 | 目标文件内容与包内一致 → 跳过（不写、不备份） |
| 覆盖前备份 | 被覆盖的文件先复制到 `<数据根>/backups/migrate/<时间戳>/<原相对路径>`，只保留最近 3 份 |
| 原子写 | 先写 `.tmp` 再 `os.replace` |
| 不碰密钥 | 不改写 `config/.admin_key` |

## 5. 界面（`/admin/migrate`）

**导出卡**：分段勾选（框架三段 + 各插件，标注版本 / 文件数 / 体积 / `plugins/<id>/` 路径）→
两次输入口令 → 「导出并下载」→ 结果区提示包名、体积与"请牢记口令"。

**导入卡**：选择 `.jzdata` + 口令 → 「解析预览」（显示来源机器 / 导出时间 / 程序版本 / 各段摘要，
并标注"将覆盖 N 个文件""含 N 处密钥"）→ 勾选段 → 「确认导入」（二次确认）→ 结果报告：
写入/跳过文件数、备份目录、涉及插件，并在导入账号数据后提示"当前登录账号可能失效"、
导入工具注册表后提示"需重启服务后完全生效"。

界面细节：导出走 `fetch` + `Blob` 下载（不能走 `AdminCommon.api`，它按 JSON 解析）；
文件名优先取 RFC 5987 的 `filename*=UTF-8''…`（中文名在这里），退回 ASCII 的 `filename=`。

## 7. 安全清单

| 项 | 措施 |
| --- | --- |
| 传输/落盘 | 包整包口令加密；上传暂存目录里的也是密文；导入后立即删除暂存 |
| 密钥材料 | `config/.admin_key` 永不进包；信封密钥只在内存活 30 分钟、不回传前端 |
| 越权 | 全部接口仅超级管理员；页面非超管 302 |
| 路径穿越 | 逐条白名单校验（与插件包同一套规则） |
| 误操作 | 覆盖前备份（留最近 3 份）；预览与导入两步分离；导入前二次确认；账号段单独警示 |
| 暴力破解 | PBKDF2 20 万次迭代；迭代次数写在包头（可随硬件提升） |
| 包损坏/伪造 | 认证加密 + 清单格式校验（`format`/`schema`），不认的包直接拒绝 |

## 8. 遗留与后续

| 项 | 说明 |
| --- | --- |
| 口令找回 | 刻意不做：口令即凭据，找回机制会削弱它。界面上明确提示"遗失无法恢复" |
| 增量/差异迁移 | 现在是整段覆盖。若将来数据量大到 300 MB 上限吃紧，可加"按插件增量（只导变化文件）" |
| 定时自动备份 | 现在是手动导出。可做成"每周自动导出到指定目录"（需要口令托管策略，属策略问题） |
| 日志与任务缓存 | 刻意不进包；若确实要迁移访问日志，单独提供"日志归档"功能更合适 |
| 跨版本兼容 | 包带 `schema`；将来结构变更时递增并给出"请用同版本或更新的程序"提示（已有该分支） |
