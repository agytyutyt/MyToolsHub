## 0. 结论速览

1. **形态推荐：静态目录型商店（两阶段）**。S1 = 商店只是一个**内网可 HTTP 访问的静态目录**（包文件 + `catalog.json`），零服务端逻辑、零账号面，上架 = 可信机跑入库脚本；S2（可选，按需立项）= 独立轻量管理面（上传/审核/统计），不进主包进程。选型对比见 §3.1。
2. **包不重做**：「上架即原包」——商店只收各出包链的产物并登记哈希；**两种包形态并行**（客户端本地包=zip 根即插件目录，T18 六连断言；服务器插件包=plugin-package.json+payload/，升级方案 §4），catalog 以 `runtime` 字段区分（local / server / dep-slot）。
3. **catalog 与共享盘 index.json 同构扩展**：`schema:1, packages:[…]` 骨架与字段名不变（id/version/file/sha256/size/min_app_version/changelog），增补 `runtime/name/published_at` 等——现客户端读取器不升级也能读，客户端升级后获得商店能力，兑现接缝①「读取器零改动」承诺的反向（目录向前兼容）。
4. **客户端三处补完**：安装收口 `install(pkg_source)` 单入口（现为上传单通道）；`plugin_source` 更新源配置（现仅构建配置 `plugin_store`，且构建配置里尚未落地该段）；下载→哈希→安装闭环与商店页签。
5. **与既有通道的关系**：共享盘通道保留为离线兜底（配置可切）；**服务器插件安装权威仍在主包 admin 三分法**，商店对 server 条目只做目录展示与包分发；admin 插件将来可消费同一 catalog。
6. **安全基线**：包 sha256 必校验（目录条目 ↔ 下载物）；内网 HTTP 允许（目标机不联网，RP2 前提）、TLS 可选；路径安全/`local-` 命名空间/mount 冲突由既有装包链承担；S2 可选 catalog 签名。

## 2. 现状盘点

### 2.1 三份「目录/登记」事实（同构性的真源）

| 载体 | 形态 | 字段 | 出处 |
| --- | --- | --- | --- |
| 共享盘 index.json（服务器插件） | `{schema:1, packages:[{id,version,file,sha256,size,requires_restart,min_app_version,changelog}]}` | file 相对索引目录 | `plugin_admin.py:1097-1127` |
| 服务器侧出包登记表 | `tools/plugin-packages.json`：同上字段 + built_at/code_sha256/file_count/file_hashes | 15 插件包批次登记 | 该文件实况 |
| 客户端本地索引（检查更新） | 读 `build_cfg.plugin_store.index_path` 指向的共享盘索引，仅消费 id/version/file/changelog | 无哈希校验、无 runtime 字段 | `client/capability_app.py:385-403` |

### 2.2 四接缝兑现现状（方案 §6.8 承诺 vs 2026-10-04 实况）

| 接缝 | 承诺（T21） | 实况 | 缺口 |
| --- | --- | --- | --- |
| ① 索引 schema 同构 | 版本化 JSON，字段与商店目录同构（id/version/api_version/min_app_version/runtime/sha256/size/download_url/changelog），读取器抽象为「源」 | `lp_check_update` 只读 4 字段、直读文件路径，无「源」抽象 | sha256/size/runtime 未消费；读取器与共享盘耦合 |
| ② 更新源可配置 `plugin_source` | 共享盘路径（默认）或 HTTP base URL | 代码读 `build_cfg.plugin_store`；**构建配置里 `plugin_store` 段尚未落地**，客户端配置无 `plugin_source` | 配置链整体待补 |
| ③ 安装收口 `install(pkg_source)` 单入口 | 本地文件/共享盘/HTTP 三来源同一链路 | 仅 zip 上传单通道（`lp_install`，校验+落盘+rescan 内联） | 校验链未抽函数、无远程下载分支 |
| ④ 包格式与类别中立字段 | 包格式与 plugin-packages.json 同构（manifest+sha256+file_hashes）；索引带 runtime（local/server） | manifest 有 `runtime:"local"`；客户端本地包**无出包工具**（b4 台架手打 zip），无 sha256 旁挂 | 本地包出包工具是空白 |

### 2.3 两种包形态（并行，不合并）

| | 客户端本地包 | 服务器插件包 |
| --- | --- | --- |
| zip 形态 | **包根即插件目录**：`manifest.json` + `frontend/` + `backend/` | `plugin-package.json` + `SHA256SUMS` + `payload/plugins/<id>/` |
| 校验 | T18 六连断言（能力层装包链） | inspect_package / install-plugin.ps1（升级方案 §5） |
| 消费方 | 客户端 `/local-api/plugins/install` | 主包 admin 三分法 / 共享盘 batch_apply |
| 商店 runtime 字段 | `local`（含 hybrid） | `server` |

## 3. 总体设计

### 3.1 形态选型

| 备选 | 说明 | 判定 |
| --- | --- | --- |
| **静态目录型（推荐 S1）** | 包文件 + catalog.json 挂内网静态 HTTP 站点（IIS 虚拟目录 / 任意静态服务）；上架 = 可信机跑入库脚本 | 零服务端逻辑、零新依赖、零账号面；攻击面最小；与共享盘同级的运维成本；匿名下载（内网） |
| 独立商店服务 | Flask 小服务：上传/审核/账号/统计 | S2 再议；首版把「审核流 + 账号」背进来，交付成本翻倍且内网无人力收益 |
| 并入主包（admin 插件延伸） | 商店页挂进主包后台 | 商店发版节奏被主包绑死；违背「商店服务端独立设计」边界；**否决**（admin 将来只作为 catalog 消费方） |

**S1 部署位形（待拍板 Q1）**：推荐主包服务器同机新开静态站点/虚拟目录（只读权限），目录结构见 §3.2；不进主包进程与发版链。

### 3.2 商店目录结构与 catalog 契约

```
<商店根>\                        ← 内网静态 HTTP 站点根
├── catalog.json                 ← 唯一目录文档（§3.2.1）；入库脚本唯一写入口
├── packages\
│   ├── JZClient-本地插件-local-report-tool-v1.2.0.zip
│   ├── JZToolsHub-插件-file-filter-v1.5.0.zip      ← 服务器插件包原样上架
│   └── JZToolsHub-依赖槽-cv2-v4.9.0.80.zip         ← 依赖槽包（联动 O1）
└── archive\                     ← 历史版本归档（不进 catalog；人工按需取用）
```

#### 3.2.1 catalog.json（schema 1，向后兼容扩展）

```jsonc
{
  "schema": 1,                       // 与共享盘 index.json 同主版本：老读取器照读
  "kind": "jz-plugin-store",         // 新增；老读取器忽略
  "generated_at": "2026-10-04T10:00:00+08:00",
  "packages": [
    {
      "id": "local-report-tool",     // 与共享盘 index.json 同名同义
      "version": "1.2.0",
      "file": "packages/JZClient-本地插件-local-report-tool-v1.2.0.zip",  // 相对商店根，/ 分隔
      "sha256": "…", "size": 48213,  // 必填（共享盘索引已有语义：客户端必校验）
      "runtime": "local",            // 新增：local | server | dep-slot；老读取器忽略
      "name": "台账报表（本地）", "description": "…",          // 新增：展示字段（信息性）
      "changelog": "…", "min_app_version": "",                 // 沿共享盘语义
      "api_version": 1,              // 客户端与 plugin_api 比对（沿用 jz_deps 门控语义）
      "published_at": "2026-10-04T10:00:00+08:00",
      "built_at": "2026-10-04T09:00:00+08:00", "built_from": {"commit": "…", "dirty": false}
    }
  ]
}
```

- 同 id 只挂**最新可用版**一条（与共享盘索引同口径）；历史版本进 `archive\` 不进目录（开放问题 Q4：是否需要版本历史浏览/回装）。
- `download_url` 不做字段：客户端由 `base_url + file` 拼接，避免两处漂移（如需 CDN/镜像，S2 以 base_url 换源实现）。

### 3.3 上架流程（S1 = 线下人工审核 + 脚本入库）

```
出包（各链）→ 校验（机器）→ 人工验收 → publish-store.py 入库 → catalog 再生
```

1. **出包**：本地包走新出包工具（§4.2）；服务器插件包走既有 `tools/build-plugin-package.ps1`；槽包走 O1 工具。
2. **机器校验**：入库脚本对每个包复跑对应链的校验（本地包=六连断言等价检查 + manifest↔文件名↔版本一致性；服务器包=plugin-package.json 结构与 SHA256SUMS 抽查），失败拒收。
3. **人工验收**：审核人按《验收手册》口径做装机冒烟（S1 的「审核」= 这一步的留痕：验收记录挂包号归档）；S2 再转线上流。
4. **入库**：`tools/store/publish-store.py` —— 算 sha256/size、合并/替换 catalog 条目（同 id 高版本生效，低版本拒绝回退，`--force` 显式降级）、写 `published_at`、输出变更摘要。脚本只操作商店目录，幂等可重跑。

### 3.4 客户端分发与安装闭环

```
管理页「商店」页签 → Source.list_catalog() → 列表/比对已装版本（_ver_lt 沿用）
  → 点安装 → Source.fetch(entry, <data>\downloads\) → sha256 对目录条目
  → pkg_install.install(zip)（六连断言 → 落盘 local-plugins\<id> → rescan）
  → 热插拔既有口径（worker 即时；hybrid 装卸即时、升级秒级重启）
  → 下载缓存保留最近 5 个（安装成功即可清）
```

- **`client/pkg_install.py`（新）**：从 `lp_install` 抽出完整校验+落盘链为 `install(zf|path, manifests, local_plugins_dir, log)`；上传/共享盘文件/商店下载三来源都汇到这里（接缝③收口）。哈希校验参数化：商店/共享盘来源必须带期望 sha256（目录条目或索引条目），本地上传可选旁挂 `.sha256` 文件。
- **`client/plugin_source.py`（新）**：`Source` 抽象 `list_catalog() / fetch(entry, dest)`；实现 `ShareSource`（index_path 所在目录=file base，行为=现况）与 `HttpSource`（GET base_url/catalog.json + base_url/file 流式下载，超时与 3 次重试）。**读取端零改动切换**（接缝①承诺兑现）。
- **`plugin_source` 配置**（接缝②）：客户端 `config.json` 增 `"plugin_source": {"type": "share", "index_path": …} | {"type": "http", "base_url": …}`；解析顺序=客户端配置 → 构建配置 `plugin_store.default_source`（出包定型）→ 无（仅本地上传）。管理页提供来源切换（写配置即生效，免重启）。
- **`check-update` 改造**：`lp_check_update` 改走 Source，消费 sha256/size/runtime；`runtime != "local"` 的条目不进安装列表（server 条目只读提示「到主包后台安装」；dep-slot 条目进依赖页签，联动 O1）。

### 3.5 与共享盘通道、admin 的关系

- **共享盘通道保留**：`plugin_source` 切回 `share` 即回到现状（离线兜底/无站点环境）；两通道不同时生效，单源模型（多源并存列开放问题 Q3）。
- **admin（服务器插件）**：安装权威仍在主包 admin 三分法与共享盘 batch_apply；商店 server 条目只做**目录展示 + 包分发**（给服务器管理员取包），客户端绝不安装 server 包；将来 admin 若接商店，消费同一 catalog（schema 同构是前提，这也是接缝④坚持类别中立字段的原因）。
- **主包出包链零改动**：商店不参与出包，只消费产物（「上架即原包」）；`plugin-packages.json` 登记表继续是真源，入库脚本可从其条目复用元数据（不复制文件哈希，重算为准）。

### 3.6 安全口径

| 面 | 口径 |
| --- | --- |
| 包完整性 | sha256 必校验（catalog 条目 ↔ 下载物；共享盘索引同款语义）；不符拒装并提示「介质损坏或被篡改」 |
| 传输 | 内网 HTTP 允许（目标机不联网，RP2 前提）；站点可配 TLS，客户端 https 直接支持；**不引入强制证书体系** |
| 目录防篡改 | S1 依赖商店目录的文件系统权限（只读发布、受控写）；catalog 签名（ed25519，公钥随构建配置）列 S2 可选增强 |
| 包内容 | 六连断言 + `local-` 命名空间 + mount 冲突 + 禁 `shell=True` 铁律由既有装包链承担，商店不另设白名单 |
| 数据边界 | 商店只分发代码包；类 C `server_data:true` 的「数据出机」明示仍在安装时弹出（既有行为），与商店来源无关 |

### 4.3 `/local-api` 增量

| 接口 | 方法 | 语义 |
| --- | --- | --- |
| `/local-api/store/catalog` | GET | 经 Source 拉目录，返回合并视图（条目 + 已装版本 + 可升级标记 + runtime）；商店不可达返回错误态（页面降级提示，不影响其他页签） |

| `/local-api/config/plugin-source` | GET/POST | 读取/切换更新源（写客户端配置，免重启） |

### 4.4 管理页增量（`local_admin.html`）

「商店」页签：目录列表（名称/版本/体积/发布时间/changelog/来源徽标）+ 安装/更新按钮 + 已装条目比对高亮；「依赖组件」页签挂 dep-slot 条目（联动 O1 §4.3）；来源切换下拉（共享盘路径 / 商店地址）。

## 6. 验收标准

| # | 用例 | 预期 |
| --- | --- | --- |
| B1 | publish-store 入库（本地包/服务器包/槽包各 1） | 三种 runtime 条目进 catalog；重复入库幂等；低版本回退被拒 |

## 7. 风险与开放问题（拍板清单）

| # | 项 | 建议 |
