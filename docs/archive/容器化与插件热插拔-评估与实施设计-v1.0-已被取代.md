## 1. 背景与目标

### 1.1 需求来源

项目未来部署于 Linux 服务器。期望开发者添加 L2 插件时，只需将插件后端放入约定位置（挂载），即可正常使用，**无需重启整个项目服务**。

### 1.2 目标清单

| 编号 | 目标 | 度量口径 |
| --- | --- | --- |
| G1 | 主框架具备容器化运行形态（镜像 + 卷挂载） | 一条 `docker compose up` 可起完整站点 |
| G2 | 新增 B 型插件**零重启**生效 | 拷贝目录 + 登记 tools.json → 刷新浏览器可用，主进程无任何重启动作 |
| G3 | 新增 A 型插件准零停机生效 | 平滑重载（worker 秒级换血），用户登录态不丢 |
| G4 | 插件间依赖彻底隔离 | 任一插件的第三方依赖版本变化不影响其他插件与主框架 |
| G5 | 全程不改业务插件代码即可迁移到新形态 | 现有 9 个插件在改造后原样可用 |

### 1.3 非目标（本期不做）

- 多机分布式部署 / 高可用集群；
- 插件市场与远程分发渠道；
- A 型插件的进程内热注册（明确否决，理由见 2.3）；
- 前端构建链路改造。

## 2. 现状分析

### 2.1 架构现状（关键代码位置）

| 机制 | 位置 | 行为 |
| --- | --- | --- |
| 后端注册 | `app.py` → `register_plugin_backends()`，仅在 `__main__` 启动时调用一次 | 启动后不再扫描，新增 L2 后端必须重启 |
| 后端加载方式 | `_load_backend_module()` | 以独立模块名 `jztools_<id>` 动态 import 进**主进程解释器** |
| 配置读取 | `load_registry()` 等 | **每请求实时读** `config/tools.json`——名称/启停/排序改动天然免重启 |
| 会话 | Flask 签名 Cookie；`SECRET_KEY` 由 admin 插件从 `config/admin.json` 持久化加载 | 进程重启 / worker 换血后登录态**不丢** |
| 异步任务 | 各插件进程内字典（如 character-graph 的 `TASKS`） | 仅单进程模型下自洽，多 worker 会失联（见 5.5 地雷 T-1） |
| 运行平台 | 当前 Windows + Flask 开发服务器 | 生产建议 gunicorn/waitress（README 已有此建议） |

### 2.2 能力缺口对照

| 编号 | 缺口 | 影响 |
| --- | --- | --- |
| K1 | 无 B 型插件的通用接收入口——适配器本身也是 `routes.py`，仍需启动注册 | B 型无法免重启（规范 v1.1 的 12.3 步骤 6 要求重启） |
| K2 | 所有插件共享同一解释器环境 | `numpy` / `opencv-python` 等版本互相牵制，依赖冲突随插件数增长必然爆发 |
| K3 | 无生产级 WSGI 与进程管理 | 无法平滑重载、无法容器化编排 |
| K4 | 无挂载物完整性校验环节 | "免重启上线"会绕过人工确认闸门，需机器校验补位 |

### 2.3 关键认知（决定方案走向）

1. **venv 单独不解决问题**。venv 只能隔离主项目；同一进程内不可能同时加载两个版本的 `numpy`。真正的依赖隔离只有两条路——子进程或容器，而这正是规范 v1.1 的 B 型模型。
2. **A 型做不到真·免重启**。A 型后端是进程内 import 的 Python 代码，"不重启而换代码"意味着进程内热注入——模块卸载不干净、线程池泄漏、全局状态残留，明确**禁止**。A 型的最好形态是"秒级平滑重载，用户无感"。
3. **B 型可以真·零重启**。B 型后端本就是独立进程，只要框架有一条**配置驱动的通用代理路由**，新增 B 型插件就退化为"放文件 + 写配置"，主进程一行代码都不动。
4. **会话天然抗重启**。签名 Cookie + 持久化 SECRET_KEY，任何形式的 worker 换血都不影响已登录用户。

## 3. 总体方案：三阶段演进

```
阶段一（框架内改造）        阶段二（容器化主框架）           阶段三（插件即容器）
┌─────────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
│ app.py + jz_gateway │   │ Docker 镜像            │   │ Compose 编排           │
│ 通用代理路由         │──▶│ gunicorn 单进程多线程   │──▶│ hub 容器 + N 个插件容器 │
│ runtime.json 直通    │   │ plugins/config 卷挂载  │   │ 内部网络互信           │
│ → B 型零重启         │   │ HUP 平滑重载 → A 型准零 │   │ → 彻底隔离，按需扩缩   │
└─────────────────┘   └──────────────────────┘   └──────────────────────┘
     约 2~3 人日              约 3~5 人日                   按需启动
```

| 阶段 | 兑现能力 | 前置条件 |
| --- | --- | --- |
| 一 | G2（B 型零重启） | 无——纯框架内小改，Windows/Linux 皆可 |
| 二 | G1、G3、部分 G4（B 型子进程隔离） | 阶段一；目标机具备 Docker 或为 Linux 裸机 |
| 三 | G4 完全体、面向多插件规模 | 阶段二；确有插件数量/隔离强度诉求 |

**选型原则**：每阶段独立交付价值、独立回滚；不叠加不做。

## 4. 阶段一：内置网关与 B 型直通（零重启核心）

### 4.1 设计原则

1. **一条通配路由服务所有 B 型插件**：框架只注册一次 `POST/GET/... /api/<pid>/<path>` 兜底规则，转发目标由各插件的 `backend/runtime.json` 实时决定——新增插件不需要任何 Python 代码进入主进程。
2. **实时发现**：网关每次请求（带短 TTL 缓存）扫描 `plugins/*/backend/runtime.json`，与现有 `load_manifests()` 的实时风格一致，因此"拷入目录即被发现"。
3. **不遮蔽既有路由**：Werkzeug 按"静态段优先于动态转换器"匹配，`/api/tools`、admin 的路由永远先于通配规则命中；网关侧再加黑名单双保险。
4. **复用规范契约**：身份注入头、健康检查、环境变量、数据目录全部沿用《插件设计规范》8.7–8.8 的 `jz-runtime-1` 定义，插件无需感知接入通道的变化。

### 4.2 发现与路由规则

```
请求 GET /api/excel-pro/convert
  ├─ pid 合法性检查 ^[A-Za-z0-9_-]+$ ──✗──▶ 404
  ├─ pid ∈ 启动期已注册前缀集合（A 型/admin）──▶ 理论上不会到达（静态路由已命中），防御性 404
  ├─ 扫描 plugins/<pid>/backend/runtime.json
  │     ├─ 不存在 ──▶ 404 {"error": "unknown plugin"}
  │     ├─ mode=http-service ──▶ 确保内部服务在线 ──▶ 反向代理
  │     ├─ mode=remote       ──▶ 直接反代 service_url（阶段三容器场景）
  │     └─ mode=cli          ──▶ 501（CLI 模式仍走附录 D 适配器，不在网关范围）
  └─ 转发：剥离 Cookie → 注入 X-JZ-* 身份头 → 流式透传 → 剥离逐跳响应头
```

`runtime.json` 在规范 8.7 基础上增加一个取值：

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `mode` | `remote` | **新增**。不本地拉起子进程，直接反代 `service_url`（供容器编排场景使用） |
| `service_url` | `http://host:port` | `mode=remote` 时必填 |

### 4.3 参考实现：`jz_gateway.py`

新建于项目根目录，与 `app.py` 同级；由 `register_plugin_backends(app)` 末尾按开关调用：

```python
"""JZToolsHub 内置网关 —— B 型插件零重启接入（阶段一参考实现）。

约定：
- 服务对象：plugins/<id>/backend/runtime.json 存在且未被启动期注册的插件；
- 协议：jz-runtime-1（《插件设计规范》8.7 / 8.8）；
- 开关：config/tools.json → site.gateway.enabled（缺省 false，灰度后打开）。
"""
import atexit
import json
import os
import re
import socket
import subprocess
import threading
import time
from collections import defaultdict, deque

import requests
from flask import Response, jsonify, request

try:
    from jztools_admin.routes import get_session_user
except Exception:
    get_session_user = None

BASE_DIR = os.path.dirname(os.path.abspath(__file__))
PLUGINS_DIR = os.path.join(BASE_DIR, "plugins")
PID_RE = re.compile(r"^[A-Za-z0-9_-]+$")

# 启动期已注册的插件前缀（由 app.register_plugin_backends 注入），网关一律跳过
STARTUP_REGISTERED = set()
# 框架保留前缀，双保险防遮蔽
FORBIDDEN = {"tools", "admin", "login", "logout", "session", "account"}

_SCAN_LOCK = threading.Lock()
_SCAN_CACHE = {}          # pid -> {rt, mtime}
_SCAN_TS = 0.0
_SCAN_TTL = 3.0           # 秒；目录扫描节流

_CHILDREN = {}            # pid -> {proc, base, error, fails: deque[ts]}
_CHILD_LOCKS = defaultdict(threading.Lock)
_CRASH_WINDOW = 300.0     # 5 分钟崩溃窗口
_CRASH_MAX = 3


def _scan_runtimes():
    """TTL 扫描全部候选 B 型插件，返回 {pid: runtime_dict}。"""
    global _SCAN_CACHE, _SCAN_TS
    now = time.time()
    if now - _SCAN_TS < _SCAN_TTL:
        return _SCAN_CACHE
    found = {}
    if os.path.isdir(PLUGINS_DIR):
        for name in os.listdir(PLUGINS_DIR):
            if not PID_RE.match(name) or name in STARTUP_REGISTERED:
                continue
            path = os.path.join(PLUGINS_DIR, name, "backend", "runtime.json")
            try:
                mtime = os.path.getmtime(path)
            except OSError:
                continue
            cached = _SCAN_CACHE.get(name)
            if cached and cached["mtime"] == mtime:
                found[name] = cached["rt"]
                continue
            try:
                with open(path, encoding="utf-8") as f:
                    rt = json.load(f)
                if isinstance(rt.get("protocol"), str) and rt["protocol"].startswith("jz-runtime-"):
                    found[name] = rt
                    _SCAN_CACHE[name] = {"rt": rt, "mtime": mtime}
            except Exception:
                continue  # 坏文件视同不存在，不影响其他插件
    _SCAN_CACHE = found
    _SCAN_TS = now
    return found


def _free_port():
    s = socket.socket()
    s.bind(("127.0.0.1", 0))
    port = s.getsockname()[1]
    s.close()
    return port


def _resolve_exe(pid, rt):
    platform = "win-amd64" if os.name == "nt" else "linux-amd64"
    ext = ".exe" if os.name == "nt" else ""
    rel = rt["executable"].replace("{platform}", platform).replace("{ext}", ext)
    exe = os.path.join(PLUGINS_DIR, pid, rel)
    if not os.path.isfile(exe):
        raise FileNotFoundError(f"缺少可执行文件：{rel}")
    return exe


def _spawn(pid, rt):
    st = _CHILDREN.setdefault(pid, {"proc": None, "base": None,
                                    "error": None, "fails": deque(maxlen=10)})
    now = time.time()
    recent = [t for t in st["fails"] if now - t < _CRASH_WINDOW]
    if len(recent) >= _CRASH_MAX:
        raise RuntimeError(f"crash-loop：{_CRASH_WINDOW:.0f}s 内失败 {len(recent)} 次，熔断中")
    port = _free_port()
    home = os.path.join(PLUGINS_DIR, pid)
    backend = os.path.join(home, "backend")
    env = {**os.environ,
           "JZ_PLUGIN_PORT": str(port),
           "JZ_PLUGIN_HOME": home,
           "JZ_PLUGIN_DATA": os.path.join(backend, "data"),
           "JZ_PLUGIN_CONFIG_FILE": os.path.join(backend, "config.json")}
    args = [a.replace("{port}", str(port)) for a in rt.get("args", ["--port={port}"])]
    os.makedirs(os.path.join(backend, "data"), exist_ok=True)
    log = open(os.path.join(backend, "data", "service.log"), "ab")
    proc = subprocess.Popen([_resolve_exe(pid, rt)] + args, cwd=home, env=env,
                            stdout=log, stderr=subprocess.STDOUT)
    base = f"http://127.0.0.1:{port}"
    deadline = time.time() + rt.get("startup_timeout_s", 15)
    while time.time() < deadline:
        if proc.poll() is not None:
            st["fails"].append(time.time())
            raise RuntimeError("内部服务启动即退出，详见 backend/data/service.log")
        try:
            if requests.get(base + rt.get("health_path", "/healthz"), timeout=1).ok:
                st.update(proc=proc, base=base, error=None)
                return
        except Exception:
            time.sleep(0.3)
    proc.terminate()
    st["fails"].append(time.time())
    raise TimeoutError("内部服务健康检查超时")


def _ensure_up(pid, rt):
    with _CHILD_LOCKS[pid]:
        st = _CHILDREN.setdefault(pid, {"proc": None, "base": None,
                                        "error": None, "fails": deque(maxlen=10)})
        if st["proc"] and st["proc"].poll() is None:
            return st["base"]
        st["error"] = None
        try:
            _spawn(pid, rt)
        except Exception as exc:
            st["error"] = str(exc)
            raise
        return st["base"]


def _identity_headers():
    u = get_session_user() if get_session_user else None
    if not u:
        return {}
    return {"X-JZ-User": u.get("username", ""),
            "X-JZ-Display-Name": u.get("name", ""),
            "X-JZ-Unit-Id": str(u.get("unit_id") or ""),
            "X-JZ-Department-Id": str(u.get("department_id") or ""),
            "X-JZ-Super-Admin": "true" if u.get("super_admin") else "false"}


_HOP_HEADERS = {"connection", "keep-alive", "transfer-encoding",
                "te", "trailer", "upgrade", "proxy-authorization",
                "proxy-authenticate", "content-encoding", "content-length"}


def register_gateway(app):
    """由 app.register_plugin_backends() 在启动期末尾调用一次。"""

    @app.route("/api/<pid>/<path:rest>",
               methods=["GET", "POST", "PUT", "DELETE", "PATCH"])
    def _gateway_proxy(pid, rest):
        if not PID_RE.match(pid) or pid in FORBIDDEN or pid in STARTUP_REGISTERED:
            return jsonify({"error": "unknown plugin"}), 404
        rt = _scan_runtimes().get(pid)
        if rt is None:
            return jsonify({"error": "unknown plugin"}), 404
        mode = rt.get("mode", "http-service")
        try:
            if mode == "remote":
                base = rt["service_url"].rstrip("/")
            elif mode == "http-service":
                base = _ensure_up(pid, rt)
            else:
                return jsonify({"error": f"gateway 未支持 mode={mode}，请使用 SDK 适配器"}), 501
        except Exception as exc:
            return jsonify({"error": f"internal service unavailable: {exc}"}), 503

        try:
            up = requests.request(
                request.method, f"{base}/{rest}",
                params=request.args, data=request.get_data(),
                headers={"Content-Type": request.content_type or "",
                         **_identity_headers()},
                stream=True, timeout=(3, 120))
        except requests.RequestException as exc:
            return jsonify({"error": f"upstream unreachable: {exc}"}), 502
        headers = [(k, v) for k, v in up.headers.items()
                   if k.lower() not in _HOP_HEADERS]
        return Response(up.iter_content(chunk_size=64 * 1024),
                        status=up.status_code, headers=headers)

    @app.get("/api/<pid>/__gateway/status")
    def _gateway_status(pid):
        st = _CHILDREN.get(pid, {})
        proc = st.get("proc")
        up = proc is not None and proc.poll() is None
        return jsonify({"plugin": pid,
                        "internal_service": "healthy" if up else "down",
                        "error": st.get("error")})

    @atexit.register
    def _shutdown_all():
        for st in _CHILDREN.values():
            if st["proc"] and st["proc"].poll() is None:
                st["proc"].terminate()
```

### 4.5 与既有适配器模式的关系

| 场景 | 接入通道 | 是否需要重启 |
| --- | --- | --- |
| B 型 + `mode=http-service`，无特殊需求 | **内置网关**（推荐，插件包内不再需要 routes.py） | 否 |
| B 型 + `mode=remote`（阶段三容器场景） | **内置网关** | 否 |
| B 型 + CLI 模式 / 需要定制桥接逻辑 | 附录 D 标准 SDK 适配器（启动期注册） | 是（首次） |
| A 型源码插件 | 启动期注册 | 是 / 平滑重载（阶段二） |

兼容性结论：网关是**增量通道**，不改变任何既有插件的行为；规范附录 D 适配器继续有效，作为"非标桥接"的逃生舱。

### 4.6 验收标准（阶段一完成定义）

- [ ] 拷入一个仅含 `manifest.json + frontend/ + backend/{runtime.json, bin/, data/}` 的 B 型插件（无 routes.py），登记 tools.json 后刷新浏览器即可用，期间 `ps` 确认主进程 PID 未变；
- [ ] 删除该插件目录后刷新，卡片消失且网关返回 404，无残留子进程（`pgrep -f hello-pro` 为空）；
- [ ] 强杀内部服务子进程：≤5 分钟内自动恢复 ≤3 次，之后 `/api/<pid>/__gateway/status` 报告熔断错误；
- [ ] 匿名 curl 直达 `/api/<pid>/anything` 被上游以 401 拒绝；登录后上游能读到正确的 `X-JZ-*` 头；
- [ ] `/api/tools`、admin 全部接口回归通过（通配路由未遮蔽任何既有端点）。

## 5. 阶段二：主框架容器化（Linux）

### 5.1 运行时选型与"单进程陷阱"

```python
# gunicorn.conf.py（放项目根目录）
bind = "0.0.0.0:5000"
workers = 1              # ★ 见下文 T-1：进程内任务表未外置前必须保持 1
worker_class = "gthread"
threads = 16             # 并发由线程承担（实测单线程模型 300 并发即瓶颈）
timeout = 120            # 与网关上游超时对齐
graceful_timeout = 30
accesslog = None         # 访问日志由应用层异步记录，避免双份
errorlog = "-"
preload_app = False
```

> **T-1 地雷（务必知晓）**：character-graph / case-report 等插件的异步任务表存放在**进程内存**中。一旦 `workers > 1`，提交与轮询可能落到不同 worker，表现为"task_id 永远 pending"。解除路径（按代价排序）：
> ① 维持 `workers=1, threads=N`（当前推荐，配合平滑重载足够）；
> ② 任务表落盘 SQLite（`backend/data/tasks.sqlite`，改动各插件约 20 行）；
> ③ 引入 Redis 集中任务存储（引入新组件，仅在多机时考虑）。
> 在 T-1 解除前，**禁止**盲目调大 workers。

### 5.3 docker-compose 参考

```yaml
services:
  hub:
    build: .
    image: jztoolshub:latest
    container_name: hub
    ports:
      - "127.0.0.1:5000:5000"        # 生产由 nginx 反代对外，宿主机仅绑回环
    volumes:
      - ./plugins:/app/plugins       # 插件热插拔的主入口（B 型拷入即生效）
      - ./config:/app/config         # tools.json / admin.json（含密钥，勿进镜像）

    restart: unless-stopped
    # 资源护栏（按需调整）
    mem_limit: 1g
    pids_limit: 256
```

要点：

- **三个卷就是全部状态**：代码无状态化后，备份/迁移 = 备份这三个目录；
- `plugins/` 以读写挂载——网关需要写入各插件的 `backend/data/service.log`；
- 对外发布统一走 nginx 反代（gzip、TLS、限流都在那一层做），hub 不直接暴露公网。

### 5.4 上线操作手册（Linux）

**B 型插件（零重启）**

```bash
unzip excel-pro.zip -d plugins/
cd plugins/excel-pro && sha256sum -c SHA256SUMS   # SEC-8 强制
pip 无需执行——B 型无 Python 业务依赖（适配器场景除外）
# 编辑 config/tools.json 登记 …
curl -fsS localhost:5000/api/tools | grep excel-pro   # 即刻可见
```

**A 型插件（准零停机）**

```bash
unzip my-tool.zip -d plugins/
# 编辑 config/tools.json 登记 …
docker exec hub kill -HUP 1        # gunicorn master 平滑重载全部 worker
# 裸机 systemd 等价：systemctl reload jztoolshub
sleep 2 && curl -fsS localhost:5000/api/tools | grep my-tool
```

平滑重载语义：master 常驻监听，旧 worker 处理完存量请求后退出，新 worker 加载新代码——全程端口不掉、Cookie 会话不掉。**唯一损失**：重载瞬间进程内异步任务表清空（T-1），故应避开长任务高峰。

### 5.5 systemd 裸机部署（不用 Docker 时）

```ini
# /etc/systemd/system/jztoolshub.service
[Unit]
Description=JZToolsHub toolbox
After=network.target

[Service]
Type=simple
User=jz
Group=jz
WorkingDirectory=/opt/jztoolshub
Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/jztoolshub/venv/bin/gunicorn -c gunicorn.conf.py app:app
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure
RestartSec=3
# 加固
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/opt/jztoolshub/plugins /opt/jztoolshub/config /opt/jztoolshub/logs
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

裸机形态下 B 型零重启照常成立（网关在同一进程内），A 型用 `systemctl reload` 达到同等平滑效果。

## 6. 阶段三：插件即容器（Compose 编排）

### 6.1 拓扑

```
nginx ──▶ hub 容器（网关/框架/Admin）
              │ 同一内部网络 jzinternal（DNS 互访）
              ├──▶ excel-pro 容器   （B 型，image 独立）
              ├──▶ char-graph 容器  （B 型）
              └──▶ …按需扩展
```

- 插件容器**不发布任何宿主机端口**，只在 `jzinternal` 网络内可达——SEC-7 的"仅回环"语义在网络层被等价实现（信任边界 = 编排网络边界）；
- 插件的 `runtime.json` 使用 `mode=remote`：

```json
{
  "protocol": "jz-runtime-1",
  "mode": "remote",
  "service_url": "http://excel-pro:8080",
  "health_path": "/healthz"
}
```

### 6.2 compose 片段示例

```yaml
services:
  hub:
    # …同 5.3，另加：
    networks: [edge, jzinternal]

  excel-pro:
    image: registry.local/jz/excel-pro:1.4.0
    networks: [jzinternal]
    expose: ["8080"]                       # 仅网络内可见
    environment:
      JZ_PLUGIN_PORT: "8080"
      JZ_PLUGIN_DATA: /data
      JZ_PLUGIN_CONFIG_FILE: /conf/config.json
    volumes:
      - ./data/excel-pro:/data             # 数据仍按插件分目录，便于备份/卸载
      - ./config/excel-pro:/conf:ro
    mem_limit: 512m
    pids_limit: 128
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1:8080/healthz"]
      interval: 15s

networks:
  edge: {}
  jzinternal:
    internal: true        # 默认无出网能力；确需外联的插件单独开第二网络
```

## 7. 安全加固（贯穿三阶段）

| 编号 | 措施 | 适用 |
| --- | --- | --- |
| S-A | **挂载即信任原则显性化**：安装脚本强制 `sha256sum -c SHA256SUMS`，失败即中止；校验记录写入安装日志 | 一/二/三 |

## 10. 风险登记册

| # | 风险 | 等级 | 缓解 |
| --- | --- | --- | --- |
| R1 | 多 worker 导致进程内任务表失效（T-1） | 高 | 阶段二锁死 `workers=1`；任务表外置列为独立工作项 |
| R2 | 通配路由遮蔽未来新增的框架端点 | 中 | FORBIDDEN 黑名单 + 新框架端点命名评审纳入 checklist |
| R3 | 免重启上线绕过人工复核，恶意/劣质包直接生效 | 中 | S-A 强制校验和 + S-B 配置审计；网关对坏 runtime.json 静默跳过 |
| R4 | B 型子进程孤儿（hub 被 `kill -9`） | 低 | atexit 覆盖常规退出；极端残留靠 `service.pid` 清理脚本（列入运维手册 TODO） |
| R5 | Windows 开发 / Linux 生产路径与大小写差异 | 低 | 框架已全用 `os.path`；插件 ID 规范已强制小写连字符；CI 增加 Linux 冒烟 |
| R6 | gunicorn HUP 重载瞬间丢失进行中的长任务 | 中 | 运维窗口约定（低峰重载）；长任务插件优先 B 型化（子进程不受影响） |
| R7 | 插件容器镜像供应链风险 | 中 | 私有 registry + 固定 digest/tag；S-C 资源限额兜底爆炸半径 |
