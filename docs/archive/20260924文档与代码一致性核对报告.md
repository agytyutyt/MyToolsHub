## 2. 总体结论

**代码本身仍是好的**：本轮 111 条问题里，**需要改代码的只有 6 条**（P0-1/2/3、C-3、D-2，以及 E 组 1 条权限模块的二选一修复），其余 **105 条均为文档/注释/界面文案回写**。

但**文档侧的漂移面比上一轮更宽**，且出现三类新特征：

1. **修复本身引入的回归**（P0-1）：上一轮为删死代码而删掉 `if` 行，留下 `else if`，导致 knowledge-base 前端**整份 JS 失效**——这是本轮唯一的"功能性 P0"，且它藏在未提交改动里，`node --check` 一行即可发现。
2. **大改动后的口径分裂**（A 组 + S-1/S-2/S-3）：09-23 统一大模型落地后，"插件不再自持 API Key"这一条在**代码里是彻底的**（模板清空、启动迁移删段、`/config` 只回状态），但在**插件 README、设计文档、规范条款（F-4）、代码 docstring** 里仍有 5 处自持口径存活，其中规范 F-4 是**必须级条款**，照它做正好把已清除的东西放回去。
3. **批量复述的老毛病复发**（S-1/S-2/S-3）：三类事实各被 8~11 份文件复制且全部过时——**依赖表把组件包内包名写成"框架已打包"（8 份）、规范依据错引 U-2/U-4/U-6（11 份）、"五要素"（13 个文件）**。这类问题单条修很慢、批量脚本一次可清，且 `docs/README.md` §3.1 已有对应纪律，属"纪律已立、执行未跟上"。

**最需要立刻处理的三件事**：P0-1（一行修复，恢复知识库前端）、P0-3（批量导入会清空既有描述，**会丢数据**）、P0-2（用户自助设置的大模型 custom 模板被静默丢弃，**用户按界面操作必失败**）。
