## 2. 总体结论（先看这里）

**整体一致性：中偏差，且偏差高度集中在"文档滞后于解耦改造与功能迭代"这一类。**

| 维度 | 评价 |
| --- | --- |
| 框架级接口文档（根 `README.md` §7） | 好。12 条核心接口逐条吻合，仅有遗漏（代码有、文档没写），**无"文档写了但代码不存在"** |
| 插件接口文档（`plugins/<id>/README.md`） | 参差。base64 / color-picker / json-formatter / md5-generator / shared-docs / qr-video-decode 6 个完全吻合；`case-report`、`character-graph`、`trajectory-sketch`、`notice-board`、`admin` 偏差较大 |
| 交付/打包文档 | 差。属**系统性滞后**：主包体积、包内组成、模板自检阈值、version.json 字段、依赖白名单 5 类事实全部停留在解耦前口径 |
| 设计文档（`docs/design/`） | 偏差大。`知识库Office预览`、`登录改造与数据隔离`、`主体与插件解耦` 三份存在大段已被实现推翻的正文，且文首横幅未覆盖 |
| 文档之间 | 存在**唯一真源被破坏**：`map-marker` 资产归属、`PACKAGES` 项数、主体版本号、审计条目数 4 类事实在 2~3 份文档间互相矛盾 |
| 代码注释 vs 文档 | 注释本身也有滞后（`info-transfer/routes.py` 6 处、`reader.js` 3 处），但与文档方向一致，属同源滞后 |

**两类根因**：

1. **改造后未回写**（占 ~70%）：2026-09-19 起的「主体与插件解耦」把 `cv2/numpy` 等移出主包、把 LLM 配置收归 `jz_llm`、把跨插件 HTTP 调用改为本地实现、把知识库 PDF 管线换成 HTML 引擎——**代码全改了，文档只改了少数几处**。
2. **缺少"事实项清单"**：`docs/README.md` §3 覆盖矩阵规定了唯一落点，但**未定义"哪些事实属于易漂移事实、必须在改造 checklist 中逐项回写"**，导致版本号、项数、体积这类数值型事实无人维护。

**最需要立刻修的是 4 个 P0**（照文档操作会直接出错），其余按 §5 的批次推进。
