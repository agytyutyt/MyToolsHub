# 公告板（notice-board）

单位与部门公告发布与查看插件。

## 功能

- **查看**：全体登录用户默认可用（`config/tools.json` 中 `grant_all: true`，无需逐人授权）；
- **发布**：仅「管理员」角色（role-admin）与超级管理员。发布对话框为左右结构：
  左侧输入标题与内容，右侧选择可见范围——
  单位→部门→用户 树状勾选（左）｜「选择」按钮（中）｜已选对象框（右，可逐项移除）；
- **可见性**：公告仅对所选对象可见，命中任一目标即可见；
- **修改**：管理员角色（role-admin）与超级管理员可改标题、内容与可见范围（`PUT /announcements/<aid>`）；
  创建归属与创建时间保留；
- **删除**：发布者本人或超级管理员。

## 接口

前缀 `/api/notice-board`（`backend/routes.py`）：

| 接口 | 方法 | 说明 | 权限 |
| --- | --- | --- | --- |
| `GET /api/notice-board/status` | GET | 依赖自检（纯标准库实现，恒可用） | 无需登录 |
| `GET /api/notice-board/config` | GET | 前端渲染开关：当前用户是否可发布公告（`can_publish`） | 无需登录（未登录返回 `can_publish: false`） |
| `GET /api/notice-board/announcements` | GET | 公告列表：先按可见性过滤再返回（附 `manageable` / `editable` 标记） | 登录用户（未登录 401） |
| `GET /api/notice-board/latest` | GET | 最新一条可见公告（供站点首页公告条展示） | 登录用户（未登录 401） |
| `POST /api/notice-board/announcements` | POST | 发布公告：标题 ≤80 字、内容 ≤5000 字、可见范围 1~50 个目标 | 管理员角色（role-admin / 「管理员」）或超级管理员（无权限 403） |
| `PUT /api/notice-board/announcements/<aid>` | PUT | 修改标题 / 内容 / 可见范围，保留创建归属与创建时间 | 管理员角色或超级管理员，且该公告对其可见（不可见 404 / 无权限 403） |
| `DELETE /api/notice-board/announcements/<aid>` | DELETE | 删除公告 | 创建者本人或超级管理员（不可见 404 / 无权限 403） |

- 未登录一律 401；`POST` / `PUT` 的标题、内容、可见范围校验失败返回 400；
  归属四字段（`created_by` / `created_by_name` / `unit_id` / `department_id`）一律取自服务端会话，不从请求体接收。
- `PUT` / `DELETE` 对「不存在」与「不可见」统一返回 404，不暴露公告存在性。

## 可见性规则

| 目标类型 | 可见条件 |
| --- | --- |
| 单位 | 与目标同单位的用户 |
| 部门 | 与目标同部门且同单位的用户 |
| 用户 | 该用户本人 |
| 超级管理员 | 全部可见 |

## 依赖与升级

| 项 | 内容 |
| --- | --- |
| 框架已打包依赖 | `flask` >=3.0（必需，随主包） |
| 插件自带依赖（`backend/vendor/`） | 无 |
| 外部程序组件 | 无 |
| 能否单独升级 | ✅ 可以——依赖全部落在框架已打包清单或插件目录内（构建期 C-4/C-10 校验） |
| 升级是否需重启 | 含 `backend/**` 改动**需要**重启（后台/安装器会自动重启，约 5~10 秒）；纯前端改动免重启，Ctrl+F5 即可 |

> 声明真源是 `manifest.json` 的 `requires`（三类依赖：框架包 / 自带 vendor / 外部程序组件）；
> 出包工具构建期校验「声明 ↔ 实测 import」一致（C-10）。后台「插件管理」按它显示
> 逐依赖徽标与可运行性：缺**必需**依赖 → 标记不可运行并暂不加载，补齐后重启自动恢复；
> 缺**可选**依赖 → 照常加载但标注功能降级。规范依据：《插件设计规范》§15 U-7a / U-8。

## 已知限制

- 发布角色依据 admin 插件的角色 ID（role-admin）/角色名（管理员）判定，
  如在「人员管理 → 角色管理」中重建同名角色请保持 ID 一致；
