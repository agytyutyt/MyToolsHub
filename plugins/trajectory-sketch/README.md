# 轨迹速写（trajectory-sketch）

> 上传原始轨迹表（Excel，**自动删除文档里的背景图片**）→ **字段过滤**（本插件自带实现：
> 默认硬过滤，可切换大模型辅助做表头语义关联）→ 轨迹分析 → **速写报告**（页内预览 + Excel 工作簿下载）。

JZToolsHub 插件 · L2 前后端一体（A 型源码插件）· 设计文档见仓库 `docs/design/轨迹速写插件-设计文档.md`

---

## 1. 功能

| 步骤 | 说明 |
| --- | --- |
| ⓪ 删除背景图片 | 上传后**先**识别文档里嵌入的**工作表背景图片**（Excel「页面布局 → 背景」插入的图，常被用来夹带水印/机构标识），识别到就摘掉再落盘暂存——后续自检 / 分析 / 报告全链路只面对"干净"的文档。自检卡片与报告的「数据质量」sheet 都会记录这条结论 |
| ① 上传与自检 | 拖拽/点选 `xlsx` / `xls` / `csv`（≤20MB）。后端读表后**立即**用本插件自带的过滤实现做一次硬过滤预演，返回真实表头、保留/删除字段、必需列命中情况与过滤后数据预览 |
| ② 过滤模式 | **硬过滤（默认）**：字段名与保留名单精确匹配；**大模型辅助**：由统一大模型做表头语义关联（如「采集起始时刻」↔「开始时间」），需先在「大模型设置」中配置接入信息（见 §2） |
| ③ 轨迹分析 | 内置可插拔引擎：地点簇 → 自适应停留点 → 出行段（含位移/切换判别）→ 报告 |
| ④ 速写报告 | 页内展示速写摘要、报告正文、停留点、出行段、数据质量、地点簇；可下载 5 个 sheet 的 Excel |

> 背景图片清理的实现与边界（只摘背景引用、保留其余部件字节、没命中就不改写文件、
> `csv`/`xls` 不检测）见 `backend/bg_image.py` 模块文档与
> `docs/design/轨迹速写插件-设计文档.md` §2；该文件与 `plugins/file-filter/backend/bg_image.py` 是
> **逐字节相同的双份副本**（规范 B-7 禁止插件间 import），改动须两处同步。
>
> **读表不信任工作表 `<dimension>` 声明**：该声明在 OOXML 里只是"提示"，部分工具会写出与实际
> 内容不符的值（如声明 `A1` 而实际有 A1:A4）。openpyxl 只读模式以它为遍历范围上界，会**只读到
> 首格**——上传后表现为「只识别第一行第一列」，分析阶段表现为「表格只有表头，没有可分析的数据行」。
> 现改为清掉声明、按 `sheetData` 实际内容扫描并统一补齐行宽
> （`backend/excel_io.py` 的 `_reset_dimensions` / `_pad_rows`，两步必须成对）。

## 2. 依赖

```
pip install -r plugins/trajectory-sketch/backend/requirements.txt     # openpyxl / xlrd / requests
```

- **轨迹分析引擎零第三方依赖**（纯 Python 标准库），无需 pandas / numpy；
- **字段过滤由本插件自带实现**（`backend/filter_local.py`），**不依赖「过滤器」插件**，
  也不需要对方处于启用状态或额外授权——两个插件相互独立（《插件设计规范》B-7）；
- **大模型辅助**走**主体模块** `jz_llm`：接入信息（格式 / 地址 / Key / 模型）不存本插件，
  管理员在「管理后台 → 大模型设置」维护；用户各自设置模式下由用户在首页右下角「⋯」→
  「大模型设置」填写。**本插件不持有任何密钥**；缺 `requests` 时大模型辅助不可用，
  硬过滤不受影响（装「依赖组件包」后刷新页面即可，免重启）。

## 3. 配置（管理员在插件页「⚙️ 管理配置」中维护）

| 配置项 | 作用 |
| --- | --- |
| 保留字段名单 | 字段白名单。可写规范列名（`BEGINTIME`）或任意别名（`时间`/`经度`）——保存后自动展开为该规范列的**全部别名**再匹配 |
| 列映射 | 规范列 ↔ 本表表头别名的对应关系；换一种来源的轨迹表时在此补别名 |
| 分析阈值 | 地点簇、停留点、出行段的全部判定阈值（改完对下次分析生效，无需改代码） |
| 报告文案 | 抬头、落款、「速写摘要」开关、无数据时段标注开关 |

必需字段为 `BEGINTIME`（时间）/ `LONGITUDE`（经度）/ `LATITUDE`（纬度），缺任一无法分析；
`USERNUM`（号码）/ `ADDRESS`（地址）/ `LAI`·`CI`（小区）缺失时会**降级**处理并给出提示。

## 6. 算法说明（v2）

参考项目 `D:\SQLRewrite`（基站工参级定位数据适配）。并查集结构与合并顺序与其一致；
**两处有意分叉**（v1.2.7，针对月度真实数据的漏报修正，见各模块文档）：
切换合并只数"快速往返弹跳"而非切换总次数；净位移达高置信线时回访/直线度不再触发合并。

- **地点簇**：并查集合并「地址相同 / 共址（<50m）/ 快速往返弹跳（a→b→a ≤10 分钟）
  且距离 ≤2km」的小区，以"地点"为单位判定，避免把基站切换误判为位移；
  按总次数计数会把用户日常通勤的两个地点并成一簇，故改数弹跳；
- **自适应停留点**：由数据自身估计**定位噪声半径**（低速样本位移的 95 分位），
  停留半径 = 噪声 × 系数（夹取 [300m, 3km]，auto/fixed 模式均可配），
  再用「点到窗口质心距离 ≤ 停留半径」的双指针扫描检出停留点（乒乓切换被吸收）；
- **出行段**：停留点质心之间的净位移 + 直线度 + 回访检验；净位移不足者**合并**停留点，
  显著超过噪声者判「有效出行」（此时回访/直线度不再有合并权），
  噪声量级者判「位置变动」并如实标注不确定性；
- **报告**：停留 / 运动中 / 位置变动 / 无定位上报四类句式，时间轴闭合，单位自适应。

算法可插拔：新增算法 = 在 `engine/algorithms/` 下新建版本目录 + `registry.register()`，
路由与前端**无需改动**；算法不与表格、Flask、数据库耦合（输入二维表 + 参数，输出纯 dict）。

### v3 算法（五态窗口栅格，1.2.8 新增）

`analysis.algo: "v3"` 可选，与 v2 并列（底座同源：清洗去重 + 地点簇，位置取簇质心）。
口径：5 分钟墙钟窗口 → 每窗三票（左对 / 自身 / 右对，恰一窗空时**单空窗桥接**）→
四行计数判定出五态（失联 / 静默 / 缓行 / 快速 / 极速）→ **聚合以位移切分**出停留段 /
出行段 / 无数据段（状态栅格不切条目，短途出行不被缓行吞）。报告正文按**窗口状态聚合
叙述**（同态连续区间一条，五态命名，速度=净位移÷实际时间）；`quality` 增 `v3_状态分布`
等键。参数全在 `analysis.v3` 节。

**算法切换**：字段自检卡片顶部的「算法」胶囊（switch 形态，v2 ↔ v3 分段高亮）是
**唯一切换入口**，办案员 / 管理员均可点击，下一次生成报告即生效（`POST /algorithm`
仅写 `analysis.algo`；配置面板不再提供算法选择）。
口径与实测预测：`docs/design/轨迹速写v3算法-设计文档.md`；实施清单：
`docs/plan/轨迹速写v3算法-TODO清单.md`。

### 分析参数逐项说明（分析阈值 · v2 / v3 分立）

参数位于插件配置 `analysis` 节（`config.template.json` 为模板）；全部参数在
`engine/params.py` 归一化并夹取越界值，非法配置不致命（自动回退默认/边界）。
**通用底座参数（清洗、地点簇、噪声估计、报告格式）v2/v3 共用**；v2 专属为
`staypoint` 半径组与 `trip` 判定组，v3 专属为 `v3` 节。配置保存后下一次分析即生效。

#### ① 清洗与去重（clean · v2/v3 共用）

| 参数 | 默认 | 功能与调整预期 |
| --- | --- | --- |
| min_longitude | 1.0 | 经度下限，≤ 该值的行丢弃（记"经度低于下限"）。正常不调；经度 0/负为无效数据。 |
| min_latitude（含 enable 开关） | 0.0 / true | 纬度下限及开关，同上。调高 → 丢弃更多低纬度行。 |
| geo_precision | 3 | 去重位置指纹小数位（3 位 ≈ 100 米）。调大 → 指纹更细，抖动算不同位置、点数变多；调小 → 折叠更狠，细碎移动被抹平。 |
| grid_seconds | 300 | 网格去重时间桶：同桶 + 同指纹只留最早一条（折叠信令突发）。调大 → 点更稀，速度类判定更钝；0 = 关闭。 |
| max_gap_seconds | 6000 | 断档阈值（100 分钟）：**仅 v2** 报告对 ≥ 该间隔的空洞标注"无定位上报"；v3 失联为显式状态，不读此参数。调小 → v2 无数据标注变多。 |

#### ② 地点簇（cluster · v2 判定层 / v3 底座，共用）

合并三信号（按序尝试）：地址相同 → 必并；距离 < `co_site_meters` → 必并；
**快速往返弹跳**（a→b→a 全程 ≤ `handover_bounce_minutes`）次数 ≥ `handover_min_count`
且距离 ≤ `handover_max_meters` → 并。

| 参数 | 默认 | 功能与调整预期 |
| --- | --- | --- |
| enable | true | 关闭 → 每小区自成一簇：v2 退化为纯几何判定（夜间乒乓碎化，靠出行合并兜底）；v3 位置=点本身，静默门限按原始抖动计算。不建议关闭。 |
| merge_same_address | true | 地址相同必并（最强信号）。关闭 → 同址不同小区不再合并，可能碎片化（地址可信时保持开启）。 |
| co_site_meters | 50 | 共址合并距离。调大 → 邻近小区更易并簇（可能吞掉相邻真实地点）；调小 → 只有几乎重合的才并。 |
| handover_min_count | 3 | 弹跳次数下限。调大 → 并簇更难（乒乓碎化）；调小 → 更易并簇。**调得过小会把通勤两端并成一簇（1.2.6 漏报外出事故的根因，1.2.7 起语义为弹跳次数）**。 |
| handover_bounce_minutes | 10 | 弹跳窗：a→b→a 全程 ≤ 该窗才计一次乒乓。调大 → 更宽的乒乓认定（快速折返也可能并簇）；调小 → 只认秒级抖动。 |
| handover_max_meters | 2000 | 弹跳并簇距离上限。调小 → 只并同站邻区（碎片化风险，由出行合并兜底）；调大 → 跨址误并风险上升（曾致漏报）。 |

#### ③ 噪声与停留半径（staypoint · v2 判定层；v3 仅用噪声部分）

噪声半径由数据自估：低速样本（相邻点对速度 < `slow_speed_kmh`）位移的
`noise_percentile` 分位。v2 用它推停留半径 D_thr；**v3 用它做静默门限**
（位移 ≤ 噪声即静默，见 ⑤ noise_floor_m）。

| 参数 | 默认 | 功能与调整预期 |
| --- | --- | --- |
| radius_mode | auto | **仅 v2**：auto/adaptive = 噪声自适应（1.2.7 起，开簇也一样），fixed = 用 fixed_radius_meters。 |
| fixed_radius_meters | 800 | 仅 fixed 模式。调大 → 停留更"黏"，近距离移动易被吞（1.2.7 前曾吞掉 560 米的住址↔工作地移动）；调小 → 碎片化。 |
| radius_factor | 1.2 | 自适应半径 = 噪声 × 系数（夹取 [radius_min, radius_max]）。调大 → 门限抬升（停留更黏、易吞移动）；调小 → 敏感、易碎。 |
| radius_min_meters / radius_max_meters | 300 / 3000 | 自适应半径下/上限。下限调大 → 弱噪声数据门限抬高；上限调小 → 强噪声数据半径受限。 |
| min_stay_minutes | 15 | **仅 v2** 最短停留 T_thr 下限：调大 → 短停留并入移动；调小 → 更碎。v3 不读（v3 用 `v3.stay_minutes`）。 |
| adaptive_min_stay_factor | 3.0 | **仅 v2** T_thr = max(下限, 系数 × 中位采样间隔)：采样越稀，最短停留越长。 |
| noise_percentile | 95 | 噪声分位（夹取 [50,100]）。调大 → 噪声估计偏大 → 门限宽松（静默/并簇更黏）；调小 → 敏感、易碎。**v2/v3 共用**。 |
| slow_speed_kmh | 5 | "低速样本"速度上限（参与噪声估计）。调大 → 更多样本计入 → 噪声估计偏大。**v2/v3 共用**。 |
| max_window_points | 2000 | **仅 v2** 停留扫描单窗点数上限（防 O(n²)）：超长停留被切成 ≤N 点的段，再由出行段合并接回。 |

#### ④ 出行判定（trip · 仅 v2）

净位移分级：≥ `high_conf_factor` × 噪声 → 「有效出行」（高置信）；≥ `mid_conf_factor` ×
噪声 → 「位置变动」；< 中置信线 → 相邻停留**合并**。**1.2.7 起净位移达高置信线即豁免
合并**（回访/直线度不再有合并权）；中置信带内的合并信号为回访与直线度。

| 参数 | 默认 | 功能与调整预期 |
| --- | --- | --- |
| high_conf_factor | 3.0 | 高置信线（× 噪声）。调大 → 更多位移判"位置变动"；调小 → 噪声级位移也可能成"有效出行"。同时是合并豁免线。 |
| mid_conf_factor | 1.5 | 中置信线（× 噪声），低于它必合并停留。 |
| straightness_min | 0.5 | 直线度否决（仅中置信带）：净位移/累计位移 < 该值 → 合并。调大 → 对绕路更严格（易合并）；调小 → 容忍绕路。 |
| merge_on_revisit | true | 窗口内"离开某小区又回来"（≤ `revisit_gap_minutes`）→ 合并。关闭 → 途经二次重选不再触发合并。 |
| revisit_gap_minutes | 60 | 回访认定窗。调大 → 更易命中回访 → 更多合并。 |
| min_trip_minutes | 5 | **仅约束首末段**：首/末未入停留的时段时长 ≥ 该值才计出行。 |
| include_leading_trailing | true | 首/末未入停留的时段是否计出行段。 |
| walk_speed_kmh | 4.0 | 预留参数，当前判定未使用。 |

#### ⑤ v3 专属（analysis.v3 节）

| 参数 | 默认 | 功能与调整预期 |
| --- | --- | --- |
| window_minutes | 5 | 状态栅格窗口宽。调大 → 粒度粗：短移动被并进邻窗或失联，过渡状态减少；调小 → 粒度细，但单窗点少、自身票更依赖守卫。 |
| creep_kmh | 10 | 缓行上限：窗速度 ≤ 该值 → 缓行。调大 → 公交/慢速驾车归缓行（移动叙述变少）；调小 → 步行也判快速。 |
| fast_kmh | 150 | 快速上限，超过为极速。调大 → 高铁判快速；调小 → 高速驾车判极速。极速多见于真实高铁或数据跳变。 |
| stay_minutes | 15 | 聚合层停留段最短时长（按窗口覆盖计）：调大 → 路边短憩并入移动段；调小 → 更碎。 |
| guard_seconds | 60 | 自身票短跨度守卫：窗内首末点间隔 < 该值只判静默/缓行（防"突发上报 200 米/30 秒"的假快速）。调大 → 更保守（真实快速通过可能降级为缓行，两窗对票会补判）；调小 → 突发噪声易成快速。 |
| noise_floor_m | 0 | 静默门限：0 = 复用 v2 自适应噪声（本测试数据 194 米）；>0 固定米数。调大 → 静默更多（移动被吞）；调小 → 抖动判缓行。**v3 的静默完全依赖该门限（速度精确为 0 在真实数据不存在）**。 |
| merge_void_into_stay | true | 相邻停留（位置差 ≤ 噪声）跨无数据段合并为一次停留，条目注记"其间失联"。关闭 → 夜间间歇上报会把停留碎成大量静默段 + 失联段（实测 534 段 / 1116 段）。 |

#### ⑥ v3 会读到哪些 v2 参数（底座共用，改动会影响 v3）

`clean.*` 全部（清洗去重）；`cluster.*` 全部（底座簇）；`staypoint` 的
`noise_percentile` / `slow_speed_kmh`（噪声 → 静默门限来源）；`trip.high_conf_factor`
（有效出行/位置变动分级线 = 系数 × 噪声）；`report.*`（抬头/落款/摘要开关/按日分节）。
v2 的 staypoint 半径组与 trip 其余参数对 v3 **无效**。

#### ⑦ 调参速查（症状 → 先查什么）

| 症状 | 先查 |
| --- | --- |
| 真实外出未进报告（v2） | cluster 弹跳合并组（1.2.7 已改口径，勿回调"总次数"语义）；`trip.high_conf_factor` 是否被调得过高 |
| 停留段碎片化（v2） | `radius_factor` ↑、`min_stay_minutes` ↑、`cluster.enable` 保持 true |
| 停留段碎片化（v3） | `merge_void_into_stay` 确认开启；`noise_floor_m` ↑ |
| 抖动被判移动（v3 缓行过多） | `noise_floor_m` ↑，或 `staypoint.slow_speed_kmh` ↑（抬高噪声估计） |
| 高铁只显示缓行（v3） | 窗口内被平均属正常（trips 中有净位移）；需要更细粒度则 `window_minutes` ↓ |
| 突发上报被判快速（v3） | `guard_seconds` ↑（默认 60 已可挡 200 米/30 秒级突发） |
| 报告行数过多 | v2：`min_stay_minutes` ↑ / `report.fill_holes` 关；v3：`merge_void_into_stay` 保持开 |

## 7. 已知限制

- 单次上传 ≤ 20MB、数据行 ≤ 10 万行；
- **背景图片只对 `.xlsx` 做识别 + 删除**：`.xls`（BIFF 二进制流）与 `.csv` 不检测，但两者在本插件里
  都会"读成二维表 → 重新生成输出"，产物天然不含背景图片；加密压缩包与解压后 > 256MB 的文档跳过检测
  （结论里如实说明），不影响后续流程；
- 定位坐标为**基站工参坐标**时精度约百米~公里级，1 公里量级的位移会被标为「位置变动」而非确定出行，
  这是**如实呈现不确定性**而非缺陷；
- 阈值标定样本为单一号码、约 18 小时；多号码/多日数据到位后建议按数据重新标定阈值（配置里可改）；
- 任务产物与上传暂存保留 30 分钟，过期需重新上传；
- 大文件（>5 万行）建议改用 CSV 以缩短解析时间。

## 依赖与升级

| 项 | 内容 |
| --- | --- |
| 框架已打包依赖 | `flask` >=3.0（必需，随主包） |
| 依赖组件包（可选，不随主包） | `openpyxl` >=3.1、`xlrd` >=2.0（缺失则 xlsx/xls 读取与报告导出不可用）；`requests` >=2.28（缺失则大模型辅助不可用，硬过滤不受影响） |
| 插件自带依赖（`backend/vendor/`） | 无 |
| 外部程序组件 | 无 |
| 能否单独升级 | ✅ 可以——业务依赖走「依赖组件包」，插件不 import 其他插件（构建期 C-4/C-10/C-11 校验） |
| 升级是否需重启 | 含 `backend/**` 改动**需要**重启（后台/安装器会自动重启，约 5~10 秒）；纯前端改动免重启，Ctrl+F5 即可 |

> 声明真源是 `manifest.json` 的 `requires`（三类依赖：框架包 / 自带 vendor / 外部程序组件）；
> 出包工具构建期校验「声明 ↔ 实测 import」一致（C-10）。后台「插件管理」按它显示
> 逐依赖徽标与可运行性：缺**必需**依赖 → 标记不可运行并暂不加载，补齐后重启自动恢复；
> 缺**可选**依赖 → 照常加载但标注功能降级。规范依据：《插件设计规范》§15 U-7a / U-8。
>
> **关于 `requests` 的声明口径**：本插件不直接 `import requests`——HTTP 由框架模块 `jz_llm`
> 发起。但「大模型辅助」能否用取决于它在不在，按「声明即契约」（U-7/U-8）仍须声明，
> 与 `file-filter` / `case-report` / `character-graph` 三个同类插件一致
> （C-10 对此会给出"声明了但未 import"的提示性警告，属预期）。
