# 轨迹速写（trajectory-sketch）

> 上传原始轨迹表（Excel，**自动删除文档里的背景图片**）→ **字段过滤**（本插件自带实现：
> 默认硬过滤，可切换大模型辅助做表头语义关联）→ 轨迹分析 → **速写报告**（页内预览 + Excel 工作簿下载）。

JZToolsHub 插件 · L2 前后端一体（A 型源码插件）· 设计文档见仓库 `docs/design/轨迹速写插件-设计文档.md`

---

## 1. 功能

| 步骤 | 说明 |
| --- | --- |
| ⓪ 删除背景图片 | 上传后**先**识别文档里嵌入的**工作表背景图片**（Excel「页面布局 → 背景」插入的图，常被用来夹带水印/机构标识），识别到就摘掉再落盘暂存——后续自检 / 分析 / 报告全链路只面对"干净"的文档。自检卡片与报告的「数据质量」sheet 都会记录这条结论 |
| ① 上传与自检 | 拖拽/点选 `xlsx` / `xls` / `csv`（≤20MB）。后端读表后**立即**用本插件自带的过滤实现做一次硬过滤预演，返回真实表头、保留/删除字段、必需列命中情况与过滤后数据预览 |
| ② 过滤模式 | **硬过滤（默认）**：字段名与保留名单精确匹配；**大模型辅助**：由统一大模型做表头语义关联（如「采集起始时刻」↔「开始时间」），需先在「大模型设置」中配置接入信息（见 §2） |
| ③ 轨迹分析 | 内置可插拔引擎：地点簇 → 自适应停留点 → 出行段（含位移/切换判别）→ 报告 |
| ④ 速写报告 | 页内展示速写摘要、报告正文、停留点、出行段、数据质量、地点簇；可下载 5 个 sheet 的 Excel |

> 背景图片清理的实现与边界（只摘背景引用、保留其余部件字节、没命中就不改写文件、
> `csv`/`xls` 不检测）见 `backend/bg_image.py` 模块文档与
> `docs/design/轨迹速写插件-设计文档.md` §2；该文件与 `plugins/file-filter/backend/bg_image.py` 是
> **逐字节相同的双份副本**（规范 B-7 禁止插件间 import），改动须两处同步。
>
> **读表不信任工作表 `<dimension>` 声明**：该声明在 OOXML 里只是"提示"，部分工具会写出与实际
> 内容不符的值（如声明 `A1` 而实际有 A1:A4）。openpyxl 只读模式以它为遍历范围上界，会**只读到
> 首格**——上传后表现为「只识别第一行第一列」，分析阶段表现为「表格只有表头，没有可分析的数据行」。
> 现改为清掉声明、按 `sheetData` 实际内容扫描并统一补齐行宽
> （`backend/excel_io.py` 的 `_reset_dimensions` / `_pad_rows`，两步必须成对）。

## 2. 依赖

```
pip install -r plugins/trajectory-sketch/backend/requirements.txt     # openpyxl / xlrd / requests
```

- **轨迹分析引擎零第三方依赖**（纯 Python 标准库），无需 pandas / numpy；
- **字段过滤由本插件自带实现**（`backend/filter_local.py`），**不依赖「过滤器」插件**，
  也不需要对方处于启用状态或额外授权——两个插件相互独立（《插件设计规范》B-7）；
- **大模型辅助**走**主体模块** `jz_llm`：接入信息（格式 / 地址 / Key / 模型）不存本插件，
  管理员在「管理后台 → 大模型设置」维护；用户各自设置模式下由用户在首页右下角「⋯」→
  「大模型设置」填写。**本插件不持有任何密钥**；缺 `requests` 时大模型辅助不可用，
  硬过滤不受影响（装「依赖组件包」后刷新页面即可，免重启）。

## 3. 配置（管理员在插件页「⚙️ 管理配置」中维护）

| 配置项 | 作用 |
| --- | --- |
| 保留字段名单 | 字段白名单。可写规范列名（`BEGINTIME`）或任意别名（`时间`/`经度`）——保存后自动展开为该规范列的**全部别名**再匹配 |
| 列映射 | 规范列 ↔ 本表表头别名的对应关系；换一种来源的轨迹表时在此补别名 |
| 分析阈值 | 地点簇、停留点、出行段的全部判定阈值（改完对下次分析生效，无需改代码） |
| 报告文案 | 抬头、落款、「速写摘要」开关、无数据时段标注开关 |

必需字段为 `BEGINTIME`（时间）/ `LONGITUDE`（经度）/ `LATITUDE`（纬度），缺任一无法分析；
`USERNUM`（号码）/ `ADDRESS`（地址）/ `LAI`·`CI`（小区）缺失时会**降级**处理并给出提示。

## 4. 后端接口（前缀 `/api/trajectory-sketch`）

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/status` | GET | 依赖自检（`openpyxl` / `xlrd` / `requests`）+ 过滤能力状态（含大模型是否已配置）+ 算法版本 + 配置提醒 |
| `/config` | GET | 读取配置（含保留字段别名展开明细、`can_manage`） |
| `/config` | POST | 保存配置（仅管理员/超管） |
| `/upload` | POST | multipart `file` → **删除背景图片** → 暂存 + 硬过滤预演 + 字段自检（同步）；响应含 `sanitize` |
| `/analyze` | POST | `{staged_id, mode}` → **异步**返回 `task_id` |
| `/result/<task_id>` | GET | 轮询进度与结果（含质量/停留点/出行段/报告/警告/`sanitize`） |
| `/download/<task_id>` | GET | 下载速写报告 `.xlsx` |
| `/ping` | GET | 探活 |

## 6. 算法说明（v2）

参考项目 `D:\SQLRewrite`（基站工参级定位数据适配），同一份样本数据与其 v2 输出**逐项一致**。

- **地点簇**：并查集合并「地址相同 / 共址（<50m）/ 双向切换且距离 ≤2km」的小区，
  以"地点"为单位判定，避免把基站切换误判为位移；
- **自适应停留点**：由数据自身估计**定位噪声半径**（低速样本位移的 95 分位），
  再用「点到窗口质心距离 ≤ 停留半径」的双指针扫描检出停留点（乒乓切换被吸收）；
- **出行段**：停留点质心之间的净位移 + 直线度 + 回访检验；净位移不足者**合并**停留点，
  显著超过噪声者判「有效出行」，噪声量级者判「位置变动」并如实标注不确定性；
- **报告**：停留 / 运动中 / 位置变动 / 无定位上报四类句式，时间轴闭合，单位自适应。

算法可插拔：新增算法 = 在 `engine/algorithms/` 下新建版本目录 + `registry.register()`，
路由与前端**无需改动**；算法不与表格、Flask、数据库耦合（输入二维表 + 参数，输出纯 dict）。

### 独立自测

```bash
BE=plugins/trajectory-sketch/backend
python $BE/engine/selftest.py                      # 单元自检（43 项）
python $BE/engine/selftest.py --excel 轨迹表.xlsx   # 另跑真实表格并打印报告
```

## 7. 已知限制

- 单次上传 ≤ 20MB、数据行 ≤ 10 万行；
- **背景图片只对 `.xlsx` 做识别 + 删除**：`.xls`（BIFF 二进制流）与 `.csv` 不检测，但两者在本插件里
  都会"读成二维表 → 重新生成输出"，产物天然不含背景图片；加密压缩包与解压后 > 256MB 的文档跳过检测
  （结论里如实说明），不影响后续流程；
- 定位坐标为**基站工参坐标**时精度约百米~公里级，1 公里量级的位移会被标为「位置变动」而非确定出行，
  这是**如实呈现不确定性**而非缺陷；
- 阈值标定样本为单一号码、约 18 小时；多号码/多日数据到位后建议按数据重新标定阈值（配置里可改）；
- 任务产物与上传暂存保留 30 分钟，过期需重新上传；
- 大文件（>5 万行）建议改用 CSV 以缩短解析时间。

## 依赖与升级

| 项 | 内容 |
| --- | --- |
| 框架已打包依赖 | `flask` >=3.0（必需，随主包） |
| 依赖组件包（可选，不随主包） | `openpyxl` >=3.1、`xlrd` >=2.0（缺失则 xlsx/xls 读取与报告导出不可用）；`requests` >=2.28（缺失则大模型辅助不可用，硬过滤不受影响） |
| 插件自带依赖（`backend/vendor/`） | 无 |
| 外部程序组件 | 无 |
| 能否单独升级 | ✅ 可以——业务依赖走「依赖组件包」，插件不 import 其他插件（构建期 C-4/C-10/C-11 校验） |
| 升级是否需重启 | 含 `backend/**` 改动**需要**重启（后台/安装器会自动重启，约 5~10 秒）；纯前端改动免重启，Ctrl+F5 即可 |

> 声明真源是 `manifest.json` 的 `requires`（三类依赖：框架包 / 自带 vendor / 外部程序组件）；
> 出包工具构建期校验「声明 ↔ 实测 import」一致（C-10）。后台「插件管理」按它显示
> 逐依赖徽标与可运行性：缺**必需**依赖 → 标记不可运行并暂不加载，补齐后重启自动恢复；
> 缺**可选**依赖 → 照常加载但标注功能降级。规范依据：《插件设计规范》§15 U-7a / U-8。
>
> **关于 `requests` 的声明口径**：本插件不直接 `import requests`——HTTP 由框架模块 `jz_llm`
> 发起。但「大模型辅助」能否用取决于它在不在，按「声明即契约」（U-7/U-8）仍须声明，
> 与 `file-filter` / `case-report` / `character-graph` 三个同类插件一致
> （C-10 对此会给出"声明了但未 import"的提示性警告，属预期）。
