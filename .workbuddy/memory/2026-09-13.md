### 踩坑（本次实测）
1. **Excel m/mm 上下文**：`h:mm` 里的 `mm` 是分钟不是月份——判定标志 `prev_h` 会被
   `:` 等字面量 token 打断；字面量必须**保持**上下文，且"下一个有意义的日期 token"
   要跳过引号与普通字面量再判（`mm分ss秒` 的 mm 应为分钟）。
2. **日期 token 正则漏 `dd`**：`dddd|ddd|` 后直接接 `d`，`dd` 被拆成两个 `d` 渲染出 `22`。
3. **ddd/dddd 是星期不是"日"**：fields 里 `d`=日、`dw`=weekday 必须分开存，否则
   `ddd` 拿 day-of-month 当索引直接 IndexError。
4. **`[h]` 经时**：token 判断要用去掉方括号的 inner 比较（`"[h]"` 不匹配 `^h+$`）；
   经时格式下 `m/mm` 恒为分钟（无月份概念）。
5. **尾逗号千分缩放的 lambda 闭包**：`re.sub(r",+$", lambda m: (scale:=scale+1)...)` 的
   walrus 落在 lambda 作用域，外层 scale 恒 0——改用 search+切片。
6. **openpyxl 新建簿的主题是 Office 2007**（accent1=4F81BD），与 Excel 2016 默认
   （4472C4）不同——测试断言别按后者写；tint 的 HLS 换算与 Excel 实测一致（黑 +0.5=7F7F7F）。
7. 测试期望值坑：`#,##0,` 千分缩放对 1234.5 显示 `1` 是 Excel 正确行为；字符串值不受
   number_format 影响；行高 24（pt）→ 32（px）是 4/3 换算。

## 知识库插件：Office 预览引擎整体替换为 xhr/dhr 双引擎（二次迭代）

**需求**：用户指定阅读 `D:\TestWorkSpace` 下的代码，Word（doc/docx）和 Excel（xls/xlsx）
两类文档预览采用其转换引擎（`xlsx-html-preview` 项目：xhr = XLSX/XLS→HTML 重绘引擎、
dhr = DOC/DOCX→HTML 渲染引擎），**舍弃原方案**（上午刚交付的 xlsx_render 手绘 +
此前的 LibreOffice→PDF）。

### 引擎调研结论
- 纯 Python 标准库、零第三方依赖（xlrd 可选、LibreOffice 外部可选），IR 中间层 +
  格式化显示文本（不输出原始序列值）+ 统一错误码（用户可读文案）+ 安全白名单
  （URL 协议/字体/图片魔数），369 个 pytest 用例，50 页 Word 渲染约 250ms。
- dhr 顶层 `from xhr.core import ...` → 两包必须同为顶层导入，vendor 后用
  sys.path 注入接入（上游 demo 同款）。

### 交付物
- `backend/vendor/{xhr,dhr}/`（53 个 .py 零改动拷贝 + README 来源说明）+
  `backend/office_render.py` 适配层（XHR_SOFFICE 配置注入：config.json
  `office.soffice_path` 新键兼容旧 `pdf.soffice_path`；渲染锁；XhrError→用户文案）。

  失败自动回退 mammoth/SheetJS）；app.js 删轮询/角标/提示条 pending 分支；
  style.css 删手绘样式；版本 v22/v6/v16。
- 文档：两份设计文档（阶段 8/9）、README×2、requirements 注释、HANDOFF、本日志。

### 踩坑（本次实测）
1. **DOMPurify 整块丢弃 `<style>` 元素**（本轮核心坑）：xhr/dhr 都是 class 型 CSS
   （`<style>` 去重声明），直接 sanitize 后 Excel 全裸、Word 表格无边框。
   解法：正则摘取全部 `<style>` 块 → 仅正文过 DOMPurify → CSS 用
   `document.createElement("style")` 原样挂回。CSS 为引擎生成静态内容
   （字体白名单/无 URL），无注入面，安全。
2. dhr 的表格输出里还有**嵌在 `<table>` 内部的第二个 `<style>`**（单元格 padding
   覆盖），同样要摘——`<style>` 在 table 内会被 HTML 解析器 foster-parent，
   innerHTML 注入时行为不定，统一摘出来最稳。
3. `model.meta` 是 MetaInfo 对象不是 dict（`meta.warnings` 取属性不取键）。
4. Python 模块 docstring 含 Windows 路径 `D:\TestWorkSpace\xlsx...` 会触发
   `\x` unicode 转义错误 → docstring 用 raw 字符串。
5. 本会话 Bash 工具 heredoc 会吃反斜杠（`\t`/`\n` 变真实字符）——含转义的补丁
   一律用 Write 工具写脚本文件再执行，别用 heredoc 内嵌（MEMORY 旧坑的新形态）。
6. LibreOffice `.doc→docx` 归一化回环对微型表格会退化为制表符段落（内容保留）；
   真实链路 .doc 走 doc_convert 转换件不经过此通道，仅历史失败记录会踩到。

### 验证结果
- 模块级四格式：docx/xlsx 直读 + soffice 转出的 .xls（LibreOffice 通道）/. doc

  Excel 蓝色主题/红字负数/货币/中文日期/隐藏行列/多 sheet 页签切换（aria-selected

## 附：真机反馈排查——「集成测试表格」空白处大量蓝格子

**现象**：真实库里 `f-88a782ee 集成测试表格.xlsx` 预览时空白处出现大量蓝色格子
（实测 179 个空 `<td>` 套上 `kbsheet-c0` = A1 蓝底标题样式）。

**根因（上游 xhr 引擎 bug）**：`xhr/renderer/table.py` `_build_cell_attrs` 对 XML 里
不存在的格子取 `style_table[0]`；而 `StyleTable.intern` 按**首次出现顺序**分配 id，
`[0]` 是首个被解析单元格的样式（本文件恰好是 A1 蓝底大标题）而非「默认样式」——
凡「工作簿首个带样式单元格非默认 + used_range 内有缺格」的文件都会触发。

**修复**：vendor 副本打补丁——缺格一律按无样式渲染（Excel 原生行为）；
上游 272 个 xhr 相关测试（render/style/core/fixtures/stress/expr_cf/layout_safety）
全部通过；已同步记录到 `vendor/README.md`（上游项目待修，位置相同）。
另：用户看到的旧预览是**缓存产物**（`<id>.preview.json`），修复后已删除该缓存，
重新打开即按新引擎产物渲染。
