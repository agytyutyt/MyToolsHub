# 2026-09-15 工作日志

## 插件热插拔评估 v2.1：W0 打包探测（实测通过）

承接 9-14 的 `docs/插件热插拔-容器化改造评估.md`。评估里列了三个"不先定就必返工"
的决策点，其中 **D1（sidecar 的 Python 依赖从哪来 = 能否产一个共享 `_internal` 的
独立 exe）是整条 sidecar 路线的唯一技术前提**。本次把它做实了，11/11 断言全绿。

### 做了什么

在临时目录（未入库，污染零）搭了一个最小双入口实验，写法刻意对齐 `JZToolsHub.spec`：

- `probe.spec`：两个 `Analysis` → 两个 `EXE` → **同一个 `COLLECT`**
- `probe_host.py`（宿主）+ `probe_sidecar.py`（sidecar）+ `probe_common.py`（模拟未来的
  `jz_plugin_sdk`）+ `probe_single.spec`（单入口对照组，用来量增量）
- 依赖只用 `collect_all("cryptography")`（abi3 C 扩展，代表本项目最典型依赖类型）
- 契约：sidecar 起随机端口 HTTP → stdout 打 `JZRT|1|<port>` → 校验 `X-JZ-Token`

### 实测结论（数字都写进评估文档附录 A 了）

- **共享 `_internal` 成立**：两个 exe 的 `sys._MEIPASS` 完全相同，`_internal` 只有一份
- **入口增量 3.00 MB / +9.7%（一次性）**：31.04 MB → 34.04 MB，而 `_internal` 一点没变大
  （28.13 MB 共用），新增的就是第二个 exe 本身（2.99 MB = bootloader + 它自己的 PYZ）
- **冷启动 431 ms**（stdlib + cryptography；真实 sidecar 要 import Flask，粗估 0.6~2 s）
- `CREATE_NO_WINDOW` + `stdout=PIPE` **可读握手行**（Windows 上最容易翻车的一处，实测没翻）
- Token 校验生效：无 Token → 401（回环端口的信任边界只能靠它）

### 两条修正（推翻了评估草稿里的表述）

1. **包体成本是一次性的，不是按插件线性增长**。因为做"一个通用 sidecar 入口"（由
   `runtime.json` 决定加载哪个插件），不是每插件一个 exe → 11 个插件也只要这一个入口。
2. **不需要改 `build-deploy.ps1`**：第 132 行 `Copy-Item -Recurse (Join-Path $Dist
   "JZToolsHub\*") $AppDir` 是整目录搬运，新 exe 自动带上 → W6 的一部分工作量归零。

### 顺带确认的

`hashicorp/go-plugin` 的 `MagicCookie` 只防"被双击执行"，不防攻击；本项目必须把它
升格为真实凭据（一次性随机 Token 经环境变量注入，**不走命令行**，避免
`wmic process list` 泄密）。

### 踩坑（探针设计错误，与打包机制无关，但值得记）

连续两次写出"天然不可能相等"的跨进程指纹断言：
① 用 `Fernet.generate_key()` → 密钥随机；
② 改成固定密钥后又去摘要 **Fernet token** → token 内含时间戳 + 随机 IV，照样不等。
**跨进程一致性指纹必须对随机源免疫**：只取确定性输出（这里是 `sha256(PBKDF2(...))`），
加解密往返另作可用性断言，不要混进指纹。

### 剩余

D2（任务表外置，否则空闲回收/停止插件会丢用户长任务）与 D3（握手 Token 落地）
仍是硬前置；R1（打包风险）已消解，原定的"同一 exe 加 `--jz-sidecar` 参数"回退方案
不需要了。主体（W1~W7，约 24~33 人日）尚未开始，等立项决策。

## 第十一轮：插件包校验失败不再只报「HTTP 400」（admin 1.3.1）

### 现象
目标机上传 `JZToolsHub-插件-admin-v1.3.0.zip` → 页面只显示「校验未通过：HTTP 400」，
看不到任何原因，现场无法自助处理。

### 根因（两个）
1. **前端吞错误**：`admin-common.js` 的 `api()` 抛错只取 `data.error`，而插件包校验失败
   的响应体是 `{ok:false, errors:[...]}`，没有 `error` 字段 → 退化成 `HTTP 400`。
2. 真实被拒原因（沙箱复现可枚举）：
   - 同版本重装（目标机已是该版本，多半是**前一次其实应用成功了**又传了一次）
   - 主程序版本过低 / 程序目录缺 `version.json`（我本地仓库就是后者，所以本地一直复现 400）
   - 包在传递中损坏 → 哈希不符

沙箱复现结论：**标准目标机（admin 1.2.0 + 主程序 1.9.0）下 1.3.0 包校验是通过的**，
所以问题在环境差异，不在包本身。

### 修复（commit 5a1771f）
- 后端：`upload` / `apply` 的 400 响应**同时给 `error` 摘要**（`"；".join(errors)`）。
- 前端：`api()` 兜底拼 `errors[]`，并给 error 对象挂 `err.errors`；插件管理页新增
  `errListHtml()` / `rejectHint()`：逐条列原因 + 按类型给下一步
  （勾「强制」/ 先升主包 / 检查部署目录 / 重拷原包别解压重压）。
- 前端资源戳：admin-common.js v5(v2)→v6、admin-plugins.js v2→v3（7 个入口页同步）。
- 测试：断言 400 响应必须带 `error` 摘要，防再次退化。

### 验证
- 两套 Python 测试全绿；浏览器实测：再传同版本小包 →
  显示「• 同版本重装：包与已装版本都是 1.0.0（确需重装请勾选「强制」）」+ 处置建议。
- 新包 1.3.1 在目标机 admin=1.2.0 / 1.3.0 两种状态下**均校验通过**（1.3.1 自身才拒同版本）。

### 产物
`deploy/插件包/JZToolsHub-插件-admin-v1.3.1.zip`（0.11 MB / 25 文件，
sha256 a719fd33739b9529175ae0732ee4d00d4a8970610b4beccd292c7e5b48761c74）。

### 文档同步
- README 新增 **§3.4「插件包：只升级一个插件（出包 + 目标机更新）」**：出包前置与参数、
  产物与登记、两条更新入口、**校验被拒排查表**、回滚；§12 补两条排查项；§6.6 指向 §3.4。
- HANDOFF：状态头、§2.2 插件包产物表、§10.2 快速命令、§7.3 新增踩坑 #17（api 吞 errors）。

### 本机坑（记牢）
- **沙箱 safe-delete 会拦"批量删除 >50 项"**：上传 25 文件的插件包时，服务端清理 staging

## 知识库 1.2.0：预览缩放修复（背景卡片同步放大）+ 缩放百分比可输入

### 现象与根因
用户报告：由 xls 转换而来的文档放大时只放大主要内容、背景白底卡片不跟着放大（其他类型正常）。
根因：`reader.js` 的 `setZoomTarget` 把 CSS `zoom` 设在内容元素上；Excel 类渲染件
`.kb-office` 是 `width:100%`，缩放后溢出按原宽度排版的 `.reader-frame` 卡片。
markdown/text 的 `.paper` 是 fit-content + margin auto，视觉上"恰好"看起来同步，掩盖了问题。

### 修复（commit fbf57fb）
- **zoom 目标改为 `.reader-frame` 卡片本身**（`setZoomTarget` 优先 `zoomFrame()`），
  全格式观感一致；`resetFrameZoom()` 在 render/destroy 清理；zoom>1 时卡片加
  `.zoomed`（去居中 margin）且 `#view-reader { overflow-x:auto }` 横向滚动。
- **百分比输入**：dock 中间显示框改 `<input id="zoom-input">`（50~300 回车生效，
  点击全选；越界按引擎上限钳制：HTML 0.5~3.0 / PDF·OFD 0.4~3.0；非法输入失焦回显）。
  `KBReader` 新增 `setZoom/getZoom`（pdf 走 applyScale、ofd 用引擎 API 步进逼近、
  HTML 走 htmlZoomSet）；app.js `syncZoomInput/applyZoomInput` + onPage/onZoom 回显。
- 资源戳 reader.js v8 / app.js v18 / style.css v26；manifest 1.1.0 → **1.2.0**。

### 验证（浏览器 E2E，agent-browser + 自包含 Flask 服务器全绿）
`.workbuddy/e2e_kb_zoom_server.py`（可复用）：`JZTOOLS_DATA_ROOT` 隔离 + 伪造
jztools_admin 会话 + 托管插件前端 `/plugin/knowledge-base/*` + openpyxl 造 xlsx 经
soffice 转 xls 后走真实上传 API。实测：初始 653px/100% → ＋×2 后卡片 783px（=653×1.2，
**卡片随内容放大**）→ 输入 200% 生效 → 999% 钳 300% 且横向滚动出现 → 非法输入回显恢复。

### 出包与文档
- `deploy/插件包/JZToolsHub-插件-knowledge-base-v1.2.0.zip`（1.28 MB / 80 文件，
  sha256 a408727b1ff94d3e…，`requires_restart=false`），登记 `tools/plugin-packages.json`。
- 文档同步：设计文档 §7.4 缩放两条重写、插件 README 阅读节、HANDOFF 状态头 + 产物表。

## 知识库 1.2.1：修 1.2.0 缩放左对齐回归（commit 9a31aae）

### 现象
1.2.0 给 zoom>1 加了 `.reader-frame.zoomed{margin:0}` 强制去居中——卡片放大后只要还
小于视口（如 120% 的 783px < 1425px），就被错误推到左边，用户反馈“卡片靠左、格式乱了”。

### 正解（实测教训）
**居中始终交给 `margin:0 auto`，JS/CSS 都不要干预**：块级布局下卡片比容器宽时
auto 边距自动收窄（Chrome 实测是均分残留边距而非归 0），配合 `#view-reader{overflow-x:auto}`
内容全部可达、无左侧裁切。当初担心的“margin auto 在滚动容器里左侧不可达”是
flex/grid 居中（justify-content:center）才有的问题，块级 margin auto 不存在。

### 改动
删 `.zoomed` CSS 规则 + reader.js 里 class 加/删死代码；资源戳 style.css v27 / reader.js v9；
manifest 1.2.1，包 1.28MB/80 文件 sha256 da3521617c70b6f2…（requires_restart=false）。
浏览器 E2E：120% 居中偏移 321=321 完美居中；300% scrollW1675>1425 可滚动；滚动往返左缘无裁。

### 踩坑：Edit 成功但内容丢失
上一轮对 HANDOFF 产物表的编辑（1.1.0→1.2.0 行）返回成功，但提交后 HEAD 里仍是旧行
（状态头编辑却在）——疑似文件被外部回写覆盖。教训：**对同一文件的多处编辑，提交前
用 grep 复核每一处都真的落盘**，不能只信编辑成功回执。本轮已补回该行（v1.2.1）。

## 权限全流程不可见：隐藏工具浮窗泄露未授权插件（修复）

### 现象
用户未被赋予某插件权限点时，首页不显示该插件，但「隐藏工具」浮窗
（`GET /api/tools/visibility` 返回全量清单）里能看到并可切换它。

### 修复（充分解耦，不动单个插件）
1. **app.py 权限点读取收口**：新增 `_current_user_allowlist()` 作为唯一读取入口
   （来自 admin 插件 `get_session_user().permissions` = 逐人授权 + grant_all；
   匿名被 R2 强制登录拦截、超管不限）。`_filter_visible_tools` 改为经它取集合。
2. **`GET /api/tools/visibility` 按同一口径过滤**：工具仅返回授权项；
   分类仅返回仍含可见工具者。
3. **`POST /api/tools/visibility` 写权限拦截**：未授权工具 / 不含可见工具的分类
   切换 → 403（防绕过前端直改）。
4. **admin 新增 `GET /api/admin/permission-points`**（`permission_required("user")`）：
   返回全量工具（含停用），专供人员「权限设置」弹窗。`admin-user.js:269` 从
   `/api/tools/visibility` 切换过来——权限分配 UI 与首页隐藏浮窗彻底解耦，
   有 user 模块的非超管也不会因自身权限点被过滤而漏勾。

### 验证（隔离数据根 + test_client，9 断言全绿后已删临时脚本）
匿名 401；超管 permission-points 全量；受限用户（md5-generator+case-report）
首页与 visibility 均只剩授权项+grant_all，分类只剩 dev/office；
未授权工具/分类写 403、授权的 200；无 user 模块访问 permission-points 403；
未授权插件 API 403 / 详情 404 回归通过。

### 文档同步
README §7.1 visibility 两行重写 + §7.2 新增 permission-points 行；
admin README 人员管理 bullet 补解耦说明。
