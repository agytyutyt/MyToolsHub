## 知识库插件：阅读页背景卡片改为贴合预览内容宽度

**需求**：预览界面原来的背景卡片（`.reader-frame`）是通栏白卡片，打开 Word/PDF
等窄版心文档时两侧出现大片空白。要求去掉通栏卡片，改为**宽度适配预览文件实际
宽度**的卡片（内容多宽卡片多宽，居中，两侧露出页面灰底）。

### 实现（纯前端 CSS，`frontend/style.css`，v22 → v23）

- `.reader-frame`：`width: -moz-fit-content / fit-content` + `max-width: 100%`
  + `margin: 0 auto`。宽度由各渲染器输出的自然宽度决定：
  - Word（dhr flow）：`.kbdoc-body` 内联 `max-width:{版心+64}px;margin:0 auto`
    ——max-width 会封顶子元素对父级 shrink-to-fit 的贡献 → 卡片贴合版心
    （A4 实测 698px = 666 + 卡片内边距 32）；
  - Excel（xhr）：`.kbsheet-t` 表格输出显式 `width:{total}px` → 窄表卡片收缩、
    宽表卡片顶到视口上限后由 `.kbsheet-viewport{overflow:auto}` 内部滚动；
  - PDF：canvas 显式 px 宽（scale×595）→ 卡片贴合画布（1.25 倍实测 776px），
    缩放跟随；
  - Markdown / txt / mammoth 降级：`.paper{max-width:860px}` 封顶贡献 → 卡片
    随内容伸缩、最长 892px；
  - OFD：画布随缩放变化，卡片跟随（`fit-content` 自动适应）。
- 兜底：`@media (min-width:600px){ .reader-frame{min-width:520px} }`——窄表、
  加载/错误提示态不出现细条卡片；不支持 fit-content 的老内核回退
  `width:auto`（即旧的通栏行为，优雅降级）。
- 配套两处防撑破：① dhr 引擎对 `width_px` 固定宽表格输出显式宽度会**溢出版心**，
  新增 `.kb-office-word{overflow-x:auto}` 让超宽表格在卡片内横向滚动（此前通栏
  卡片时溢出落在白底上不可见，贴合后必须收进滚动容器）；② `.reader-notice`
  （旧格式转换提示条）限宽 `max-width:640px`，长文案换行，不参与撑宽卡片。
- `index.html` 资源版本 `style.css?v=23`（F-2 缓存绕过约定）。reader.js /
  app.js 零改动。

### 验证

- 静态测试台（模拟四种渲染器 DOM + 引擎骨架 CSS）+ IAB 浏览器实测，八场景：
  Word 正常 698px ✓ / Word 宽表格（width:1200px）卡片不撑破、表格卡内滚动 ✓ /
  Excel 宽表撑满可用宽+内部滚动 ✓ / Excel 窄表 520px 兜底 ✓ / SheetJS 降级 ✓ /
  PDF 776px 贴合画布 ✓ / Markdown 随内容伸缩 ✓ / 加载态 520px ✓ / 转换提示条
  不撑宽（698px 不变）✓。
- **实测坑**：浏览器 auto 表格布局下 `<col width=Npx>` 是软约束，表格会被收缩
  进容器——测试台的"宽表格"必须像真实引擎一样给 `<table>` 显式 `width:Npx`
  才能复现溢出场景。
- 测试台为一次性产物，已删除；后端未动，无需跑 pytest。

## 知识库插件：修「会话开发文档」横向滚动条（用户实测反馈）

**现象**：阅读该 docx 出现横向滚动条（挂在 8.7 加的 `.kb-office-word`
overflow-x:auto 上，说明有内容真溢出了版心）。

**排查**（真实缓存预览 HTML f-7524b543.preview.json + 探针页逐层测量）：
- 该文档是 API 接口说明，参数表 `<table class="kbdoc-t kbdoc-c9">`（**无显式
  宽度**，auto 布局）的「说明」列里有 `chat.completion/chat.completion.chunk`
  等无空格长 token → 该列 min-content 被撑到 345px → 整表 601px > 版心内容盒
  554px（body 618 − padding 64），溢出 47px。auto 布局收缩的下限就是列的
  min-content，内容不允许缩就溢出；
- 正文另有大量 **NBSP（\xa0）缩进的 JSON 长行**——NBSP 不可折行，同属
  "长 unbreakable token" 一类；
- 页面级（body）与 reader-container 层均无溢出，卡片 650px 贴合正常——溢出
  仅在版心内容层。

**根修**（style.css v24）：
- `.kb-office-word { overflow-wrap: anywhere }`：断词且**参与 min-content
  intrinsic 尺寸计算**（`break-word` 不参与计算——这是选 anywhere 的关键），
  列 min-content 塌下去 → 表格收缩回版心；NBSP 长行获得正常折行。
- `.paper { overflow-wrap: anywhere }`：md/txt/mammoth 的同类隐患一并防住。
- `.kb-office-word{overflow-x:auto}` 保留：真正超宽的固定表（引擎对 width_px
  表格输出显式 `width:Npx`）仍走卡内滚动兜底（回归验证 1200px 表 kwHScroll=true、
  页面级永不横滚）。
- **预览缓存不用失效**：`<id>.preview.json` 是引擎渲染产物，本次纯 CSS，
  重开阅读页即生效。

**复测**（真实预览 HTML 探针）：body/kb-office-word/reader-container/page 四层
scrollWidth==clientWidth，两表均 554px 正好贴合版心，零元素溢出，卡片 650px
不变；表格内长 token 在列内断行（chat.completio|n.chunk），JSON 段落排版正常。

**经验**：① `overflow-wrap:break-word` 只在渲染时断词、不影响 intrinsic 尺寸，
修不了"表格被 min-content 撑破"；要参与计算必须 `anywhere`（Chrome 80+，本项目
reader-dock 已用 flex gap=Chrome 84+，无兼容问题）。② 排查横向滚动条要分层量
scrollWidth（page/reader-container/kb-office-word/kbdoc-body），一层层排除。

**文档同步**：设计文档阶段 8.7/8.7.1、HANDOFF 头部、本日志。

## 产出 `docs/P0问题修复方案.md`（补丁级方案，未执行）

针对 P0-1~P0-6 给出可直接落地的改动清单。核心洞察：

- **P0-1 + P0-2 是同一个根因**：模板文件与运行时配置**同名**（都叫 config.json），
  打包脚本按名字删运行时配置时连模板一起删了。所以不要"保住 config.json"，
  而要**让模板不再叫 config.json** —— 统一改名 `config.template.json`，一处改动同时解决两个问题，
  且 `build-deploy.ps1` 的清理规则（`-eq "config.json"` 精确匹配）**无需修改**。
- **P0-3 不加指针存在性校验**：备份指针的用途正是"主指针丢失后找回自定义数据目录"，
  该目录可能临时不可用（网络盘），加校验反而破坏设计意图；只做 `git rm --cached` + gitignore。
- **P0-4 修法**：`build-deploy.ps1` 未传 `-Version` 时**自动递增 patch**（1.6→1.7），
  与上一版相同则 throw（除非 `-Force`）；顺带把 `commit` / `built_at` 写进 `version.json`
  （`_read_version()` 只读 `.app`，加字段安全；注意用现有 `ConvertTo-Utf8NoBom` 避免 BOM）。
- **P0-5 改名安全性已核实**：全项目仅 `admin/backend/routes.py` 用 `url_for`，
  且引用的是 `admin_login`/`admin_index`（不动），其余插件无 `url_for`/`endpoint=` → 纯标识符改名零外部影响。
- **P0-6 隔离要写清两条限制**：① `register(app)` 中途抛错时已注册路由**无法回滚**
  （隔离只保证整站起得来 + 错误可诊断）；② 模块缓存不刷新，后端改动仍需重启。

  PowerShell 版 `Merge-DeepKeys` 递归实现，并说明"或简化为只做初始化、深度补键交给
  app 首启 sync_templates（但受版本门控，首次安装必须完成初始化）"。
