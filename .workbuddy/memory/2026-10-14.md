- 上一会话已落地 ①②（工作区未提交）：`client/capability_app.py`（卸载进度台账 `uninstall-dep/progress`、逐项删除 `_rm_tree_tick`）+ `plugins/store/frontend/store.js`（`pendingBtnHtml` 定格、依赖卡三态）+ `store.css`（`.st-btn-pending`/`.indet`）+ `store-page-state-tests.js`、`store-deps-bench.py` L/M 段 + 设计文档 v3.3 注。本轮补齐 **③（依赖侧）** 并修掉两个真实缺口：

  1. **前端只定格「发起安装的那张卡」**：`restartPending` 此前只记 `e.id`，联合安装（`include_deps`）里一并装上的依赖组件虽然能力层已报 `dep_results[].pending=true`，但依赖卡片照旧显示「安装」。改为三条来源合成 `pendIds`（响应 `restart_required` + 响应带回的**组件 id**（可不等于商店条目 id）+ `dep_results[].pending` + `pending_components`），命中即把对应依赖卡片一起定格；`selfPending` 单独判定，未要求重启的插件自身不会被误定格（台架 F1/F2 钉住）。
  2. **客户端暂存判据漏掉升级场景**（真缺陷，非显示问题）：`client/pkg_install.installed_components` 原来「登记里的 id 就跳过暂存区」，于是**升级**（新版已暂存 `.pending/<id>`、旧版仍在 `manifest.json`）时报旧版本 + `pending=false` → 商店卡片显示「已安装」/「升级到 vX」，用户点完安装、选「稍后」后看着像安装没生效。改为**暂存区优先**：同 id 在暂存区 → `pending=true` 且版本取暂存声明（新增 `staged_component_version()`，兼容客户端与 `install-dep-component.ps1` 两种同形 `entry.json`）；暂存残骸（缺 `entry.json`）仍算待重启、版本退回登记值。
