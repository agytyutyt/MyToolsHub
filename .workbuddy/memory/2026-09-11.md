**关键设计与实测发现**
1. **`\x07\x07` 是 Word 表格行结束标志**（空缓冲的连续两个 `\x07`）——单 `\x07` 单元格结束、
   `\r` 段落结束。状态机必须把这三种边界符号都识别清楚，**且 `\r` 到来即封表**（否则后续段落
   会被插到表格前面）。
2. **闭包捕获 `buf = []` 会读到旧列表**：状态机里 `buf_text()` 捕获 `buf` 这个列表对象，
   函数里一旦 `buf = []`（重绑定）外层仍读旧列表 → 幻影内容。解决：原地 `del buf[:]`。
3. **`close_row()` 不得给空缓冲补单元格**——Word 行结束符自身若被当成一列，末尾会出现
   凭空多出的空列。改为 `if buf: cells.append(buf_text())`。
4. **测试时模块重复加载陷阱**：`import_module("jztools_knowledge_base")` 拿到的是包对象，
   改它的 `_get_session_user` 不影响 `sys.modules["jztools_knowledge_base.routes"]`（路由 handler
   闭包捕获的是子模块）。直接 patch 子模块才生效，或走真实 `/api/login`。
5. **Werkzeug 3 test_client 忽略手写 Cookie**（HANDOFF §7 第 13 条已记）——走真实登录更稳。
6. **agent-browser 在 iframe 内不可见**：`/tool/...` 用 iframe 包裹插件页，eval 找不到卡片；
   直接打开 `/plugin/<id>/index.html` 跳过 shell 才能走查。
7. **依赖缺失优雅降级**：`/status` 返回 `{ok: true, dependencies: {convert_legacy: {ok: false, missing: ["xlrd"]}}}`，

## 评估：知识库 Word/Excel 预览的样式保真度（未实施，仅评估）

用 vendor 真实库（SheetJS 0.18.5 / mammoth 1.6.0）+ openpyxl/python-docx 造的带样式夹具做了实证
（脚本留存 `build/kb_eval/`，含 styled.docx/xlsx 夹具与 test_style_fidelity.js，供后续实现复用）：

- **docx（mammoth 现状）**：h1/h2、strong/em、ul/li、table 保留；**颜色/字号/对齐/下划线/表格边框全丢**。
- **xlsx（SheetJS 默认）**：值、数字格式（经 cell.w → 35.0%、日期）、合并单元格（colspan/rowspan）已体现；
  列宽、填充、字体颜色、边框丢。`cellStyles:true` 实测只补出 !cols 与 fill（A1 底色 1F4E78 读到），
  **font 读不出（A4 红色加粗 s={}）**——CE 完整样式在 Pro。
- **.doc**：上传时纯 Python 转换已丢全部样式，前端换渲染器也救不回；保样式唯一路径 = WPS/Office COM
  或 LibreOffice（与环境约束冲突）。
- **.xls**：可在服务端转换时保样式——xlrd `formatting_info=True`（BIFF8/Excel 97+）读字体/填充/边框/
  数字格式/列宽/合并 → openpyxl 写回 xlsx；更老 BIFF 版本 try/except 回退纯值转换。

可行路线（按收益排）：① docx 换 docx-preview（+jszip 复用 vendor，~600KB）；② xls→xlsx 转换带样式；
③ xlsx 渲染器补列宽/填充；④ .doc 维持现状或 COM 混合（需拍板）。
