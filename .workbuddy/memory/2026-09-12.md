## 知识库 Word 预览三问题：排查 + 实施修复（当日完成）

- 排查知识库 Word 预览三问题：仿宋_GB2312 竖细、部分文字加粗、单元格穿模。
- 根因定位：
  1. 字体回退：仿宋_GB2312 缺失时直接 fallback 到 Microsoft YaHei（黑体），墨量差约 2.56 倍 → "加粗"；混排时粗细不均。
  2. 表格行高：`<tr>` 上 `overflow:hidden` 对 table-row 无效，精确行高约束失效；`<p>` 默认 margin 未重置，进一步撑坏行距。
- 复现实验：生成 `kb_fs_sample.docx`、`kb_cell_sample.docx`，Canvas 像素签名法测字体命中，agent-browser 测实际行高。

### 实施（方案：后端 HTML 后处理，vendor 零改动）

- `office_render.py` 新增 `_polish_word_html()` 三段子补丁：
  - `_patch_font_fallback()`：目标字体与雅黑之间插 `"FangSong","仿宋","SimSun"`。
  - `_patch_table_overflow()`：清 `<tr>` 上无效的 `overflow:hidden`（留 height）。
  - `_patch_css()`：追加 `p{margin:0}` / `word-break:break-all` / `td>p:only-child{overflow:hidden}`，带标记 `/*kbdoc-patch*/`。
- `routes.py`：`PREVIEW_CACHE_VERSION` 3 → **4**（关键：否则目标机旧缓存让修复不生效）。
- `test_routes_preview.py` 第 0b 节：新增 6 项补丁回归断言。
- 实测：字体 雅黑 → **仿宋**；字重 `font-weight:400`；表格行高 49/67/49px → **33/51/33px**。
- 验证：完整回归 + 边界用例（6 种仿宋写法/裸仿宋/已修链/无 style 块/空串/None）+ 缓存版本失效模拟（篡改 v3 → 自动重渲染）全通过。
- 文档同步：`docs/eval/知识库Word预览三问题排查报告.md`（新建）、设计文档 §16、插件 README。

### 踩坑（勿重犯）

1. **裸 `"仿宋"` 不能进 `_FANGSONG_NAMES`**：它既是查找键又是插入值，二次处理自我匹配 → 重复注入，幂等破坏。
2. 验证断言口径：`font-family:` 声明串含双引号，`[^;}"]+` 会截断造成假阴性；统计 `<tr>` 用标签正则别用 `<tr\b`（会命中 CSS 选择器文本）。
3. `<tr>` 清理须限定标签内部（`<tr\b[^>]*>`），部分匹配替换会破坏标签闭合。
